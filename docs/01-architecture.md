# 01 · Architecture

## Workspace

```
rerun_/
├─ crates/
│  ├─ rerun-core/      Library: detection, Topo engine, primitives, Journal, system layer
│  ├─ rerun-proto/     Small shared types (CPU topology and its pure Windows-record parser; from Phase 3 launch profile, CPU rule), no dependencies, serde only via feature
│  ├─ rerun-cli/       Binary `rerun` (phase 1: system, scan; phase 2: plan, apply, revert, status, forget; later topo validate)
│  ├─ rerun-launch/    Binary `rerun-launch.exe` – launch shim, only windows-sys + rerun-proto
│  ├─ rerun-cpu/       cdylib `rerun-cpu.asi` – inproc CPU fix, x86 + x64
│  └─ rerun-workbench/ Curator tool: query PCGamingWiki, generate Topo draft
├─ app/                Tauri 2 + Svelte 5 + TypeScript (Vite); `app/src-tauri` joins the Cargo workspace only in Phase 5
├─ topos/              Game recipes (YAML)
├─ packages/           Upstream tools (YAML)
├─ data/               Reference data (YAML): GPU architecture table `gpu-arch.yaml`
├─ schema/             JSON Schema for Topo, package and GPU architecture table
├─ tests/fixtures/     CPU topologies, path parity cases, valid/invalid schema fixtures
└─ docs/
```

Dependencies always point to `rerun-core` or `rerun-proto`, never back.

P2-13: `load` (public), `preview_stored` (the preview of stored bytes, current rules) and `preview_head` (a recorded head, recorded rules, registry data only by type, length and SHA-256). |
| `exec` | Apply, verify, revert and forget per op kind (ADR 0020): checks before the first change (lock, hash, root identity, Steam state, game closed via `users()`, stacking, old state re-observed), `Observed` (`Before`, `After`, `Drifted`, `Foreign`), a foreign state is never overwritten (`forget` instead), immediate rollback on failure, a rebind under strict conditions (planned, P2-14). P2-8: `ExecCtx { sys, fr, app, tag }`, `apply` (`Outcome::{Nothing, Applied}`, `ApplyError::{Refused, RolledBack, LeftOpen}`), `verify` (read only), `revert` (also recovery and, on the same writer, the rollback; `RevertReport`), `forget`; modules `roots` (reopen, Steam, `users()`, old state), `stack` (stacking and LIFO on the listing), `file` (the file op kinds: apply, observe, act). P2-10a: dispatch by `Op::target()` to the module of the op's domain (`file`, and `reg` for registry keys and values since P2-10b), one revert loop; a revert opens each root on its own and halts at a file op whose root does not open (`Halt`, `Verified`). P2-10b: `reg` (apply, observe, act, records of `CreateKey`/`SetValue` through `policy::registry`), `Refusal::{Registry, Elevated}`, `HKCU` flushed before `Applied` and before each registry op's `RevertDone`. P2-11: `TokenList` in `reg` (semantic revert of a shared compatibility-layer value through `RegWriter::add_tokens`/`remove_tokens`, `Drifted`; the shared keys `AppCompatFlags`/`Layers` left when not empty), recorded heads decoded with `plan::Rules::Recorded`. P2-12: `ini` (`IniValue`, a file op whose apply, observation and record check go to `exec::ini`: the edited bytes from `policy::ini`, a semantic rewrite of a file the game rewrote with `from`/`to` in its `RevertIntent`, the binding of a recorded head to its backups before a revert and `verify`, a `Detail` per op in `verify` and the report). P2-13: `check` (every check of `apply` before `begin`, read only, one `preflight` chain with `apply`; an existing lock file held read side), `standard_user` (user decision E3: `apply`, `check`, `revert` and `forget` refuse an elevated or undeterminable process for every plan), `status`/`txn_status` (journal only: `TxnStatus`, `TxnLine`, `OpStatus`, `OpState`, `Backup`), `OpReport::backup` typed (`Backup::{Bin, Inline}`), a revert error before the run's first record is `Refused` (`Refusal::Observe`), a closing entry that may be on disk `Unconfirmed`; `revert_check` (every check of `revert` before its first record, read only, the same chain); a damaged transaction with a usable head blocks applies and earlier reverts on its objects. |
| `journal` | File-based (ADR 0019) under `AppDir` (`<LocalAppData>\Rerun\journal`): one folder per transaction with `head.json` (the plan bytes, opaque to the journal) and immutable numbered records (`NNNN.json`) and backups (`op-NNNN.bin`), each written once with `create_new`; one grammar (`journal::replay`) for reader and writer; `TxnWriter` for an apply, `RevertWriter` (revert only) for a resumed transaction; write-ahead (backup read back and hashed, then the intent, then the change); flush of every changed file, parent folder and registry key before the closing record; `journal\lock` (share 0) held by apply, revert and forget; untrusted reader with budgets; LIFO revert per object. P2-10a: one record form for files, keys and values (`Intent.before` as `.bin` or inline up to 16 KiB, `Done.file_id` optional, `RevertIntent { from, to }` reserved for P2-12; P2-11 does without it). |

## Primitives

A primitive is a planner (ADR 0020, user decision D9): it turns its spec into ops of a few generic kinds, and `exec` applies, verifies and reverts each op kind with the journal (ADR 0019). Every primitive still needs its own round-trip test (`docs/09-testing.md`).

```rust
pub enum Step { FileInstall(FileInstallSpec), RegistrySet(RegistrySetSpec),
                CompatLayer(CompatLayerSpec), IniSet(IniSetSpec) }
pub fn plan(steps: &[Step], ctx: &PlanCtx<'_>) -> Result<Plan, PlanError>; // GameDir, AppDir, RegPolicy; reads only
```

Phase 2: `file_install` (local package files under `<AppDir>\packages`; `prim::file_install`, done in P2-8: `PlanCtx { game, app, steam_app, main_exe }`, the `RegPolicy` joins with P2-9), `registry_set` (`prim::registry_set`, P2-10b: values below `HKCU\Software\<Vendor>\<Product>`, read through `PlanCtx::reg`, a `RegReader` of `policy::registry`; the builder puts every registry op after every file op), `compat_layer` (`prim::compat_layer`, P2-11: tokens for an executable of the game folder in `AppCompatFlags\Layers` as a `TokenList` op; the executable in its stored spelling, a game folder reached through a link refused through `GameDir::launch_path`; the token allowlist from the Sandbox probes, P2-11b), `ini_set` (`prim::ini_set`, P2-12: keys of an existing `.ini` file of the game folder as one `IniValue` op per file with its edits, read and edited through `policy::ini`, ADR 0021; the file in its stored spelling, a missing file refused, the main executable required). Until the Topo engine (phase 4) `rerun plan` reads a JSON step file whose step objects are the durable spec types (ADR 0020, D7).

| Primitive | Effect | Admin |
|---|---|---|
| `compat_layer` | `HKCU\…\AppCompatFlags\Layers` (mode, DISABLEDXMAXIMIZEDWINDOWEDMODE, HIGHDPIAWARE, 16BITCOLOR …) | no |
| `priority` | `IFEO\<exe>\PerfOptions\CpuPriorityClass` | yes |
| `firewall_rule` | Outbound block for the exe only (INetFwPolicy2) | yes |
| `file_install` | Files from a package into the game folder, occupy slots, backups | no* |
| `ini_set` | Set individual keys of an existing `.ini` file (ANSI or UTF-8; UTF-16 from phase 4) | no* |
| `registry_set` | Values under allowed game keys | depends on hive |
| `launch_option` | Steam launch option (localconfig.vdf, only while Steam is closed) | no |
| `launch_method` | `direct` / `watch` / `hold` / `ifeo` / `inproc` + CPU rule (see `04`) | ifeo: yes |
| `laa_patch` | Large Address Aware flag in the exe, with backup; not for DRM-protected exes | no* |
| `steam_input` | Hint/link: enable Steam Input per game | no |

\* unless the game is located under `Program Files` → then via the helper.

## Data flow

```
detect ─► hw ─► topo(when) ─► plan ─► [preview UI/CLI] ─► apply ─► journal
                                                     └► elevate (admin parts only)
start: Steam %command% / IFEO ─► rerun-launch ─► read profile ─► method ─► check ─► exit
revert: journal ─► observe each op (never overwrite a foreign state) ─► restore backups / values, LIFO ─► (phase 3: firewall/IFEO/launch option) ─► folder comparison
```

## rerun-cli

- Phase 1 (ADR 0016): `rerun system` (`hw::read` with the built-in GPU table: GPU, CPU topology, OS build, the five condition facts) and `rerun scan [APP_ID…] [--hashes]` (`ForbiddenRoots` from its own install folder, `steam::scan`, per installed app `open_game` + `scan_game`, streamed per game; apps Steam is updating are listed, never opened).
- Phase 2 (ADR 0020, P2-13; ADR 0016 amendment P2-13): `rerun plan <steps.json> [--dry-run]` (the step file through `policy::root::read_input` and `prim::StepFile`, the preview of the encoded bytes, then `plan::store`; `--dry-run` creates nothing), `rerun apply <plan-hash> [--dry-run] [--yes]` (the preview of the stored bytes, `exec::check`, the question, `exec::apply`), `rerun revert <txn> [--dry-run] [--yes]` (`exec::txn_status`, `exec::verify` as the preview, the question, `exec::revert`), `rerun status [--all]` (`exec::status`, journal only), `rerun forget <txn> [--yes]` (every backup and pending cleanup, `verify`, what forget does not do, the question, `exec::forget`); `apply`, `revert` and `forget` take the journal lock, the others do not. Elevated, only `system`, `scan` and `status` run (user decision E3). The rebind of a transaction whose game folder moved comes with P2-14.
- Order in `main`: `restrict_dll_search`, then clap (`--help`/`--version` and malformed plan hashes or transaction names touch neither registry nor file system), then `WinSystem::new()`. Exit codes: 0 done or report, 1 fatal without report, 2 usage (also no console without `--yes`), 3 nothing changed (refused, declined, preview not delivered), 4 rolled back, 5 open (ADR 0016 amendment P2-13).
- Modules: `messages` (every user-facing string, named parameters; the phase 2 lines in `messages::txn`), `out` (`Out`: line writer, `BrokenPipe` ends silently, last-resort net: every line through `escape::text`, a panic in tests; `prompt` for the question), `system`, `scan` (pure render functions over core values), `host` (the `Host` with the system, the install folder and the `Confirm`; the guards and the exit mapping), `confirm` (the question on stderr, only with stdin and stdout consoles), `preview` (the one renderer of a plan's preview), `plan`, `apply`, `txn` (`status`, `revert`, `forget`). Human-readable English text only, not a stable interface; untrusted fields only as `escape::Shown` (raw text through `RawText::escaped`, never `as_raw_str`; a source rule test checks it), untrusted text last on its line. Never changes console state (no `SetConsoleMode`, no `SetConsoleOutputCP`; clap without `color`); no console control handler (Ctrl+C is a crash the journal recovers from).

## rerun-launch

- Reads the launch profile of the target exe from `%LOCALAPPDATA%\Rerun\profiles\<hash>.json` (written on apply).
- Knows no Topos, no network, no registry except reading the profile.
- Target: < 1 MB, < 50 ms startup time, exits immediately (direct/watch) or together with the game (hold/ifeo).
- DLL hardening like every shipped executable (ADR 0008 amendment 2026-11-05): linked with `/DEPENDENTLOADFLAG:0x800` (`build.rs`), and the first statement of `main` restricts the DLL search path to System32 (`src/dll.rs`, its own copy of the one `SetDefaultDllDirectories` call), failing closed. `rerun` does the same through `rerun_core::sys::win::restrict_dll_search`.

## rerun-cpu (inproc)

- Loaded via Ultimate ASI Loader (`scripts/rerun-cpu.asi`) or as a proxy DLL.
- Sets affinity/CPU Sets from inside, hooks `SetProcessAffinityMask`, reports a smaller core count if needed (`GetSystemInfo`, `GetNativeSystemInfo`, possibly `GetLogicalProcessorInformation`).
- Configuration from `rerun-cpu.ini` next to it. Builds for x86 and x64.
- Cargo produces `rerun_cpu.dll`; the build step copies it to `dist/<arch>/rerun-cpu.asi` (ADR 0006). Static CRT, `panic = "abort"`.

## Frontend (app/)

- Tauri 2, Svelte 5, TypeScript, Vite. No UI library.
- Commands: `scan`, `game_detail`, `plan`, `apply(plan_hash)`, `revert(txn_id)`, `forget(txn_id)`, `status`, `system_profile`.
- The frontend holds no system state. It displays plans, the core executes.

## Network

Only two destinations: the signed Topo index (GitHub Releases of `mythenstudios/rerun-topos`) and package downloads from the hosts in `packages/`. No telemetry. Feedback = pre-filled GitHub issue in the browser.

# 01 · Architecture

## Workspace

```
rerun_/
├─ crates/
│  ├─ rerun-core/      Library: detection, Topo engine, primitives, Journal, system layer
│  ├─ rerun-proto/     Small shared types (CPU topology and its pure Windows-record parser; from Phase 3 launch profile, CPU rule), no dependencies, serde only via feature
│  ├─ rerun-cli/       Binary `rerun` (phase 1: system, scan; phase 2: plan, apply, revert, status, forget; later topo validate)
│  ├─ rerun-launch/    Binary `rerun-launch.exe` – launch shim, only windows-sys + rerun-proto
│  ├─ rerun-helper/    Binary `rerun-helper.exe` – the elevated helper (ADR 0023): only Rerun's own firewall rules; P4-2c: validation chain; P4-2d: the batch in `exec`; P4-5b: writes through COM
│  ├─ rerun-cpu/       cdylib `rerun-cpu.asi` – inproc CPU fix, x86 + x64
│  └─ rerun-workbench/ Curator tool, not shipped: build and sign the index (P4-3), later query PCGamingWiki for Topo drafts
├─ app/                Tauri 2 + Svelte 5 + TypeScript (Vite); `app/src-tauri` joins the Cargo workspace only in Phase 5
├─ topos/              Game recipes (YAML)
├─ packages/           Upstream tools (YAML)
├─ data/               Reference data (YAML): GPU architecture table `gpu-arch.yaml`
├─ schema/             JSON Schema for Topo, package, the signed index bundle and the GPU architecture table
├─ tests/fixtures/     CPU topologies, path parity cases, valid/invalid schema fixtures
└─ docs/
```

Dependencies always point to `rerun-core` or `rerun-proto`, never back.

## rerun-core: modules

| Module | Purpose |
|---|---|
| `detect` | Steam (libraryfolders.vdf, appmanifest_*.acf), GOG (registry), Ubisoft Connect, Epic, manual. PE parsing (architecture, imports → graphics API, LAA flag, version info), hashes. `detect::pe` (ADR 0013): own bounded parser over `Read + Seek`, no memory mapping and no whole-file read; `Pe::parse` reads the header region once (at most 64 KiB) and recognises DOS, NE and LE/LX executables as `Legacy`; `Headers` (machine, PE32/PE32+, characteristics with Large Address Aware and DLL, subsystem, DLL characteristics, image base, CLR header present); `imports`/`delay_imports`: DLL names only (`DllName`: 1 to 255 bytes of printable ASCII, compared ASCII case-insensitively), at most 1,024 per table, VC6 delay descriptors with virtual addresses; `dependent_load_flags` from the load config; `version_info`: the `RT_VERSION` branch at fixed depth (ID 1 else the lowest, language neutral, then en-US, then the lowest) and a tolerant VS_VERSIONINFO parser (explicit loop over four levels, the fixed part and six strings of one string table as `RawText`); `info` returns all of it, a broken version resource kept as an error next to the headers and imports; `open_game_exe(&GameDir, &RelPath, &Limits)` is the only reader for product code (handle-relative `Dir::open_read`, ADR 0007; the length is never asked for; `PeReadError` names the file, `into_inner` hands the handle back for hashing); every read is a bounded range read charged to a total budget per file (1 MiB); errors carry a kind and a file offset, never file content. `detect::exe` (ADR 0014): store-agnostic, takes a `GameDir`; `scan_game(&GameDir, &Options) -> GameExes` never fails as a whole: a breadth-first walk of the game folder (every directory opened relative to the game handle, listings sorted by folded name, names through `classify`, reparse points and restricted entries never followed, case-sensitive directories not used, a skip list for redistributable and anti-cheat folders; at most depth 3, 128 listed directories, 20,000 entries, 64 parsed executables, partial result with `complete == false` at a limit), roles from fixed name rules and PE facts (`Game`, `Launcher`, `Helper`, `CrashReporter`, `AntiCheat`, `Installer`, `NotAnApp`, `Legacy`; hints, nothing dropped), the graphics API from the static and delay imports (`ApiReport`: verdict and evidence; `GraphicsApi::topo_name` maps to the Topo `api` values, `d3d12`/`vulkan`/`glide` reserved), a ranking and the main executable (`One`, `Tied`, `None`); `inspect_exe` is the per-file pipeline (also for Topo matching) and, only with `--hashes`, streams SHA-1 and SHA-256 over the very handle that was parsed (256 KiB chunks, 2 GiB per file, 8 files and 4 GiB plus one chunk per hashed file per game, `Game` candidates only); problems are `ExeIssue`s or stay on their candidate. `detect::vdf`: pure bounded parser for Valve KeyValues text (quoted subset only, limits for bytes, depth, entries and string length, explicit stack, no recursion) and `read_store_file`, the only reader, handle-relative to a `StoreDir` through `Dir::read_limited` (`max_bytes`, more is `TooLarge`); `detect::steam::files`: typed views `LibraryFolders` (current and pre-2021 format) and `AppManifest`, untrusted text as `RawText` (`detect::text`, shared by every detector; no `Display`, `Debug` shows only the length) for `policy::root` (ADR 0011, ADR 0012). `detect::steam::scan(&dyn System, &ForbiddenRoots) -> SteamScan` (ADR 0012): never fails as a whole, every problem an `Issue` with a location; Steam root from `HKCU` `SteamPath`, then `HKLM` `InstallPath` (32-bit, then native view) through `Registry::get` only, every candidate through `StoreDir::open`, a disagreeing one reported and not scanned; library list from `steamapps\libraryfolders.vdf` (`config\libraryfolders.vdf` only on `NotFound`, never merged, at most 256), libraries de-duplicated by `RootId`; `steamapps` listed relative to each library with `Dir::read_dir_limited` (16,384 plus a margin of 1,024 entries, refused beyond it), `appmanifest_<id>.acf` plain files only (at most 16,384, counted first), `appid` equal to `<id>`, `installdir` classified; `StateFlags` → `AppState`; duplicate app IDs kept and reported; game folders only through `SteamLibrary::open_game` (`StoreDir::game`). |
| `hw` | System profile (ADR 0015): a consumer of `sys::Gpu`, `sys::Topology` and `sys::Registry`, no FFI of its own. `read(&dyn System, Option<&GpuArchTable>) -> SystemProfile` never fails as a whole (GPU, CPU and OS each a `Result`): hardware adapters in DXGI order (software and vendor `0x1414` dropped) with vendor, architecture and `integrated` from the GPU architecture table (`data/gpu-arch.yaml`; a built-in copy until the phase 4 index), the CPU topology (`03-cpu-topology.md`), the OS build from `CurrentBuildNumber`; accessors give the facts for the five `when` keys (`02-topo-format.md`). Display properties: `03b-gpu-display.md`. |
| `catalog` | The signed index and the typed catalogue (ADR 0024, ADR 0005; P4-3). `key`: two compiled-in release key slots (`RELEASE_KEYS`, current and next; empty until the release key is generated offline, then every index is refused with `NoKeys`), `RETIRED_KEYS` (former release keys, only for `store::by_hash` through `revert_keys()`), `REVOKED_KEYS` (refused by `verify` everywhere, `Revoked`), `KeyId` (first 8 bytes of SHA-256 over the key), the published test key only with the feature `test-key` (dev-dependencies only). `verify(index, sig, keys) -> Verified`: at most `MAX_INDEX_BYTES` (8 MiB), a signature of exactly 64 bytes, Ed25519 over the raw bytes (`ed25519-compact`, verification only) before anything is parsed. `Catalog::from_verified`: `format` first, then `model::Index` (`deny_unknown_fields` everywhere, `RelPath`, typed hashes, the planners' step specs reused) and `check_index` (`check::topo`/`check::package` with `Rules::Release`: no draft, no `TODO`; IDs sorted and unique; every referenced package present); lookups by ID. `check`: the schema rules the types cannot carry plus loader rules (unique issue and variant IDs, registry vendor deny list, provenance, `TODO` ⇒ draft with `Rules::Source`). `store`: `<AppDir>\index` (`<sha256>.json`/`.sig` kept per accepted index, `current.json` pointer with the `seq` floor, `lock`); `import` (rollback and same-`seq` refused), `current` and `by_hash` (the index a transaction was applied with, signature only, no floor; condition R1) re-check everything they read. |
| `topo` | The Topo engine (P4-4, ADR 0020 amendment P4-4): `read_game` (every `match.exes` entry hashed on its parsed handle, anti-cheat markers through `detect::exe::anti_cheat`), `when::eval` (ADR 0015, three-valued), `report` (issues, `when`, variants, refusals; preselects nothing), `plan` (picked variants to the existing steps, `auto` resolved, `PlanSource` set, then `prim::plan`; P4-7: a `package` step becomes a `file_install` step through `prim::package`, for the matched entry's architecture and `api`, a package's `requires` in the same plan), `policy::ANTI_CHEAT_RULES` (refuse or warn per step kind, also for later kinds; user decision E4). |
| `pkg` | Packages (ADR 0025). P4-6 `pkg::download`: `downloads` (a package's `source.release` or `assets[]`, form and provenance checked again; none for `community` or `TODO`) and `fetch` (non-elevated only; `<AppDir>\cache` handle-relative under `cache\lock`, leftover temp files swept; a cache entry `<sha256>` hashed on a guard before every use, replaced if it does not match; the request chain over `sys::Http` with every redirect through `policy::url::HttpsUrl::redirect`, at most 3; `Content-Length` advisory, at most `MAX_DOWNLOAD_BYTES` (64 MiB) counted on the bytes read and `MAX_DOWNLOAD_TIME` (10 minutes) overall; the body streamed through `DirWrite::create_new`, kept only with the pinned SHA-256). P4-7 `pkg::archive`: Rerun's own bounded zip and tar.gz readers (inflate by `miniz_oxide`; the whole archive in memory, its structure checked before any content, one name rule for every entry, only files and folders, limits); `pkg::extract`: only the files a package names, from the cached archive hashed again, into `<AppDir>\packages\<id>\<version>` (`<arch>\` below it for `assets`) under `packages\.lock`, each kept only with its pinned SHA-256 (ADR 0025 part 2). |
| `prim` | Primitives as planners (ADR 0020, see below): durable spec types (`deny_unknown_fields`) and one planner each, turning a step into ops; no system writes. P2-13: `PlanCtx::app` is an `Option` (`plan --dry-run` creates no `AppDir`: `file_install` refused, `compat_layer` looks up no transaction); `StepFile` (`prim::step_file`), the step file of `rerun plan <steps.json>`: since P4-4 the local, unsigned input (L8; no `PlanSource`, never a helper op; the anti-cheat rule applies as to a Topo plan), removed at the earliest before A6. P4-7: `prim::package::file_install` (pure) turns a package of the signed index into the `file_install` step of its files for the game's architecture and API, sources placed by `Package::place` (ADR 0020 amendment P4-7). |
| `plan` | `Plan` (ADR 0020): `format`, `roots[]` (kind, canonical path, `RootId`, origin, main executable) and `ops`, each file op with its root index; op kinds `CreateDir`, `CreateFile`, `ReplaceFile`, `CreateKey`, `SetValue`, `IniValue`, `TokenList`; ops with equal old and new state omitted; serialised once, `PlanHash` = SHA-256 over the stored bytes (`BTreeMap` only, IDs and bytes as hex). Phase 4: conflicts (DLL slots, dependencies). P4-8: the op kind `Hold` (a package file the game folder holds already with the step's content: nothing written, an object for stacking; `Op::package_file` names it with the written package files), `HOLD_NOTE` in the preview (ADR 0020 amendment P4-8). P2-13: `load` (public), `preview_stored` (the preview of stored bytes, current rules) and `preview_head` (a recorded head, recorded rules, registry data only by type, length and SHA-256). P3-3a: the root kind `Profiles` (`PlanOrigin::AppDir`, `PROFILES_ROOT_ID`: `<LocalAppData>\Rerun\profiles` without identity), `ContentRef::Inline` (at most 2 KiB, hex), `profile_id` (from the Steam app ID), the fence of both in `plan::profile` (ADR 0020 amendment P3-3); the preview decodes the profile (`ProfilePreview`). |
| `exec` | Apply, verify, revert and forget per op kind (ADR 0020): checks before the first change (lock, hash, root identity, Steam state, game closed via `users()`, stacking, old state re-observed), `Observed` (`Before`, `After`, `Drifted`, `Foreign`), a foreign state is never overwritten (`forget` instead), immediate rollback on failure, a rebind under strict conditions (P2-14). P2-8: `ExecCtx { sys, fr, app, tag }`, `apply` (`Outcome::{Nothing, Applied}`, `ApplyError::{Refused, RolledBack, LeftOpen}`), `verify` (read only), `revert` (also recovery and, on the same writer, the rollback; `RevertReport`), `forget`; modules `roots` (reopen, Steam, `users()`, old state), `stack` (stacking and LIFO on the listing), `file` (the file op kinds: apply, observe, act). P2-10a: dispatch by `Op::target()` to the module of the op's domain (`file`, and `reg` for registry keys and values since P2-10b), one revert loop; a revert opens each root on its own and halts at a file op whose root does not open (`Halt`, `Verified`). P2-10b: `reg` (apply, observe, act, records of `CreateKey`/`SetValue` through `policy::registry`), `Refusal::{Registry, Elevated}`, `HKCU` flushed before `Applied` and before each registry op's `RevertDone`. P2-11: `TokenList` in `reg` (semantic revert of a shared compatibility-layer value through `RegWriter::add_tokens`/`remove_tokens`, `Drifted`; the shared keys `AppCompatFlags`/`Layers` left when not empty), recorded heads decoded with `plan::Rules::Recorded`. P2-12: `ini` (`IniValue`, a file op whose apply, observation and record check go to `exec::ini`: the edited bytes from `policy::ini`, a semantic rewrite of a file the game rewrote with `from`/`to` in its `RevertIntent`, the binding of a recorded head to its backups before a revert and `verify`, a `Detail` per op in `verify` and the report). P2-13: `check` (every check of `apply` before `begin`, read only, one `preflight` chain with `apply`; an existing lock file held read side), `standard_user` (user decision E3: `apply`, `check`, `revert` and `forget` refuse an elevated or undeterminable process for every plan), `status`/`txn_status` (journal only: `TxnStatus`, `TxnLine`, `OpStatus`, `OpState`, `Backup`), `OpReport::backup` typed (`Backup::{Bin, Inline}`), a revert error before the run's first record is `Refused` (`Refusal::Observe`), a closing entry that may be on disk `Unconfirmed`; `revert_check` (every check of `revert` before its first record, read only, the same chain); a damaged transaction with a usable head blocks applies and earlier reverts on its objects. P2-14: `bind` (`Bindings`: the binding of each root of a recorded head, the head's root or the folder of the last `Rebind` of that root, checked against the head on every revert, `verify` and stacking; a binding acts only where a root is opened, registry locations stay the head's; `CreateDir` proven by the record's file IDs) and `rebind` (`rebind_check(cx, txn) -> RebindPreview`: the one root that does not open, the one Steam library the Steam scan finds holding the app, every check read only, the preview with the binding before and after, the observation there and the created folders; `revert_rebound(cx, txn, &RebindTo)`: the scan and every check again under the lock, `Changed` on any difference, the `Rebind` record, the revert loop; `RebindRefusal`), `TxnStatus::rebinds` (`RebindLine`). P3-2: `launch_results` (the result files of `rerun-launch` in `<AppDir>\launch`, read handle-relative, bounded and decoded as untrusted input with `rerun_proto::launch`; `launch_result` re-exports the result types for front ends). P3-3a: `roots::Opened { Game, Profiles }` (the profiles root opened through `AppDir::profiles`, created by the apply, never by a revert; another path than the plan's refuses an apply, `Refusal::ProfilesMoved`, and is reported by a revert and `verify`, `profiles_moved`); `file` streams inline content; no journal change. P4-2d (`exec::helper`, ADR 0023 §9, ADR 0020 amendment P4-2d): the helper batch of `FirewallRule` ops, last on apply and first on revert: the helper's pre-check and prompt state before the lock, the plan check again before `begin` (A4 S7), the request file `<AppDir>\elevate\<txn>-<n>.req` under the lock (N9), `HelperBatch`, one helper run, `Done` only when the helper and the CLI's own observation agree; a declined or refused batch rolls back the earlier ops, an unknown result stays open (`ApplyError::HelperOpen`); `ensure_idle` before a batch without a result (A4 S8); `firewall_orphans` for `status`. P4-8 (ADR 0020 amendment P4-8): `Hold` in `file` (re-observed on a guard before `Intent`, never `Foreign`, its revert acts on nothing), `stack` refuses the revert of a transaction whose file a later one holds (`Refusal::Held`) and an apply whose package DLL lies where a live transaction has another package's DLL (`Refusal::SlotTaken`, from the heads; `slot_taken_now` for the planner). |
| `journal` | File-based (ADR 0019) under `AppDir` (`<LocalAppData>\Rerun\journal`): one folder per transaction with `head.json` (the plan bytes, opaque to the journal) and immutable numbered records (`NNNN.json`) and backups (`op-NNNN.bin`), each written once with `create_new`; one grammar (`journal::replay`) for reader and writer; `TxnWriter` for an apply, `RevertWriter` (revert only) for a resumed transaction; write-ahead (backup read back and hashed, then the intent, then the change); flush of every changed file, parent folder and registry key before the closing record; `journal\lock` (share 0) held by apply, revert and forget; untrusted reader with budgets; LIFO revert per object. ## Primitives

A primitive is a planner (ADR 0020, user decision D9): it turns its spec into ops of a few generic kinds, and `exec` applies, verifies and reverts each op kind with the journal (ADR 0019). Every primitive still needs its own round-trip test (`docs/09-testing.md`).

```rust
pub enum Step { FileInstall(FileInstallSpec), RegistrySet(RegistrySetSpec),
                CompatLayer(CompatLayerSpec), IniSet(IniSetSpec) }
pub fn plan(steps: &[Step], ctx: &PlanCtx<'_>) -> Result<Plan, PlanError>; // GameDir, AppDir, RegPolicy; reads only
```

Phase 2: `file_install` (local package files under `<AppDir>\packages`; `prim::file_install`, done in P2-8: `PlanCtx { game, app, steam_app, main_exe }`, the `RegPolicy` joins with P2-9), `registry_set` (`prim::registry_set`, P2-10b: values below `HKCU\Software\<Vendor>\<Product>`, read through `PlanCtx::reg`, a `RegReader` of `policy::registry`; the builder puts every registry op after every file op), `compat_layer` (`prim::compat_layer`, P2-11: tokens for an executable of the game folder in `AppCompatFlags\Layers` as a `TokenList` op; the executable in its stored spelling, a game folder reached through a link refused through `GameDir::launch_path`; the token allowlist from the Sandbox probes, P2-11b), `ini_set` (`prim::ini_set`, P2-12: keys of an existing `.ini` file of the game folder as one `IniValue` op per file with its edits, read and edited through `policy::ini`, ADR 0021; the file in its stored spelling, a missing file refused, the main executable required). Until the Topo engine (phase 4) `rerun plan` reads a JSON step file whose step objects are the durable spec types (ADR 0020, D7). Phase 3: `launch_method` (`prim::launch_method`, P3-3c: the launch profile of a Steam game as op 0 on the plan root `<LocalAppData>\Rerun\profiles` with inline content, `PlanCtx::app_path` for a dry run before the first run; `start` is Steam's launch entry, the bitness from the PE machine of `start` and the main executable, a launcher only with a hard rule; `on_this_machine` is the preview's selection on the topology now, never in the plan; ADR 0022 amendment P3-3). Phase 4: the Topo step `package` is planned as `file_install` (`prim::package`, P4-7): the files for the main executable's architecture and the `api` of the `match.exes` entry that matched, from `<AppDir>\packages\<id>\<version>` (`<arch>\` below it for `assets`), unpacked there by `rerun package fetch`; the planner never downloads or unpacks.

## Data flow

```
detect ─► hw ─► topo(when) ─► plan ─► [preview UI/CLI] ─► apply ─► journal
                                                     └► elevate (admin parts only)
start: Steam %command% / IFEO ─► rerun-launch ─► read profile ─► method ─► check ─► exit
revert: journal ─► observe each op (never overwrite a foreign state) ─► restore backups / values, LIFO ─► (later: firewall phase 4, launch option phase 5, IFEO phase 6) ─► folder comparison
```

## rerun-cli

- Phase 1 (ADR 0016): `rerun system` (`hw::read` with the built-in GPU table: GPU, CPU topology, OS build, the five condition facts) and `rerun scan [APP_ID…] [--hashes]` (`ForbiddenRoots` from its own install folder, `steam::scan`, per installed app `open_game` + `scan_game`, streamed per game; apps Steam is updating are listed, never opened).
- Phase 2 (ADR 0020, P2-13; ADR 0016 amendment P2-13): `rerun plan <steps.json> [--dry-run]` (the step file through `policy::root::read_input` and `prim::StepFile`, the preview of the encoded bytes, then `plan::store`; `--dry-run` creates nothing), `rerun apply <plan-hash> [--dry-run] [--yes]` (the preview of the stored bytes, `exec::check`, the question, `exec::apply`), `rerun revert <txn> [--dry-run] [--yes]` (`exec::txn_status`, `exec::verify` as the preview, the question, `exec::revert`), `rerun status [--all]` (`exec::status`, journal only), `rerun forget <txn> [--yes]` (every backup and pending cleanup, `verify`, what forget does not do, the question, `exec::forget`); `apply`, `revert` and `forget` take the journal lock, the others do not. Elevated, only `system`, `scan`, `status` and (phase 4) `index show` run (user decision E3). P2-14: `rerun revert <txn> --rebind [--dry-run]` (`exec::rebind_check` as the preview, the question at a console only, `exec::revert_rebound`; ADR 0016 amendment P2-14).
- Phase 4 (P4-6, ADR 0025): `rerun package fetch <id>@<version>`: every download of a package of the current signed index into `<LocalAppData>\Rerun\cache` through `pkg::download::fetch` (refused elevated; another version than the index's is refused, user decision E2 a); exit codes per error in ADR 0025 (3 refused, 1 passing, 0 also after partial progress). P4-7: then unpacks the package's files through `pkg::extract` (one line per file).
- Phase 4 (P4-4): `rerun plan <app-id> [--pick <issue>/<variant>]… [--dry-run]` plans from the current signed index through `topo` (a target of digits only; anything else is a step file); without `--pick` a report only.
- Phase 4 (ADR 0024, P4-3): `rerun index import <index.json> <index.json.sig>` (both files through `policy::root::read_input`, the index at most 8 MiB, the signature at most 64 bytes; verified and checked before Rerun's folder is created, then `catalog::store::import`; refused elevated) and `rerun index show` (`catalog::store::current`, checked again; creates nothing). No network: a download replaces only how the two files arrive.
- Order in `main`: `restrict_dll_search`, then clap (`--help`/`--version` and malformed plan hashes or transaction names touch neither registry nor file system), then `WinSystem::new()`. Exit codes: 0 done or report, 1 fatal without report, 2 usage (also no console without `--yes`), 3 nothing changed (refused, declined, preview not delivered), 4 rolled back, 5 open (ADR 0016 amendment P2-13).
- Modules: `messages` (every user-facing string, named parameters; the phase 2 lines in `messages::txn`), `out` (`Out`: line writer, `BrokenPipe` ends silently, last-resort net: every line through `escape::text`, a panic in tests; `prompt` for the question), `system`, `scan` (pure render functions over core values), `host` (the `Host` with the system, the install folder and the `Confirm`; the guards and the exit mapping), `confirm` (the question on stderr, only with stdin and stdout consoles), `preview` (the one renderer of a plan's preview), `plan`, `apply`, `txn` (`status`, `revert`, `forget`). Human-readable English text only, not a stable interface; untrusted fields only as `escape::Shown` (raw text through `RawText::escaped`, never `as_raw_str`; a source rule test checks it), untrusted text last on its line. Never changes console state (no `SetConsoleMode`, no `SetConsoleOutputCP`; clap without `color`); no console control handler (Ctrl+C is a crash the journal recovers from).

## rerun-launch

- Reads the launch profile named by `--profile <id>` from `%LOCALAPPDATA%\Rerun\profiles\<id>.profile` (format 1, written on apply; ADR 0022).
- Knows no Topos, no network and no registry; the launch profile it reads is a file.
- Checks the rule about 5 s after the start and writes the outcome of the last start to `%LOCALAPPDATA%\Rerun\launch\<id>.result` (format 1, `rerun_proto::launch`; never when elevated; its only file write, one wrapper module; ADR 0022 amendment P3-2).
- `watch` (ADR 0022 amendment P3-4): starts Steam's command unchanged, then looks for a new process of the profile's `target` (Toolhelp32 snapshot as a name pre-filter; image path, creation time and token read through a handle opened with query rights; `win::process`), sets its priority class and then a new job with the selection (or its default CPU Sets) from outside (`win::launch`), reads the join back, checks about 5 s later; never ends a found process.
- Target: < 1 MB, < 50 ms startup time until `CreateProcessW`. Lifetime (ADR 0022, B3): `direct` waits until the started process exits and passes its exit code on; `watch` lives at least as long as the started process and at most until the target is found and checked; `hold`/`ifeo` together with the game. No console window (`windows_subsystem = "windows"`).
- DLL hardening like every shipped executable (ADR 0008 amendment 2026-11-05): linked with `/DEPENDENTLOADFLAG:0x800` (`build.rs`), and the first statement of `main` restricts the DLL search path to System32 (`src/dll.rs`, its own copy of the one `SetDefaultDllDirectories` call), failing closed. `rerun` does the same through `rerun_core::sys::win::restrict_dll_search`.

## rerun-helper

- The elevated helper (ADR 0023): started by `rerun apply` or `rerun revert` through `runas`, at most once per run, for one batch of Rerun's own firewall rules; installed only at `<FOLDERID_ProgramFiles>\Rerun\rerun-helper.exe`. No console (`windows_subsystem = "windows"`), no output, no file writes; the exit code (ADR 0023 §7) is its only report.
- Linked with `/DEPENDENTLOADFLAG:0x800` and an embedded `asInvoker` manifest (`build.rs`); `main` calls `restrict_dll_search` first, then `rerun_core::elevate::serve` with `WinHelperSystem` (no GPU, no topology, no registry; the firewall through COM since P4-5b). It never names `WinSystem`, `WinGpu`, DXGI, `hw`, the journal or `exec` (source rule), its static imports are `HELPER_IMPORTS`, and its image names neither `dxgi.dll` nor `CreateDXGIFactory1` (`tests/hardening.rs`; ADR 0008 amendment P4-2a).
- Feature `test-key` (the published index test key, for the [SB] and [DEV] helper only): `compile_error!` without debug assertions; CI checks that the shipped build does not enable it and that the release binary does not hold the key (A4 S3).

## rerun-cpu (inproc)

- Loaded via Ultimate ASI Loader (`scripts/rerun-cpu.asi`) or as a proxy DLL.
- Sets affinity/CPU Sets from inside, hooks `SetProcessAffinityMask`, reports a smaller core count if needed (`GetSystemInfo`, `GetNativeSystemInfo`, possibly `GetLogicalProcessorInformation`).
- Configuration from `rerun-cpu.ini` next to it. Builds for x86 and x64.
- Cargo produces `rerun_cpu.dll`; the build step copies it to `dist/<arch>/rerun-cpu.asi` (ADR 0006). Static CRT, `panic = "abort"`.

## Frontend (app/)

- Tauri 2, Svelte 5, TypeScript, Vite. No UI library.
- Commands: `scan`, `game_detail`, `plan`, `apply(plan_hash)`, `revert(txn_id)`, `forget(txn_id)`, `status`, `system_profile`.
- The frontend holds no system state. It displays plans, the core executes.

## Network

Only two destinations: the signed Topo index (GitHub Releases of `mythenstudios/rerun-topos`; until phase 6 imported from files, user decision E5) and package downloads from the hosts in `packages/` (P4-6, ADR 0025: one wrapper `sys::win::http` over WinHTTP, TLS with Windows certificate validation, the system proxy, redirects checked by hand against a fixed host list, nothing kept unless it hashes to its pin; never from the elevated helper). No telemetry. Feedback = pre-filled GitHub issue in the browser. The curator tool `rerun-workbench` is not shipped; its PCGamingWiki query (P4-14) will use the same wrapper and is outside this rule.

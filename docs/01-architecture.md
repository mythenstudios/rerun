# 01 · Architecture

## Workspace

```
rerun_/
├─ crates/
│  ├─ rerun-core/      Library: detection, Topo engine, primitives, Journal, system layer
│  ├─ rerun-proto/     Small shared types (CPU topology and its pure Windows-record parser; from Phase 3 launch profile, CPU rule), no dependencies, serde only via feature
│  ├─ rerun-cli/       Binary `rerun` (phase 1: system, scan; phase 2: plan, apply, revert, status, forget; later topo validate)
│  ├─ rerun-launch/    Binary `rerun-launch.exe` – launch shim, only windows-sys + rerun-proto
│  ├─ rerun-cpu/       cdylib `rerun-cpu.asi` – inproc CPU fix, x86 + x64
│  └─ rerun-workbench/ Curator tool, not shipped: build and sign the index (P4-3), later query PCGamingWiki for Topo drafts
├─ app/                Tauri 2 + Svelte 5 + TypeScript (Vite); `app/src-tauri` joins the Cargo workspace only in Phase 5
├─ topos/              Game recipes (YAML)
├─ packages/           Upstream tools (YAML)
├─ data/               Reference data (YAML): GPU architecture table `gpu-arch.yaml`
├─ schema/             JSON Schema for Topo, package, the signed index bundle and the GPU architecture table
├─ tests/fixtures/     CPU topologies, path parity cases, valid/invalid schema fixtures
└─ docs/
```

Dependencies always point to `rerun-core` or `rerun-proto`, never back.

## rerun-core: modules

`detect::steam::files`: typed views `LibraryFolders` (current and pre-2021 format) and `AppManifest`, untrusted text as `RawText` (`detect::text`, shared by every detector; no `Display`, `Debug` shows only the length) for `policy::root` (ADR 0011, ADR 0012). `detect::steam::scan(&dyn System, &ForbiddenRoots) -> SteamScan` (ADR 0012): never fails as a whole, every problem an `Issue` with a location; library list from `steamapps\libraryfolders.vdf` (`config\libraryfolders.vdf` only on `NotFound`, never merged, at most 256), libraries de-duplicated by `RootId`; `steamapps` listed relative to each library with `Dir::read_dir_limited` (16,384 plus a margin of 1,024 entries, refused beyond it), `appmanifest_<id>.acf` plain files only (at most 16,384, counted first), `appid` equal to `<id>`, `installdir` classified; `StateFlags` → `AppState`; duplicate app IDs kept and reported; game folders only through `SteamLibrary::open_game` (`StoreDir::game`). |
| `hw` | System profile (ADR 0015): a consumer of `sys::Gpu`, `sys::Topology` and `sys::Registry`, no FFI of its own. `read(&dyn System, Option<&GpuArchTable>) -> SystemProfile` never fails as a whole (GPU, CPU and OS each a `Result`): hardware adapters in DXGI order (software and vendor `0x1414` dropped) with vendor, architecture and `integrated` from the GPU architecture table (`data/gpu-arch.yaml`; a built-in copy until the phase 4 index), the CPU topology (`03-cpu-topology.md`), the OS build from `CurrentBuildNumber`; accessors give the facts for the five `when` keys (`02-topo-format.md`). Display properties: `03b-gpu-display.md`. |
| `catalog` | The signed index and the typed catalogue (ADR 0024, ADR 0005; P4-3). `key`: two compiled-in release key slots (`RELEASE_KEYS`, current and next; empty until the release key is generated offline, then every index is refused with `NoKeys`), `RETIRED_KEYS` (former release keys, only for `store::by_hash` through `revert_keys()`), `REVOKED_KEYS` (refused by `verify` everywhere, `Revoked`), `KeyId` (first 8 bytes of SHA-256 over the key), the published test key only with the feature `test-key` (dev-dependencies only). `verify(index, sig, keys) -> Verified`: at most `MAX_INDEX_BYTES` (8 MiB), a signature of exactly 64 bytes, Ed25519 over the raw bytes (`ed25519-compact`, verification only) before anything is parsed. `Catalog::from_verified`: `format` first, then `model::Index` (`deny_unknown_fields` everywhere, `RelPath`, typed hashes, the planners' step specs reused) and `check_index` (`check::topo`/`check::package` with `Rules::Release`: no draft, no `TODO`; IDs sorted and unique; every referenced package present); lookups by ID. `check`: the schema rules the types cannot carry plus loader rules (unique issue and variant IDs, registry vendor deny list, provenance, `TODO` ⇒ draft with `Rules::Source`). `store`: `<AppDir>\index` (`<sha256>.json`/`.sig` kept per accepted index, `current.json` pointer with the `seq` floor, `lock`); `import` (rollback and same-`seq` refused), `current` and `by_hash` (the index a transaction was applied with, signature only, no floor; condition R1) re-check everything they read. |
| `topo` | The Topo engine (P4-4, ADR 0020 amendment P4-4): `read_game` (every `match.exes` entry hashed on its parsed handle, anti-cheat markers through `detect::exe::anti_cheat`), `when::eval` (ADR 0015, three-valued), `report` (issues, `when`, variants, refusals; preselects nothing), `plan` (picked variants to the existing steps, `auto` resolved, `PlanSource` set, then `prim::plan`), `policy::ANTI_CHEAT_RULES` (refuse or warn per step kind, also for later kinds; user decision E4). |
| `pkg` | Packages: download (allowed hosts only), SHA256, extraction (Zip Slip safe), cache. |
| `prim` | Primitives as planners (ADR 0020, see below): durable spec types (`deny_unknown_fields`) and one planner each, turning a step into ops; no system writes. P2-13: `PlanCtx::app` is an `Option` (`plan --dry-run` creates no `AppDir`: `file_install` refused, `compat_layer` looks up no transaction); `StepFile` (`prim::step_file`), the throwaway step-file wrapper of `rerun plan` until phase 4. |
| `plan` | `Plan` (ADR 0020): `format`, `roots[]` (kind, canonical path, `RootId`, origin, main executable) and `ops`, each file op with its root index; op kinds `CreateDir`, `CreateFile`, `ReplaceFile`, `CreateKey`, `SetValue`, `IniValue`, `TokenList`; ops with equal old and new state omitted; serialised once, `PlanHash` = SHA-256 over the stored bytes (`BTreeMap` only, IDs and bytes as hex). Phase 4: conflicts (DLL slots, dependencies). P2-13: `load` (public), `preview_stored` (the preview of stored bytes, current rules) and `preview_head` (a recorded head, recorded rules, registry data only by type, length and SHA-256). P3-3a: the root kind `Profiles` (`PlanOrigin::AppDir`, `PROFILES_ROOT_ID`: `<LocalAppData>\Rerun\profiles` without identity), `ContentRef::Inline` (at most 2 KiB, hex), `profile_id` (from the Steam app ID), the fence of both in `plan::profile` (ADR 0020 amendment P3-3); the preview decodes the profile (`ProfilePreview`). |
| `exec` | Apply, verify, revert and forget per op kind (ADR 0020): checks before the first change (lock, hash, root identity, Steam state, game closed via `users()`, stacking, old state re-observed), `Observed` (`Before`, `After`, `Drifted`, `Foreign`), a foreign state is never overwritten (`forget` instead), immediate rollback on failure, a rebind under strict conditions (P2-14). P2-8: `ExecCtx { sys, fr, app, tag }`, `apply` (`Outcome::{Nothing, Applied}`, `ApplyError::{Refused, RolledBack, LeftOpen}`), `verify` (read only), `revert` (also recovery and, on the same writer, the rollback; `RevertReport`), `forget`; modules `roots` (reopen, Steam, `users()`, old state), `stack` (stacking and LIFO on the listing), `file` (the file op kinds: apply, observe, act). P2-10a: dispatch by `Op::target()` to the module of the op's domain (`file`, and `reg` for registry keys and values since P2-10b), one revert loop; a revert opens each root on its own and halts at a file op whose root does not open (`Halt`, `Verified`). P2-10b: `reg` (apply, observe, act, records of `CreateKey`/`SetValue` through `policy::registry`), `Refusal::{Registry, Elevated}`, `HKCU` flushed before `Applied` and before each registry op's `RevertDone`. P2-11: `TokenList` in `reg` (semantic revert of a shared compatibility-layer value through `RegWriter::add_tokens`/`remove_tokens`, `Drifted`; the shared keys `AppCompatFlags`/`Layers` left when not empty), recorded heads decoded with `plan::Rules::Recorded`. P2-12: `ini` (`IniValue`, a file op whose apply, observation and record check go to `exec::ini`: the edited bytes from `policy::ini`, a semantic rewrite of a file the game rewrote with `from`/`to` in its `RevertIntent`, the binding of a recorded head to its backups before a revert and `verify`, a `Detail` per op in `verify` and the report). P2-13: `check` (every check of `apply` before `begin`, read only, one `preflight` chain with `apply`; an existing lock file held read side), `standard_user` (user decision E3: `apply`, `check`, `revert` and `forget` refuse an elevated or undeterminable process for every plan), `status`/`txn_status` (journal only: `TxnStatus`, `TxnLine`, `OpStatus`, `OpState`, `Backup`), `OpReport::backup` typed (`Backup::{Bin, Inline}`), a revert error before the run's first record is `Refused` (`Refusal::Observe`), a closing entry that may be on disk `Unconfirmed`; `revert_check` (every check of `revert` before its first record, read only, the same chain); a damaged transaction with a usable head blocks applies and earlier reverts on its objects. P2-14: `bind` (`Bindings`: the binding of each root of a recorded head, the head's root or the folder of the last `Rebind` of that root, checked against the head on every revert, `verify` and stacking; a binding acts only where a root is opened, registry locations stay the head's; `CreateDir` proven by the record's file IDs) and `rebind` (`rebind_check(cx, txn) -> RebindPreview`: the one root that does not open, the one Steam library the Steam scan finds holding the app, every check read only, the preview with the binding before and after, the observation there and the created folders; `revert_rebound(cx, txn, &RebindTo)`: the scan and every check again under the lock, `Changed` on any difference, the `Rebind` record, the revert loop; `RebindRefusal`), `TxnStatus::rebinds` (`RebindLine`). P3-2: `launch_results` (the result files of `rerun-launch` in `<AppDir>\launch`, read handle-relative, bounded and decoded as untrusted input with `rerun_proto::launch`; `launch_result` re-exports the result types for front ends). P3-3a: `roots::Opened { Game, Profiles }` (the profiles root opened through `AppDir::profiles`, created by the apply, never by a revert; another path than the plan's refuses an apply, `Refusal::ProfilesMoved`, and is reported by a revert and `verify`, `profiles_moved`); `file` streams inline content; no journal change. |
| `journal` | File-based (ADR 0019) under `AppDir` (`<LocalAppData>\Rerun\journal`): one folder per transaction with `head.json` (the plan bytes, opaque to the journal) and immutable numbered records (`NNNN.json`) and backups (`op-NNNN.bin`), each written once with `create_new`; one grammar (`journal::replay`) for reader and writer; `TxnWriter` for an apply, `RevertWriter` (revert only) for a resumed transaction; write-ahead (backup read back and hashed, then the intent, then the change); flush of every changed file, parent folder and registry key before the closing record; `journal\lock` (share 0) held by apply, revert and forget; untrusted reader with budgets; LIFO revert per object. P2-10a: one record form for files, keys and values (`Intent.before` as `.bin` or inline up to 16 KiB, `Done.file_id` optional, `RevertIntent { from, to }` reserved for P2-12; P2-11 does without it). |
| `elevate` | Phase 4 (moved from phase 3; audit A4 before it): parts of a plan that need admin go to a short-lived elevated helper (ShellExecute `runas`), which re-validates, executes, exits. Its form (a separate crate such as `rerun-helper`, or a mode of `rerun.exe`) is decided by the phase 4 helper plan; nothing of it exists yet. |

## Primitives

A primitive is a planner (ADR 0020, user decision D9): it turns its spec into ops of a few generic kinds, and `exec` applies, verifies and reverts each op kind with the journal (ADR 0019). Every primitive still needs its own round-trip test (`docs/09-testing.md`).

```rust
pub enum Step { FileInstall(FileInstallSpec), RegistrySet(RegistrySetSpec),
                CompatLayer(CompatLayerSpec), IniSet(IniSetSpec) }
pub fn plan(steps: &[Step], ctx: &PlanCtx<'_>) -> Result<Plan, PlanError>; // GameDir, AppDir, RegPolicy; reads only
```

Phase 2: `file_install` (local package files under `<AppDir>\packages`; `prim::file_install`, done in P2-8: `PlanCtx { game, app, steam_app, main_exe }`, the `RegPolicy` joins with P2-9), `registry_set` (`prim::registry_set`, P2-10b: values below `HKCU\Software\<Vendor>\<Product>`, read through `PlanCtx::reg`, a `RegReader` of `policy::registry`; the builder puts every registry op after every file op), `compat_layer` (`prim::compat_layer`, P2-11: tokens for an executable of the game folder in `AppCompatFlags\Layers` as a `TokenList` op; the executable in its stored spelling, a game folder reached through a link refused through `GameDir::launch_path`; the token allowlist from the Sandbox probes, P2-11b), `ini_set` (`prim::ini_set`, P2-12: keys of an existing `.ini` file of the game folder as one `IniValue` op per file with its edits, read and edited through `policy::ini`, ADR 0021; the file in its stored spelling, a missing file refused, the main executable required). Until the Topo engine (phase 4) `rerun plan` reads a JSON step file whose step objects are the durable spec types (ADR 0020, D7). Phase 3: `launch_method` (`prim::launch_method`, P3-3c: the launch profile of a Steam game as op 0 on the plan root `<LocalAppData>\Rerun\profiles` with inline content, `PlanCtx::app_path` for a dry run before the first run; `start` is Steam's launch entry, the bitness from the PE machine of `start` and the main executable, a launcher only with a hard rule; `on_this_machine` is the preview's selection on the topology now, never in the plan; ADR 0022 amendment P3-3).

|---|---|---|

| `priority` | Not a primitive of its own: a field of the launch profile (`launch_method`); `rerun-launch` sets the priority class of the process it starts or finds, which ends with that process (user decision D6 a; no IFEO `PerfOptions`) | no |

## Data flow

```
detect ─► hw ─► topo(when) ─► plan ─► [preview UI/CLI] ─► apply ─► journal
                                                     └► elevate (admin parts only)
start: Steam %command% / IFEO ─► rerun-launch ─► read profile ─► method ─► check ─► exit
revert: journal ─► observe each op (never overwrite a foreign state) ─► restore backups / values, LIFO ─► (later: firewall phase 4, launch option phase 5, IFEO phase 6) ─► folder comparison
```

## rerun-cli

- Phase 1 (ADR 0016): `rerun system` (`hw::read` with the built-in GPU table: GPU, CPU topology, OS build, the five condition facts) and `rerun scan [APP_ID…] [--hashes]` (`ForbiddenRoots` from its own install folder, `steam::scan`, per installed app `open_game` + `scan_game`, streamed per game; apps Steam is updating are listed, never opened).
- Phase 2 (ADR 0020, P2-13; ADR 0016 amendment P2-13): `rerun plan <steps.json> [--dry-run]` (the step file through `policy::root::read_input` and `prim::StepFile`, the preview of the encoded bytes, then `plan::store`; `--dry-run` creates nothing), `rerun apply <plan-hash> [--dry-run] [--yes]` (the preview of the stored bytes, `exec::check`, the question, `exec::apply`), `rerun revert <txn> [--dry-run] [--yes]` (`exec::txn_status`, `exec::verify` as the preview, the question, `exec::revert`), `rerun status [--all]` (`exec::status`, journal only), `rerun forget <txn> [--yes]` (every backup and pending cleanup, `verify`, what forget does not do, the question, `exec::forget`); `apply`, `revert` and `forget` take the journal lock, the others do not. Elevated, only `system`, `scan`, `status` and (phase 4) `index show` run (user decision E3). P2-14: `rerun revert <txn> --rebind [--dry-run]` (`exec::rebind_check` as the preview, the question at a console only, `exec::revert_rebound`; ADR 0016 amendment P2-14).
- Phase 4 (P4-4): `rerun plan <app-id> [--pick <issue>/<variant>]… [--dry-run]` plans from the current signed index through `topo` (a target of digits only; anything else is a step file); without `--pick` a report only.
- Phase 4 (ADR 0024, P4-3): `rerun index import <index.json> <index.json.sig>` (both files through `policy::root::read_input`, the index at most 8 MiB, the signature at most 64 bytes; verified and checked before Rerun's folder is created, then `catalog::store::import`; refused elevated) and `rerun index show` (`catalog::store::current`, checked again; creates nothing). No network: a download replaces only how the two files arrive.
- Order in `main`: `restrict_dll_search`, then clap (`--help`/`--version` and malformed plan hashes or transaction names touch neither registry nor file system), then `WinSystem::new()`. Exit codes: 0 done or report, 1 fatal without report, 2 usage (also no console without `--yes`), 3 nothing changed (refused, declined, preview not delivered), 4 rolled back, 5 open (ADR 0016 amendment P2-13).
- Modules: `messages` (every user-facing string, named parameters; the phase 2 lines in `messages::txn`), `out` (`Out`: line writer, `BrokenPipe` ends silently, last-resort net: every line through `escape::text`, a panic in tests; `prompt` for the question), `system`, `scan` (pure render functions over core values), `host` (the `Host` with the system, the install folder and the `Confirm`; the guards and the exit mapping), `confirm` (the question on stderr, only with stdin and stdout consoles), `preview` (the one renderer of a plan's preview), `plan`, `apply`, `txn` (`status`, `revert`, `forget`). Human-readable English text only, not a stable interface; untrusted fields only as `escape::Shown` (raw text through `RawText::escaped`, never `as_raw_str`; a source rule test checks it), untrusted text last on its line. Never changes console state (no `SetConsoleMode`, no `SetConsoleOutputCP`; clap without `color`); no console control handler (Ctrl+C is a crash the journal recovers from).

## rerun-launch

- Reads the launch profile named by `--profile <id>` from `%LOCALAPPDATA%\Rerun\profiles\<id>.profile` (format 1, written on apply; ADR 0022).
- Knows no Topos, no network and no registry; the launch profile it reads is a file.
- Checks the rule about 5 s after the start and writes the outcome of the last start to `%LOCALAPPDATA%\Rerun\launch\<id>.result` (format 1, `rerun_proto::launch`; never when elevated; its only file write, one wrapper module; ADR 0022 amendment P3-2).
- `watch` (ADR 0022 amendment P3-4): starts Steam's command unchanged, then looks for a new process of the profile's `target` (Toolhelp32 snapshot as a name pre-filter; image path, creation time and token read through a handle opened with query rights; `win::process`), sets its priority class and then a new job with the selection (or its default CPU Sets) from outside (`win::launch`), reads the join back, checks about 5 s later; never ends a found process.
- Target: < 1 MB, < 50 ms startup time until `CreateProcessW`. Lifetime (ADR 0022, B3): `direct` waits until the started process exits and passes its exit code on; `watch` lives at least as long as the started process and at most until the target is found and checked; `hold`/`ifeo` together with the game. No console window (`windows_subsystem = "windows"`).
- DLL hardening like every shipped executable (ADR 0008 amendment 2026-11-05): linked with `/DEPENDENTLOADFLAG:0x800` (`build.rs`), and the first statement of `main` restricts the DLL search path to System32 (`src/dll.rs`, its own copy of the one `SetDefaultDllDirectories` call), failing closed. `rerun` does the same through `rerun_core::sys::win::restrict_dll_search`.

## rerun-cpu (inproc)

- Loaded via Ultimate ASI Loader (`scripts/rerun-cpu.asi`) or as a proxy DLL.
- Sets affinity/CPU Sets from inside, hooks `SetProcessAffinityMask`, reports a smaller core count if needed (`GetSystemInfo`, `GetNativeSystemInfo`, possibly `GetLogicalProcessorInformation`).
- Configuration from `rerun-cpu.ini` next to it. Builds for x86 and x64.
- Cargo produces `rerun_cpu.dll`; the build step copies it to `dist/<arch>/rerun-cpu.asi` (ADR 0006). Static CRT, `panic = "abort"`.

## Frontend (app/)

- Tauri 2, Svelte 5, TypeScript, Vite. No UI library.
- Commands: `scan`, `game_detail`, `plan`, `apply(plan_hash)`, `revert(txn_id)`, `forget(txn_id)`, `status`, `system_profile`.
- The frontend holds no system state. It displays plans, the core executes.

## Network

Only two destinations: the signed Topo index (GitHub Releases of `mythenstudios/rerun-topos`) and package downloads from the hosts in `packages/`. No telemetry. Feedback = pre-filled GitHub issue in the browser.

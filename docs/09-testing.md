# 09 · Testing

## Levels

1. **Unit** – pure logic (parsers, CPU selection, `when` evaluation, plan building). Fast, without a system.
2. **Primitive against `sys::fake`** – round trip, idempotence, crash, tampering, path escape. Required for every primitive.
3. **Windows Sandbox** – real Win32 calls that change the machine (registry writes outside a private app hive, firewall, IFEO, Job Objects) in a disposable environment. Tests with `#[ignore]`, script `scripts/sandbox-test.wsb`.
4. **Real hardware, manual** – launch games, post-launch check, revert, folder comparison.

## Round-trip contract

```
before = sys::snapshot::snapshot(&sys, &scope)
plan → apply → verify == Ok
revert
assert_eq!(snapshot(&sys, &scope), before)   // on mismatch: before.diff(&after)
```

"Identical" means: existence, kind, casing, content (SHA-256), length, attributes (read-only, hidden, system), hard link count, reparse tag and link target; for the registry: keys, value names, value type and the exact value bytes (`RegValue::Raw` keeps types and bytes that have no canonical typed form, ADR 0009). Names that fail `policy::path::classify`, entries of case-sensitive directories and names that fold to the same key are recorded as anomalies (metadata only, never opened). Restricted entries (their DACL denies the current user every open, `Metadata.restricted`) are recorded from the listing with kind, length, attributes, reparse tag and the restricted flag; never opened, hashed or descended into, and their unknown link count does not count. Cloud placeholders are recorded without a hash (no hydration), the attributes of a scope root itself are not captured, and nesting deeper than 64 directories is an error. Each scope directory is opened once by absolute path and walked through `Dir` handles (ADR 0007). **Timestamps and file IDs do not count** (restored backups have a new mtime and ID). An empty key is different from a missing one. `snapshot` is generic over `&dyn System` and also runs in the sandbox.

`scope` covers the game folder (hashes), affected registry keys, firewall rules with the Rerun prefix, IFEO keys, Steam launch option.

## Contract tests of the system layer

`rerun_core::sys::contract` checks the semantics of the traits against `sys::fake` and `sys::win`.

- **File system contract on real Windows runs in CI and locally** in a fresh temporary directory under `target/` (decided 2026-11-04). It creates its own junctions there (no admin needed) and touches nothing outside that directory: no registry, no firewall, no game folders. File symlinks need Developer Mode or admin; those cases skip with a message when the privilege is missing. Required safeguards:
  1. The test root is created new and uniquely named under the canonical `target/` directory. The test canonicalizes it and panics unless it is inside `target/`, on a local fixed drive, not a reparse point and not under a cloud/OneDrive tag.
  2. Junction targets stay inside the test root. The escape target is a sibling `outside/` folder with a canary file whose content is asserted unchanged.
  3. Cleanup only after re-checking (1), handle-based and never following links.
  4. Locally the test skips when the process is elevated. On GitHub-hosted runners (admin, ephemeral VM) it runs. Extension (decided 2026-11-04): fixtures that change the machine beyond the test root (mount point, `subst`, `SetFileShortNameW`) run only there, never locally, and are undone by a drop guard. "There" means all three of `GITHUB_ACTIONS=true`, `RUNNER_ENVIRONMENT=github-hosted` and the explicit opt-in `RERUN_FS_MACHINE_FIXTURES=1`, which `.github/workflows/ci.yml` sets for the Windows test step only (review L6); the same gate allows the elevated run and switches on the strict skip policy. A self-hosted runner or a shell that merely sets `GITHUB_ACTIONS` gets none of it.
  5. No registry, `%TEMP%` or home-directory paths. The test-only root constructor is gated (`cfg(test)`/`fake` feature) and does not bypass the forbidden-root checks for anything else.
- **Contract split and fixture-based setup.** The file system contracts are split by side. The read side (`fs_read_contract`, `fs_link_read_contract`, `fs_volume_contract`, `fs_race_contract`) takes `&dyn Fs` and uses only `Fs::open_dir` and the reading methods of `Dir` (`info`, `open_dir`, `metadata`, `open_read`, `read`, `read_dir`); it runs against `sys::fake` and `sys::win` (read-only in phase 1). The write side (`fs_write_contract`, `fs_link_write_contract`) exercises the writing methods and runs against the fake only until `sys::win` can write (phase 2). Everything a read contract needs on disk, and every attacker move, goes through an `FsFixture` (std::fs and raw calls in test code; `FakeFs` implements it for the fake): directories, files, junctions, directory and file symlinks, hard links, renames, case-sensitive directories, mounted volumes, `subst`, 8.3 short names, WOF compression, restricted DACLs (`FsFixture::restricted`: the current user is denied every access, the runner can still restore and remove the entry). The runner owns cleanup; a contract needs a fresh, empty work directory and the read contracts never delete anything.
- **Skips are observable.** A case the fixture cannot set up (no symlink privilege, no second volume, 8.3 names disabled, no WOF) returns `Ok(false)` / `Ok(None)` from the fixture. The contract skips it and returns the case names as `Skipped` (`Result<Vec<&'static str>, String>`), so the runner can tell a pass from a pass-by-skipping. The fake test runners assert the exact skip list (the fake has no 8.3 names, no WOF and no `subst`). On GitHub runners (`GITHUB_ACTIONS=true`) a skip is a test failure, except `mount_volume` (no second volume), `short_name` (8.3 names disabled) and `wof_compress` (not supported), which are warnings.
- **What the read contracts pin down.** `Fs::open_dir` accepts only drive-absolute input (`X:\…`, `\\?\X:\…`, `/` as `\`); `.`, `..`, UNC, device and volume-GUID paths, relative paths and stream paths are `InvalidPath`. A reparse point where a directory is expected, including a file symlink, is `ReparsePoint`, never `InvalidPath`. The matrix of link kinds (junction, directory symlink, file symlink, mount point) × position (`steamapps`, `common`, `Game`) is refused everywhere, with the right tag on `metadata` of the link. After every relative open the last segment of the normalized name must equal the requested one, so an 8.3 short name finds nothing (`NotFound`). A volume mounted in a folder reports an empty `volume_path` and its own serial when opened by absolute path and is a `MOUNT_POINT` surrogate below a root; a substituted drive shows the real location in `final_path` with the identity of the target. A restricted file or directory is listed by `read_dir` and described identically by `metadata` (`restricted`, `links: None`, length and attributes from the listing, own file ID), while `open_read`, `read`, `open_dir`, `read_dir` on it, walks through it and `Fs::open_dir` of it are `AccessDenied`.
- **Race harness (M-b).** `fs_race_contract(fs, fx, work, budget)`: the probe runs for at least `budget` and until the flipper has completed one flip (at most 30 s longer, so a loaded CI runner still races); a flipper thread swaps directories for junctions to an outside folder by path (renames at the first, middle and last of three directory levels) while the main thread probes through the root handle (`read`, `metadata`, `read_dir`, `open_dir` and reads through the sub handle). No result that comes back `Ok` may contain the canary's content, file ID or name `canary-only.txt`; allowed are `ReparsePoint`, `NotFound` (gap between two renames) and the real file's content. The assertion has to be able to fail: against the fake a fixture whose "junction" is a plain copy must be caught (`the_race_contract_catches_a_leaking_swap`). Against `sys::win` a test-only naive implementation (`NaiveFs`: check `symlink_metadata` per prefix, `yield_now` plus a 1 ms pause, then act on the full path) must be caught within 30 s, otherwise the test fails with "harness lost its teeth"; the safe implementation then runs for `max(5 s, 10 × time-to-catch-naive)`. The fake runs the contract with a short budget as a sanity check; its deterministic step hooks remain the precise TOCTOU tests. Found on real Windows (2026-11-04): a flip is two renames by path (hundreds of microseconds each), so with a bare `yield_now` the naive window is far shorter than a flip and was never caught in 30 s; with the 1 ms pause it is caught in 20–100 ms on the developer machine, so the harness proves that it catches a check-then-use window the size of an ordinary preemption. Two minimal relaxations of the contract, both from real runs: the flipper retries a rename refused with `AccessDenied`/`Busy` (Windows does not rename a directory while a handle below it was opened without `FILE_SHARE_DELETE`; `open_read` shares read only, thousands of retries per run), and `info()` through a probed handle may return `NotFound` (see the `Dir::info` docs: the canonical path is resolved component by component and `sys::win` retries only a bounded number of times).
- **Fixtures that change the machine (mount point, `subst`, 8.3 short names) run only on GitHub runners** (`GITHUB_ACTIONS=true`), never locally (decided 2026-11-04). This extends safeguard 4: locally these fixtures report "not available" and their cases skip. Each one is undone by a drop guard (unmount, `subst /d`, no lasting short name), also on panic.
- **Runners against real Windows** (`sys/win/tests.rs`, fixtures in `sys/win/testfx.rs`, `cfg(all(test, windows))`). They run in the normal `cargo test` step locally and in CI; no extra CI step.
  - `TestRoot::new(case)`: the target directory is the ancestor of `current_exe()` that contains `CACHEDIR.TAG` (else panic); the root is `target/rerun-fs-contract/<pid>-<nanos>-<case>`, created with `create_dir` (never reused). After `canonicalize` it must lie strictly inside the canonical target, on a drive with `GetDriveTypeW == DRIVE_FIXED`, and no ancestor may carry `FILE_ATTRIBUTE_REPARSE_POINT`, `RECALL_ON_OPEN`, `RECALL_ON_DATA_ACCESS`, `OFFLINE`, `PINNED` or `UNPINNED` (else panic). An elevated process outside GitHub Actions gets `None` and the test returns with a note. Drop undoes the fixture's machine-wide changes newest first (mount points with `DeleteVolumeMountPointW`, drive letters with `DDD_REMOVE_DEFINITION | DDD_EXACT_MATCH_ON_REMOVE`, restricted DACLs), keeps the tree if an undo failed, re-checks the safeguards and only then calls `std::fs::remove_dir_all`, which since the CVE-2022-21658 fix is handle-based and removes links without following them (`cleanup_never_follows_a_junction` checks it with junctions to a sibling root).
  - Stale roots (review L7): `TestRoot::new` first removes roots `<pid>-<nanos>-<case>` whose process is gone (a test that was killed before its drop ran). Only plain directories (not reparse points, judged from the listing) that pass safeguard 1 are touched; every entry gets a DACL granting the current user full access through the owner's implicit `WRITE_DAC` (opened with `NtCreateFile` and `WRITE_DAC` only, because `CreateFileW` always adds `SYNCHRONIZE | FILE_READ_ATTRIBUTES`, which a restricted DACL denies), links are reset but never descended into, safeguard 1 is checked again, then `remove_dir_all`. Roots of the current or a possibly live process stay. Manual recovery if a root cannot be removed: `icacls <file> /grant <user>:F` on each restricted entry (as its owner), then delete the folder.
  - `WinFixture` (`FsFixture`) is bound to its `TestRoot` (review L5): every writing method requires the path to lie inside the root component-wise, without `.`/`..`, below no reparse point (the last component may be a link only for renames) and below no mount point of the fixture; link targets must lie inside `target/rerun-fs-contract`. Directories and files with `std::fs`; junctions with `FSCTL_SET_REPARSE_POINT` on a new empty directory (no admin, no `cmd`); symlinks with `CreateSymbolicLinkW(…ALLOW_UNPRIVILEGED_CREATE)`, `ERROR_PRIVILEGE_NOT_HELD` → not available; hard links with `CreateHardLinkW`; renames with `MoveFileExW` without `REPLACE_EXISTING`; case-sensitive directories with `SetFileInformationByHandle(FileCaseSensitiveInfo)`; WOF with `FSCTL_SET_EXTERNAL_BACKING` (file provider, XPRESS4K); restricted entries with a protected DACL denying the current user everything except `READ_CONTROL`/`WRITE_DAC`, set with `SetKernelObjectSecurity` on a handle opened before the change and kept for the undo (a new open would need `SYNCHRONIZE | FILE_READ_ATTRIBUTES`, which `CreateFileW` always adds and the DACL denies). GitHub runners only: `mount_volume` mounts another NTFS volume that is already mounted at a drive letter (so Windows never mounts a dormant volume for it) with `SetVolumeMountPointW`, and the fixture refuses every write below a mount point (the contracts never create anything there or list it); `subst` uses `DefineDosDeviceW` on a free letter; `short_name` enables `SeRestorePrivilege` on a thread impersonation token (`ImpersonateSelf`, reverted on drop), never on the process token, and calls `SetFileShortNameW`.
  - Skips: on GitHub runners (the gate of safeguard 4) a skip other than `mount_volume`, `short_name` and `wof_compress` panics; those three are written as `::warning::` lines (a `::warning::` for `mount_volume` means the I3 cases, a volume mounted in a folder, were not verified in that run) directly to the process's stdout (past the test harness capture, so the workflow sees them). Locally each skip is a note on stderr. Expected local skips on a standard user without Developer Mode: `dir_symlink`, `file_symlink`, `case_sensitive_dir` (`ERROR_ACCESS_DENIED` without the WSL component), `mount_volume`, `subst`, `short_name`.
  - `win_dir_write_methods_are_unsupported`: every writing `WinDir` method returns `Unsupported` with "read-only in phase 1" and changes nothing.
  - Found on real Windows (2026-11-04): `wof.sys` hides the WOF reparse point (no attribute, no tag in `FileAttributeTagInformation` or the listing, `FSCTL_GET_REPARSE_POINT` → `ERROR_NOT_A_REPARSE_POINT`) while `FSCTL_GET_EXTERNAL_BACKING` confirms the backing; the WOF case therefore requires the content to be unchanged and accepts no tag or the WOF tag. `GetFinalPathNameByHandleW(FILE_NAME_NORMALIZED)` fails with `ERROR_FILE_NOT_FOUND` while an ancestor is renamed; `WinDir::info` retries such failures up to 32 times.
- **Topology contract** (`topology_contract(&dyn Topology)`, ADR 0010) only reads, so it runs against `sys::win` in CI and locally (`win_fulfils_topology_contract`, and through `WinSystem` in `win_system_bundles_the_real_parts`). `sys/win/cpu.rs` holds the layout test (`parser_offsets_match_windows_sys`: every offset of `rerun_proto::cpu::parse::layout` equals `offset_of!` on the `windows-sys` structures, plus the relationship, cache-type and flag constants), the bounded size-query/retry loop against a scripted call and a smoke test of the two real calls. `dump_cpu_topology` (`#[ignore]`, run by hand: `cargo test -p rerun-core --lib dump_cpu_topology -- --ignored`) reads both calls on the current machine and writes `target/cpu-dump.json` (fixture format 1, description still `TODO`) and `target/cpu-dump.parsed.json`; it writes nothing else. It zeroes every CPU Set byte the parser does not read, bytes 20 to `Size` of each record (an allowlist; found on the 5950X, 2026-11-05: `SchedulingClass` holds the firmware's preferred-core ranking, 15 distinct values that differ per chip sample, i.e. a fingerprint), and checks that the scrubbed bytes parse to the same topology. `rerun-core/tests/cpu_fixtures.rs`: every `*.raw.json` parses to its `*.json` (strict format: four fields, `format: 1`, a description without `TODO`, lower-case hex in 32-byte lines), every parsed fixture validates, every committed dump has the unread CPU Set bytes zero, the 5950X dump is 2 L3 x 8 cores x 2 threads, and mutated real dumps never panic (xorshift, no `proptest`).
- **Known folders and GPU contracts** (`known_folders_contract(&dyn KnownFolders, &dyn Fs)`, `gpu_contract(&dyn Gpu)`) only read, so they run against `sys::win` in CI and locally. The fake sets the known folders with `FakeSystemBuilder::known_folder`, creates their directories with `windows_layout()` and adds adapters with `gpu()`; its default has no adapter, which no real machine reports.
- **GPU on real Windows** (ADR 0008 amendment 2026-11-05, read-only): `win_fulfils_gpu_contract` runs the contract against `WinGpu` and requires exactly one Microsoft Basic Render Driver (vendor `0x1414`, device `0x8c`) with the `software` flag, which every machine and every GitHub runner lists. A VM without a GPU (the GitHub runner) lists the Basic Render Driver a second time as its display adapter, without the `software` flag (found in CI 2026-11-05). `dxgi_dll_is_loaded_from_system32` asks `GetModuleFileNameW` (`testfx::module_path`) where `dxgi.dll` came from: `<Windows>\System32\dxgi.dll`. `sys/win/dxgi.rs` pins `DXGI_ADAPTER_DESC1` (size, every offset), the four vtable slots and both IIDs against `dxgi.h`, and tests the bounded enumeration loop (`collect`: end of list, exactly 64, 65 is `TooMany`, an error fails the list); `sys/win/gpu.rs` tests the name rules (first NUL within 127 units, control characters and lone surrogates as U+FFFD, a surrogate pair cut at 127, no trimming), the LUID, the field mapping (software bit, remote bit ignored, driver version as bit pattern) and the error kinds; `sys/win/loader.rs` the bare-name rule and the missing DLL/export codes. `WinGpu` refuses to enumerate until the process called `restrict_dll_search` (`Unsupported`), so every GPU test restricts its process first; the lib test process therefore runs restricted to System32, which no other test depends on. `crates/rerun-core/tests/win_gpu_restricted.rs` (its own process) checks `Unsupported` before the call, the adapter list after it, and its own imports. Adapter names: bidirectional formatting characters (U+061C, U+200E, U+200F, U+202A to U+202E, U+2066 to U+2069) are replaced like control characters, other format characters stay; the contract refuses both in the fake. `dump_gpu_adapters` (`#[ignore]`, `cargo test -p rerun-core --lib dump_gpu_adapters -- --ignored --nocapture`) prints the adapters and the time of a first and a second enumeration; it writes nothing.
- **Known folders ignore the environment** (`sys/win/known_folders.rs`, ADR 0009). `known_folders_ignore_the_environment` starts the test binary itself as a child (filtered with `--exact` to `child_reports_known_folders`, which is a no-op unless the marker `RERUN_KNOWN_FOLDERS_CHILD=1` is set) with `windir`, `SystemRoot`, `SystemDrive`, `ProgramFiles`, `ProgramFiles(x86)`, `ProgramW6432`, `CommonProgramFiles`, `CommonProgramFiles(x86)`, `CommonProgramW6432`, `ProgramData`, `ALLUSERSPROFILE`, `PUBLIC`, `USERPROFILE`, `HOMEDRIVE`, `HOMEPATH`, `LOCALAPPDATA` and `APPDATA` pointing to decoy directories in a `TestRoot`; every folder the child reports must equal the parent's and lie outside the decoys. A control line (the shell's own `FOLDERID_ProgramData`) must lie inside the decoys, so the check fails if the environment never reached the child. Found on Windows 11 (2026-11-04): with a `NULL` token `SHGetKnownFolderPath` takes `LocalAppData` and `RoamingAppData` from `%USERPROFILE%` of the process; even with the process token it takes `ProgramData` and `UserProfiles` from `%SystemDrive%` (so do `GetProfilesDirectoryW` and `GetAllUsersProfileDirectoryW`). `WinKnownFolders` therefore passes the process token and reads those two from the raw `HKLM` `ProfileList` values (through the real, read-only `WinRegistry`), expanding only `%SystemDrive%`/`%SystemRoot%` from `GetSystemWindowsDirectoryW`. Locally skipped when elevated (safeguard 4).
- **Registry contracts** (ADR 0009) are split like the file system contracts and take the narrowest trait.
  - `registry_read_contract(&dyn Registry, &dyn RegFixture, root)` pins the read semantics: missing vs empty key, case-insensitive names that keep their case, the default value, non-ASCII names, a value name with a backslash, canonical decoding (a table of about 30 `(type, bytes)` cases: each comes back as the exact stored type and bytes, typed only when canonical, `REG_EXPAND_SZ` never expanded), the input rules (`InvalidPath` for NUL, empty segment, segment over 255, path over 32,767, value name over 16,383 UTF-16 units; exactly at the limit is valid), the limits for untrusted data (value over 1 MiB, more than 16,384 values, more than 16 MiB of values, more than 65,536 subkeys: `Unsupported`, never partial) and, if the fixture can make one, reads through a symbolic-link key. `root` must be empty and outside `HKLM\SOFTWARE`, where the 32-bit view is not redirected; the runner calls the contract once per view with a different root (the contract deletes nothing) and the contract checks that the other view sees the same data. Everything the contract needs is made by a `RegFixture` (`key`, `raw`, `delete_value`, `link`): raw type numbers and bytes, no decoding. Skipped cases: `key_link` (no link keys), `value_at_limit` and `value_over_limit` (`RegFixture::large` cannot store one value of 1 MiB or more; Windows stops at 1,048,572 bytes). The fake skips only `key_link`, and its test asserts exactly that. The 16 MiB total is reached with values of half the value limit, which every registry can hold.
  - `registry_system_contract(&dyn Registry, &dyn KnownFolders)` reads only stable system keys: `ProgramFilesDir` and `CommonFilesDir` of `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion` per view against the known folders (native: `ProgramFiles`, `ProgramFilesCommon`; 32-bit: the `X86` ones), the 32-bit view of `SOFTWARE\X` against `SOFTWARE\WOW6432Node\X` of the native view, `HKLM\SYSTEM\CurrentControlSet\Control` (a link on Windows) and `AccessDenied` on `HKLM\SECURITY`. It runs against the seeded fake (test helper `system_keys()` with `FakeSystemBuilder::denied_key`) and, read-only, on the real system. Skipped case: `security_denied` (the process can open `HKLM\SECURITY`, e.g. it runs as SYSTEM). Whether an explicit `WOW6432Node` in the 32-bit view names the same key is not part of the contract; on Windows 11 it does (the fake says the same), pinned by `explicit_wow6432node_in_the_32_bit_view_is_the_same_key`.
  - **Private app hives** (ADR 0009, user decision 2026-11-04): the read contract runs against `sys::win` locally and in CI in a hive file `hive.dat` inside a fresh `TestRoot` under `target/`, loaded with `RegLoadAppKeyW(…, KEY_ALL_ACCESS, REG_PROCESS_APPKEY)`: no admin, not in the global namespace, unloaded when the last handle closes (also if the process dies; the stale-root cleanup then removes the file). This counts as test-root data, not a system change. `testfx::AppHive` is the `RegFixture`: keys with `RegCreateKeyExW` and values with `NtSetValueKey` and `RegDeleteValueW`, always relative to the hive key and segment by segment with `REG_OPTION_OPEN_LINK` (a link key on the way is opened itself, never followed, so nothing is ever created outside the hive); every handle a write uses must, by its kernel name (`NtQueryKey(KeyNameInformation)`), lie below the hive key `\REGISTRY\A\{…}`, else the write is refused before a value is set. `HKCU` and `HKLM` of the hive are its keys `HKCU` and `HKLM`, mapped by the test-only `WinRegistry::with_roots`. `testfx::HiveRoot` holds registry, fixture and `TestRoot` in that order, so the handles close and the hive unloads before the root is removed. No test writes the real registry.
  - Runners (`sys/win/tests.rs`): `win_fulfils_registry_read_contract_{hkcu,hklm}_{native,wow32}` (four fresh hives, roots `RerunContract` and `SYSTEM\RerunContract`, outside `SOFTWARE`; about 16 s each with the segment-wise fixture, run in parallel, so about 16 s wall time on the developer machine); `win_fulfils_registry_system_contract` (`WinRegistry::new()` and `WinKnownFolders` on the real system, read-only; a skip fails on GitHub runners); `win_fulfils_known_folders_contract` (`WinKnownFolders`, `WinFs`); `the_hive_root_is_a_new_handle` and `the_current_user_hive_is_the_users_own` (in `sys/win/reg.rs`); `the_values_total_counts_long_names` (fake: names count towards the 16 MiB); `win_registry_write_methods_are_unsupported` (every write method returns `Unsupported` with "read-only in phase 1" after the input rules and changes nothing in the hive); `win_registry_enumerations_survive_concurrent_writes` (a writer churns values and subkeys while `values`/`subkeys` run for 1 s: each result is complete without duplicate names, or `Busy`); `explicit_wow6432node_in_the_32_bit_view_is_the_same_key`.
  - Found on real Windows 11 (2026-11-04): `RegQueryValueExW` and `RegEnumValueW` fix up string-typed values stored without a terminating NUL (a NUL is written into the caller's buffer behind the data; of an odd-length value the last byte comes back 0), so `sys::win::reg` reads values with `NtQueryValueKey`/`NtEnumerateValueKey`, and the contract has the case `sz_odd_tail`. `RegSetValueExW` stores a string-typed value 2 bytes longer if a NUL follows the caller's buffer in memory, so the fixture writes with `NtSetValueKey`. One value of more than 1,048,572 bytes is refused (`STATUS_INSUFFICIENT_RESOURCES`, `ERROR_NO_SYSTEM_RESOURCES`), so `MAX_VALUE_BYTES` (1 MiB) is never reached on Windows (`value_at_limit`, `value_over_limit` skip). A symbolic-link key can be created in an app hive, but opening it is `ERROR_ACCESS_DENIED` (the kernel does not follow links in app hives), so `AppHive` probes once at load (outside `HKCU`/`HKLM`) and `key_link` skips; link following on reads is covered by `HKLM\SYSTEM\CurrentControlSet` in the system contract. An explicit `SOFTWARE\WOW6432Node\X` in the 32-bit view names the same key as `SOFTWARE\X` there (as in the fake), the 32-bit view of `SOFTWARE` does not list `WOW6432Node` (a listed deviation of the fake), and `HKLM\SECURITY` is `AccessDenied` for a standard user. Writing 16,385 values into one key takes about 5 s (the kernel searches the value list on every write), 65,537 subkeys about 2.5 s.
  - `registry_write_contract(&dyn Registry, root)` (formerly `registry_contract`) exercises `create_key`, `set`, `delete_value`, `delete_key`, raw values and unencodable values. Fake only until `sys::win` can write (phase 2).
  - The fake models WOW64 as follows: a key is stored once; only `HKLM\SOFTWARE\X` (below `SOFTWARE`) in the 32-bit view is `HKLM\SOFTWARE\WOW6432Node\X` in the native view; `HKLM\SOFTWARE` itself, every other `HKLM` key and all of `HKCU` are shared between the views. The list of deliberate deviations (shared and reflected subkeys, `Classes`, enumeration of `SOFTWARE` in the 32-bit view, `WOW6432Node` created on first use, no link keys, all-or-nothing access, name folding, enumeration order, no races) is at the top of `sys/fake/registry.rs`. `the_registry_read_contract_catches_a_lossy_registry` and `the_registry_system_contract_catches_wrong_data` keep both contracts honest.
- **Firewall, IFEO, registry writes outside a private app hive and anything outside the temp directory** run only in Windows Sandbox as `#[ignore]` tests.
- **TOCTOU:** the fake has test hooks that run between two path components of an operation, so a test can swap a directory for a junction mid-operation (ADR 0007). On `sys::win` the swap between two calls is tested. If the fake deviates from the real system, the contract is extended first, then the fake is adjusted. - **Hashes** (`detect/exe/hash/tests.rs`, `detect/exe/scan/tests.rs`): known SHA-1 and SHA-256 vectors (empty, `abc`, a 1 MiB pattern) in uppercase hex, the same result for every chunk size and for a reader returning 7 bytes per call, `Interrupted` retried, a failing reader keeping only its `ErrorKind`; a file of exactly `max_file_bytes` hashed, one byte more `TooLarge` after reading at most the limit plus one chunk; without `--hashes` nothing beyond the parser's reads is read (counting handle) and every outcome is `NotRequested`; with `--hashes` only parsed `Game` candidates in rank order, `NotGame` for the others, `TooManyFiles` after the limit, `GameBudget` and `TooLarge` by the listed length without reading, hashes from the handle that was parsed (`inspect_exe` hashes the very file it parsed; a file replaced between the two inspections is `Changed` and keeps its first facts, after the parser's reads only, one replaced by something unparsable is `Inspect`; with a counting fake (`FakeFs::bytes_served`) two replaced 8 MiB files and one hashed file read at most the parser budget plus `max_game_bytes` plus one chunk per hashed file; a file that grew after the listing (same facts, appended overlay) is capped by the remaining budget and is `GameBudget`, the next candidate too; the read buffer is clamped to 16 MiB; the bytes read before an I/O error or past the cap are reported). A listing with two names that fold alike (a folder that turned case-sensitive between `info` and `read_dir`) is treated as `CaseSensitiveDir`.
- **Real machine** (manual, read-only): `dump_exe_candidates` (`crates/rerun-core/tests/pe_system.rs`, `#[ignore]`, Windows only), see the manual test matrix.

## Shipped binaries

`crates/rerun-cli/tests/hardening.rs` and `crates/rerun-launch/tests/hardening.rs` (ADR 0008 amendment 2026-11-05) read the built executable (`CARGO_BIN_EXE_*`) with `rerun_core::detect::pe` over a `std::fs::File` (ADR 0013; the test policy in `tests/support/hardening.rs`, included with `#[path]`; `rerun-core` is a dev-dependency of `rerun-launch` only) and check `IMAGE_LOAD_CONFIG_DIRECTORY64::DependentLoadFlags == 0x800` (`/DEPENDENTLOADFLAG`, System32 only), every static import in the exact allowlist `SHIPPED_IMPORTS` (a new import fails with a message to review it and update the list and ADR 0008), never `dxgi.dll`, `d3d*`, `dxcore.dll`, `vcruntime*`, `msvcp*`, `ucrtbase*` or `api-ms-win-crt-*`, an empty delay-import table, PE32+ for the native machine (x64 in CI), and that the binary runs past its DLL search path restriction. The test-profile binaries are linked with the features of the test build, so CI builds the release `rerun-launch.exe` (`cargo build -p rerun-launch --release`, the size check) before the tests and `release_rerun_launch_exe_loads_dependencies_from_system32_only` checks it as well (`RERUN_RELEASE_LAUNCH_EXE`; required on GitHub-hosted runners, skipped locally when unset). `crates/rerun-core/tests/win_gpu_restricted.rs` links every part of `WinSystem` and checks its own test binary against `CORE_IMPORTS`. Teeth (`hardening_checks_have_teeth`, in every crate that includes the policy): a PE32+ written by the test itself, independent of the parser's layout constants, passes when hardened and fails with a `d3d9.dll` import (also when allowlisted), an unlisted import, a delay-load import, `DependentLoadFlags` 0, `0x1000` or `0xA00`, a PE32 image (well-formed, its flags and imports read) and a PE32+ image for another machine; malformed input is an error. `crates/rerun-core/tests/source_rules.rs` scans every `.rs` file for hand-written imports (`extern` blocks, `#[link(…)]`, `raw-dylib`; allowlist empty) and has a teeth test for each form. They print the imported DLLs (`-- --nocapture`); on 2026-11-05 both import only `kernel32.dll`, `ntdll.dll` and `api-ms-win-core-synch-l1-2-0.dll`. CI additionally checks the dependencies (`windows-sys`, `rerun-proto` only) and the release size (< 1 MiB) of `rerun-launch`.

## Rules

- No test modifies the real system outside the sandbox.
- Bugs: failing test first, then the fix.
- Fixtures are data, not code generators. **Exceptions:** PE test files are built by small builders in test code (`crates/rerun-core/src/detect/pe/testfx.rs`; the hardening teeth in `tests/support/hardening.rs`), because third-party binaries must not be committed and hand-written binary fixtures cannot be reviewed. Likewise the Windows topology records (`SYSTEM_CPU_SET_INFORMATION`, `SYSTEM_LOGICAL_PROCESSOR_INFORMATION_EX`) for the parser's edge cases are built by a byte builder in the `rerun-proto` tests (`cpu/parse/tests.rs`, ADR 0010); real machines are raw dumps (`tests/fixtures/cpu/*.raw.json`).
- VDF fixtures (`tests/fixtures/vdf/`, ADR 0011) are synthetic: every path, label, app ID, name, size and ID is invented, never copied from a real Steam installation or account. `.gitattributes` forces `eol=lf`, so CRLF and BOM cases are built inline in the tests.

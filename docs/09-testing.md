# 09 · Testing

## Levels

1. **Unit** – pure logic (parsers, CPU selection, `when` evaluation, plan building). Fast, without a system.
2. **Primitive against `sys::fake`** – round trip, idempotence, crash, tampering, path escape. Required for every primitive.
3. **Windows Sandbox** – real Win32 calls that change the machine (registry writes outside a private app hive, firewall, IFEO, Job Objects) in a disposable environment. Tests with `#[ignore]`, script `scripts/sandbox-test.wsb` (written before P2-11). Such a test runs only if `RERUN_SANDBOX=1` **and** `USERNAME` is `WDAGUtilityAccount` (the Sandbox account); otherwise it panics before touching anything, so an `--ignored` run on the developer machine cannot write the real `HKCU`.
4. **Real hardware, manual** – launch games, post-launch check, revert, folder comparison.

## Round-trip contract

```
before = sys::snapshot::snapshot(&sys, &scope)
plan → apply → verify == Ok
revert
assert_eq!(snapshot(&sys, &scope), before)   // on mismatch: before.diff(&after)
```

"Identical" means: existence, kind, casing, content (SHA-256), length, attributes (read-only, hidden, system), hard link count, reparse tag and link target; for the registry: keys, value names, value type and the exact value bytes (`RegValue::Raw` keeps types and bytes that have no canonical typed form, ADR 0009). Names that fail `policy::path::classify`, entries of case-sensitive directories and names that fold to the same key are recorded as anomalies (metadata only, never opened). Restricted entries (their DACL denies the current user every open, `Metadata.restricted`) are recorded from the listing with kind, length, attributes, reparse tag and the restricted flag; never opened, hashed or descended into, and their unknown link count does not count. Cloud placeholders are recorded without a hash (no hydration), the attributes of a scope root itself are not captured, and nesting deeper than 64 directories is an error. Each scope directory is opened once by absolute path and walked through `Dir` handles (ADR 0007). **Not compared and not restored** (user decision D3, ADR 0017): timestamps, file IDs (restored backups have a new mtime and ID), DACL and owner, alternate data streams, 8.3 names, extended attributes, compression and EFS state, `ARCHIVE` and every attribute other than read-only, hidden and system (every write sets `ARCHIVE` again); for the registry the last-write time and the key's security. An empty key is different from a missing one. The round trip runs once per primitive, for `ini_set` also with a game-style rewrite of other lines between apply and revert (`Drifted`): the revert restores only Rerun's key and keeps the other changes, and with no other change it gives exactly the old bytes (ADR 0020). `snapshot` is generic over `&dyn System` and also runs in the sandbox.

`scope` covers the game folder (hashes), affected registry keys, firewall rules with the Rerun prefix, IFEO keys, Steam launch option.

## Contract tests of the system layer

`rerun_core::sys::contract` checks the semantics of the traits against `sys::fake` and `sys::win`.

- **File system contract on real Windows runs in CI and locally** in a fresh temporary directory under `target/` (decided 2026-11-04). It creates its own junctions there (no admin needed) and touches nothing outside that directory: no registry, no firewall, no game folders. File symlinks need Developer Mode or admin; those cases skip with a message when the privilege is missing. Required safeguards:
  1. The test root is created new and uniquely named under the canonical `target/` directory. The test canonicalizes it and panics unless it is inside `target/`, on a local fixed drive, not a reparse point and not under a cloud/OneDrive tag.
  2. Junction targets stay inside the test root. The escape target is a sibling `outside/` folder with a canary file whose content is asserted unchanged.
  3. Cleanup only after re-checking (1), handle-based and never following links.
  4. Locally the test skips when the process is elevated. On GitHub-hosted runners (admin, ephemeral VM) it runs. Extension (decided 2026-11-04): fixtures that change the machine beyond the test root (mount point, `subst`, `SetFileShortNameW`) run only there, never locally, and are undone by a drop guard. "There" means all three of `GITHUB_ACTIONS=true`, `RUNNER_ENVIRONMENT=github-hosted` and the explicit opt-in `RERUN_FS_MACHINE_FIXTURES=1`, which `.github/workflows/ci.yml` sets for the Windows test step only (review L6); the same gate allows the elevated run and switches on the strict skip policy. A self-hosted runner or a shell that merely sets `GITHUB_ACTIONS` gets none of it.
  5. No registry, `%TEMP%` or home-directory paths. The test-only root constructor is gated (`cfg(test)`/`fake` feature) and does not bypass the forbidden-root checks for anything else.
- **Contract split and fixture-based setup.** The file system contracts are split by side. The read side (`fs_read_contract`, `fs_link_read_contract`, `fs_volume_contract`, `fs_race_contract`) takes `&dyn Fs` and uses only `Fs::open_dir`, the methods of `Dir` (`info`, `open_dir`, `metadata`, `open_read`, `read`, `read_dir`, `users`) and `DirWrite::open_dir_write`, which only opens; it runs against `sys::fake` and `sys::win`. `users` is pinned by its error kinds and by fixture holds (it never asserts that nobody else holds a file: a scanner may hold a fresh one). Holds (`FsFixture::hold_open(p, Access, Share)`, a handle of the test process, `CreateFileW` in `WinFixture`): a held file is reported by `users` and gone once closed (R1); a hold that shares nothing makes `read` and `open_read` `Busy` but never `metadata` or `users` (R2); a hold with write access makes `read` `Busy` (`open_read` shares read only); a folder held with share 0 makes `open_dir` and `read_dir` of it `Busy`, while a walk through it to an entry below works (R4: `sys::win` opens walk components attribute-only). R3 (`ancestor_renames`): while a `Dir` handle, an `open_read` reader, a file hold (read, sharing read and delete, or nothing), an attribute-only file hold, a folder hold or an attribute-only folder hold is open below a folder, renaming that folder or any ancestor through the fixture is `AccessDenied`, and works once the handle is closed (observed matrix in ADR 0017, A5). `Fs::open_dir_write` and `DirWrite::open_dir_write` (a `WriteCap` from test code of the crate) reach the same directories with the same errors, and `refused_at`/`refused_through` also require `open_dir_write` to stop at every junction, symlink and mount point with `ReparsePoint`. Names (the read-side cases of the phase 1 write contract, set up by the fixture): non-ASCII case folding (`über.TXT` finds `Über.txt`), `Straße` is not `STRASSE`, `a..b`, `.hidden`, `$data.bin` and `my file.txt` listed and read exactly as spelled; renaming an ancestor of an open handle is `AccessDenied` and leaves the handle intact, renaming the handle's own directory makes `final_path` follow, and once the handle is closed the ancestor renames. Bounded reads (ADR 0011, ADR 0012): `read_limited` and `read_dir_limited` at the bound return everything, one byte or entry over it is `TooLarge` (also bound 0, an empty file or directory at 0, the handle's own listing and the next listing after a refusal, a listing of 1,000 entries that spans several `NtQueryDirectoryFile` batches, and one far over the bound that stops in the first batch). The write side (`fs_write_contract`, `fs_link_write_contract`) exercises `DirWrite` and `FileGuard` (ADR 0017) and runs against the fake and, from P2-4, against `sys::win` in a `TestRoot` under `target/` (safeguards above). Everything a read contract needs on disk, and every attacker move, goes through an `FsFixture` (std::fs and raw calls in test code; `FakeFs` implements it for the fake): directories, files, junctions, directory and file symlinks, hard links, renames, case-sensitive directories, mounted volumes, `subst`, 8.3 short names, WOF compression, restricted DACLs (`FsFixture::restricted`: the current user is denied every access, the runner can still restore and remove the entry), handles held open (`FsFixture::hold_open`), another program's delete and attribute change (`FsFixture::remove`, `FsFixture::set_attrs`). The runner owns cleanup; a contract needs a fresh, empty work directory and the read contracts never delete anything.
- **Skips are observable.** A case the fixture cannot set up (no symlink privilege, no second volume, 8.3 names disabled, no WOF) returns `Ok(false)` / `Ok(None)` from the fixture. The contract skips it and returns the case names as `Skipped` (`Result<Vec<&'static str>, String>`), so the runner can tell a pass from a pass-by-skipping. The fake test runners assert the exact skip list (the fake has no 8.3 names, no WOF and no `subst`). On GitHub runners (`GITHUB_ACTIONS=true`) a skip is a test failure, except `mount_volume` (no second volume), `short_name` (8.3 names disabled) and `wof_compress` (not supported), which are warnings.
- **What the read contracts pin down.** `Fs::open_dir` accepts only drive-absolute input (`X:\…`, `\\?\X:\…`, `/` as `\`); `.`, `..`, UNC, device and volume-GUID paths, relative paths and stream paths are `InvalidPath`. A reparse point where a directory is expected, including a file symlink, is `ReparsePoint`, never `InvalidPath`. The matrix of link kinds (junction, directory symlink, file symlink, mount point) × position (`steamapps`, `common`, `Game`) is refused everywhere, with the right tag on `metadata` of the link. After every relative open the last segment of the normalized name must equal the requested one, so an 8.3 short name finds nothing (`NotFound`). A volume mounted in a folder reports an empty `volume_path` and its own serial when opened by absolute path and is a `MOUNT_POINT` surrogate below a root; a substituted drive shows the real location in `final_path` with the identity of the target. A restricted file or directory is listed by `read_dir` and described identically by `metadata` (`restricted`, `links: None`, length and attributes from the listing, own file ID), while `open_read`, `read`, `open_dir`, `read_dir` on it, walks through it and `Fs::open_dir` of it are `AccessDenied`.
- **Race harness (M-b).** `fs_race_contract(fs, fx, work, budget)`: the probe runs for at least `budget` and until the flipper has completed one flip (at most 30 s longer, so a loaded CI runner still races); a flipper thread swaps directories for junctions to an outside folder by path (renames at the first, middle and last of three directory levels) while the main thread probes through the root handle (`read`, `metadata`, `read_dir`, `open_dir` and reads through the sub handle). No result that comes back `Ok` may contain the canary's content, file ID or name `canary-only.txt`; allowed are `ReparsePoint`, `NotFound` (gap between two renames) and the real file's content. The assertion has to be able to fail: against the fake a fixture whose "junction" is a plain copy must be caught (`the_race_contract_catches_a_leaking_swap`). Against `sys::win` a test-only naive implementation (`NaiveFs`: check `symlink_metadata` per prefix, `yield_now` plus a 1 ms pause, then act on the full path) must be caught within 30 s, otherwise the test fails with "harness lost its teeth"; the safe implementation then runs for `max(5 s, 10 × time-to-catch-naive)`. The fake runs the contract with a short budget as a sanity check; its deterministic step hooks remain the precise TOCTOU tests. Found on real Windows (2026-11-04): a flip is two renames by path (hundreds of microseconds each), so with a bare `yield_now` the naive window is far shorter than a flip and was never caught in 30 s; with the 1 ms pause it is caught in 20–100 ms on the developer machine, so the harness proves that it catches a check-then-use window the size of an ordinary preemption. Two minimal relaxations of the contract, both from real runs: the flipper retries a rename refused with `AccessDenied`/`Busy` (Windows does not rename a directory while any handle is open below it, whatever its share mode, ADR 0017 A5; the fake models the same rule; thousands of retries per run), and `info()` through a probed handle may return `NotFound` (see the `Dir::info` docs: the canonical path is resolved component by component and `sys::win` retries only a bounded number of times).
- **Fixtures that change the machine (mount point, `subst`, 8.3 short names) run only on GitHub runners** (`GITHUB_ACTIONS=true`), never locally (decided 2026-11-04). This extends safeguard 4: locally these fixtures report "not available" and their cases skip. Each one is undone by a drop guard (unmount, `subst /d`, no lasting short name), also on panic.
- **Runners against real Windows** (`sys/win/tests.rs`, fixtures in `sys/win/testfx.rs`, `cfg(all(test, windows))`). They run in the normal `cargo test` step locally and in CI; no extra CI step.
  - `TestRoot::new(case)`: the target directory is the ancestor of `current_exe()` that contains `CACHEDIR.TAG` (else panic); the root is `target/rerun-fs-contract/<pid>-<nanos>-<case>`, created with `create_dir` (never reused). After `canonicalize` it must lie strictly inside the canonical target, on a drive with `GetDriveTypeW == DRIVE_FIXED`, and no ancestor may carry `FILE_ATTRIBUTE_REPARSE_POINT`, `RECALL_ON_OPEN`, `RECALL_ON_DATA_ACCESS`, `OFFLINE`, `PINNED` or `UNPINNED` (else panic). An elevated process outside GitHub Actions gets `None` and the test returns with a note. Drop undoes the fixture's machine-wide changes newest first (mount points with `DeleteVolumeMountPointW`, drive letters with `DDD_REMOVE_DEFINITION | DDD_EXACT_MATCH_ON_REMOVE`, restricted DACLs), keeps the tree if an undo failed, re-checks the safeguards and only then calls `std::fs::remove_dir_all`, which since the CVE-2022-21658 fix is handle-based and removes links without following them (`cleanup_never_follows_a_junction` checks it with junctions to a sibling root).
  - Stale roots (review L7): `TestRoot::new` first removes roots `<pid>-<nanos>-<case>` whose process is gone (a test that was killed before its drop ran). Only plain directories (not reparse points, judged from the listing) that pass safeguard 1 are touched; every entry gets a DACL granting the current user full access through the owner's implicit `WRITE_DAC` (opened with `NtCreateFile` and `WRITE_DAC` only, because `CreateFileW` always adds `SYNCHRONIZE | FILE_READ_ATTRIBUTES`, which a restricted DACL denies), links are reset but never descended into, safeguard 1 is checked again, then `remove_dir_all`. Roots of the current or a possibly live process stay. Manual recovery if a root cannot be removed: `icacls <file> /grant <user>:F` on each restricted entry (as its owner), then delete the folder.
  - `WinFixture` (`FsFixture`) is bound to its `TestRoot` (review L5): every writing method requires the path to lie inside the root component-wise, without `.`/`..`, below no reparse point (the last component may be a link only for renames) and below no mount point of the fixture; link targets must lie inside `target/rerun-fs-contract`. Directories and files with `std::fs`; junctions with `FSCTL_SET_REPARSE_POINT` on a new empty directory (no admin, no `cmd`); symlinks with `CreateSymbolicLinkW(…ALLOW_UNPRIVILEGED_CREATE)`, `ERROR_PRIVILEGE_NOT_HELD` → not available; hard links with `CreateHardLinkW`; renames with `MoveFileExW` without `REPLACE_EXISTING`; case-sensitive directories with `SetFileInformationByHandle(FileCaseSensitiveInfo)`; WOF with `FSCTL_SET_EXTERNAL_BACKING` (file provider, XPRESS4K); restricted entries with a protected DACL denying the current user everything except `READ_CONTROL`/`WRITE_DAC`, set with `SetKernelObjectSecurity` on a handle opened before the change and kept for the undo (a new open would need `SYNCHRONIZE | FILE_READ_ATTRIBUTES`, which `CreateFileW` always adds and the DACL denies). GitHub runners only: `mount_volume` mounts another NTFS volume that is already mounted at a drive letter (so Windows never mounts a dormant volume for it) with `SetVolumeMountPointW`, and the fixture refuses every write below a mount point (the contracts never create anything there or list it); `subst` uses `DefineDosDeviceW` on a free letter; `short_name` enables `SeRestorePrivilege` on a thread impersonation token (`ImpersonateSelf`, reverted on drop), never on the process token, and calls `SetFileShortNameW`.
  - Skips: on GitHub runners (the gate of safeguard 4) a skip other than `mount_volume`, `short_name` and `wof_compress` panics; those three are written as `::warning::` lines (a `::warning::` for `mount_volume` means the I3 cases, a volume mounted in a folder, were not verified in that run) directly to the process's stdout (past the test harness capture, so the workflow sees them). Locally each skip is a note on stderr. Expected local skips on a standard user without Developer Mode: `dir_symlink`, `file_symlink`, `case_sensitive_dir` (`ERROR_ACCESS_DENIED` without the WSL component), `mount_volume`, `subst`, `short_name`.
  - `win_dir_write_methods_are_unsupported`: every writing `DirWrite` method of `WinDir` (`guard`, `create_new`, `create_dir`, `remove_dir`, `flush`) returns `Unsupported` ("not implemented yet") and changes nothing, while `open_dir_write` opens the same directory as `open_dir` (until P2-4 replaces it with the write contracts).
  - Found on real Windows (2026-11-04): `wof.sys` hides the WOF reparse point (no attribute, no tag in `FileAttributeTagInformation` or the listing, `FSCTL_GET_REPARSE_POINT` → `ERROR_NOT_A_REPARSE_POINT`) while `FSCTL_GET_EXTERNAL_BACKING` confirms the backing; the WOF case therefore requires the content to be unchanged and accepts no tag or the WOF tag. `GetFinalPathNameByHandleW(FILE_NAME_NORMALIZED)` fails with `ERROR_FILE_NOT_FOUND` while an ancestor is renamed; `WinDir::info` retries such failures up to 32 times.

- **Registry contracts** (ADR 0009) are split like the file system contracts and take the narrowest trait.
  - `registry_read_contract(&dyn Registry, &dyn RegFixture, root)` pins the read semantics: missing vs empty key, case-insensitive names that keep their case, the default value, non-ASCII names, a value name with a backslash, canonical decoding (a table of about 30 `(type, bytes)` cases: each comes back as the exact stored type and bytes, typed only when canonical, `REG_EXPAND_SZ` never expanded), the input rules (`InvalidPath` for NUL, empty segment, segment over 255, path over 32,767, value name over 16,383 UTF-16 units; exactly at the limit is valid), the limits for untrusted data (value over 1 MiB, more than 16,384 values, more than 16 MiB of values, more than 65,536 subkeys: `Unsupported`, never partial) and, if the fixture can make one, reads through a symbolic-link key. `root` must be empty and outside `HKLM\SOFTWARE`, where the 32-bit view is not redirected; the runner calls the contract once per view with a different root (the contract deletes nothing) and the contract checks that the other view sees the same data. Everything the contract needs is made by a `RegFixture` (`key`, `raw`, `delete_value`, `link`): raw type numbers and bytes, no decoding. Skipped cases: `key_link` (no link keys), `value_at_limit` and `value_over_limit` (`RegFixture::large` cannot store one value of 1 MiB or more; Windows stops at 1,048,572 bytes). The fake skips only `key_link`, and its test asserts exactly that. The 16 MiB total is reached with values of half the value limit, which every registry can hold.
  - `registry_system_contract(&dyn Registry, &dyn KnownFolders)` reads only stable system keys: `ProgramFilesDir` and `CommonFilesDir` of `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion` per view against the known folders (native: `ProgramFiles`, `ProgramFilesCommon`; 32-bit: the `X86` ones), the 32-bit view of `SOFTWARE\X` against `SOFTWARE\WOW6432Node\X` of the native view, `HKLM\SYSTEM\CurrentControlSet\Control` (a link on Windows) and `AccessDenied` on `HKLM\SECURITY`. It runs against the seeded fake (test helper `system_keys()` with `FakeSystemBuilder::denied_key`) and, read-only, on the real system. Skipped case: `security_denied` (the process can open `HKLM\SECURITY`, e.g. it runs as SYSTEM). Teeth (`hardening_checks_have_teeth`, in every crate that includes the policy): a PE32+ written by the test itself, independent of the parser's layout constants, passes when hardened and fails with a `d3d9.dll` import (also when allowlisted), an unlisted import, a delay-load import, `DependentLoadFlags` 0, `0x1000` or `0xA00`, a PE32 image (well-formed, its flags and imports read) and a PE32+ image for another machine; malformed input is an error. `crates/rerun-core/tests/source_rules.rs` scans every `.rs` file for hand-written imports (`extern` blocks, `#[link(…)]`, `raw-dylib`; allowlist empty) and has a teeth test for each form. They print the imported DLLs (`-- --nocapture`); on 2026-11-05, before step 16, both imported only `kernel32.dll`, `ntdll.dll` and `api-ms-win-core-synch-l1-2-0.dll`; from step 16 `rerun.exe` links `WinSystem` (`CLI_IMPORTS`). CI additionally checks the dependencies (`windows-sys`, `rerun-proto` only) and the release size (< 1 MiB) of `rerun-launch`.

## Rules

- No test modifies the real system outside the sandbox.
- Bugs: failing test first, then the fix.
- Fixtures are data, not code generators. **Exceptions:** PE test files are built by small builders in test code (`crates/rerun-core/src/detect/pe/testfx.rs`; the minimal writer `tests/support/pe_image.rs` for the hardening teeth and the CLI tests), because third-party binaries must not be committed and hand-written binary fixtures cannot be reviewed. Likewise the Windows topology records (`SYSTEM_CPU_SET_INFORMATION`, `SYSTEM_LOGICAL_PROCESSOR_INFORMATION_EX`) for the parser's edge cases are built by a byte builder in the `rerun-proto` tests (`cpu/parse/tests.rs`, ADR 0010); real machines are raw dumps (`tests/fixtures/cpu/*.raw.json`).
- VDF fixtures (`tests/fixtures/vdf/`, ADR 0011) are synthetic: every path, label, app ID, name, size and ID is invented, never copied from a real Steam installation or account. `.gitattributes` forces `eol=lf`, so CRLF and BOM cases are built inline in the tests.

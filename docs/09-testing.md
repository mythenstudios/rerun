# 09 · Testing

## Levels

1. **Unit** – pure logic (parsers, CPU selection, `when` evaluation, plan building). Fast, without a system.
2. **Primitive against `sys::fake`** – round trip, idempotence, crash, tampering, path escape. Required for every primitive.
3. **Windows Sandbox** – real Win32 calls that change the machine (registry writes outside a private app hive, firewall, IFEO, Job Objects) in a disposable environment. Tests with `#[ignore]`, script `scripts/sandbox-test.wsb` (written before P2-11). Such a test runs only if `RERUN_SANDBOX=1` **and** `USERNAME` is `WDAGUtilityAccount` (the Sandbox account); otherwise it panics before touching anything, so an `--ignored` run on the developer machine cannot write the real `HKCU`.
4. **Real hardware, manual** – launch games, post-launch check, revert, folder comparison.

## Round-trip contract

```
scope  = Scope { dirs: vec![SnapRoot::new(game.dir(), label)], keys }   // root handles, ADR 0007
before = sys::snapshot::snapshot(sys.registry(), &scope)
plan → apply → verify == Ok
revert
assert_eq!(snapshot(sys.registry(), &scope), before)   // on mismatch: before.diff(&after)
```

"Identical" means: existence, kind, casing, content (SHA-256), length, attributes (read-only, hidden, system; on files, directories and, since P2-5, reparse points), hard link count, reparse tag and link target; for the registry: keys, value names, value type and the exact value bytes (`RegValue::Raw` keeps types and bytes that have no canonical typed form, ADR 0009); key and value names with U+FFFD (an unpaired surrogate converted by `sys`, user decision E1), names that fold alike and names no key path may hold (NUL; a subkey also `\` or empty) are registry anomalies (the case of a scope key itself is not seen: its name comes from the caller) (a key never opened or descended into, a value with its data), a multiset like the file anomalies; the registry walk stops at 64 levels of subkeys and 100,000 keys per snapshot (`TooLarge` with the limit; 64 and 100,000 are walked, 65 and 100,001 refused, tested in the fake with a broad tree without links). The allowlisted data tag of a file (WOF, dedup, cloud) is shown in a diff but not compared (P2-5, user decision E3: `wof.sys` hides the WOF tag, compression changes no content); a cloud placeholder still differs through its missing hash, and the tags of reparse points and restricted entries are compared. A reparse point that `sys` reports without its reparse data is an error, never a silent tag 0. Names that fail `policy::path::classify`, entries of case-sensitive directories and names that fold to the same key are recorded as anomalies (metadata only, never opened); anomalies with the same raw name in one directory (two names that differ only in an unpaired surrogate) are a multiset, none overwrites another. Delete-pending entries are skipped like every listing skips them (user decision E2, ADR 0017 A6): a snapshot taken while another program's delete is pending equals one taken after it. Restricted entries (their DACL denies the current user every open, `Metadata.restricted`) are recorded from the listing with kind, length, attributes, reparse tag and the restricted flag; never opened, hashed or descended into, and their unknown link count does not count. Cloud placeholders are recorded without a hash (no hydration), the attributes and the name of a root itself are not captured, and nesting deeper than 64 directories is `TooLarge` with the limit (64 levels are walked, the 65th is refused; tested exactly). A scope names its directories as root handles (`SnapRoot`: the `Dir` of a root that `policy::root` handed out, `GameDir::dir()`, later `AppDir`; P2-5), never as absolute paths; each is walked through `Dir` handles (ADR 0007), and `SnapRoot::below(sub)` takes only the entry `sub` (captured like an entry of its parent's listing; missing is `Missing`, a reparse point or a restricted entry on the way is an error; depths still count from the root). `SnapRoot::new` is public within the test-only module, so a crate with `feature = "fake"` can snapshot its roots too. Every root is recorded with its identity (volume serial, file ID, the `below` path): snapshots of different roots are never identical; the label is display only. **Not compared and not restored** (user decision D3, ADR 0017): timestamps, file IDs (restored backups have a new mtime and ID), DACL and owner, alternate data streams, 8.3 names, extended attributes, compression and EFS state, `ARCHIVE` and every attribute other than read-only, hidden and system (every write sets `ARCHIVE` again); for the registry the last-write time and the key's security. An empty key is different from a missing one. The round trip runs once per primitive, for `ini_set` also with a game-style rewrite of other lines between apply and revert (`Drifted`): the revert restores only Rerun's key and keeps the other changes, and with no other change it gives exactly the old bytes (ADR 0020). `snapshot` takes `&dyn Registry` and root handles, so it runs against the fake, against `sys::win` (`snapshot_contract`) and in the sandbox. It is test code (`cfg(any(test, feature = "fake"))`, P2-5, user decision E4): no shipped binary contains it.

`scope` covers the game folder (hashes), affected registry keys, firewall rules with the Rerun prefix, IFEO keys, Steam launch option.

## Contract tests of the system layer

`rerun_core::sys::contract` checks the semantics of the traits against `sys::fake` and `sys::win`.

- **File system contract on real Windows runs in CI and locally** in a fresh temporary directory under `target/` (decided 2026-11-04). It creates its own junctions there (no admin needed) and touches nothing outside that directory: no registry, no firewall, no game folders. File symlinks need Developer Mode or admin; those cases skip with a message when the privilege is missing. Required safeguards:
  1. The test root is created new and uniquely named under the canonical `target/` directory. The test canonicalizes it and panics unless it is inside `target/`, on a local fixed drive, not a reparse point and not under a cloud/OneDrive tag.
  2. Junction targets stay inside the test root. The escape target is a sibling `outside/` folder with a canary file whose content is asserted unchanged.
  3. Cleanup only after re-checking (1), handle-based and never following links.
  4. Locally the test skips when the process is elevated. On GitHub-hosted runners (admin, ephemeral VM) it runs. Extension (decided 2026-11-04): fixtures that change the machine beyond the test root (mount point, `subst`, `SetFileShortNameW`) run only there, never locally, and are undone by a drop guard. "There" means all three of `GITHUB_ACTIONS=true`, `RUNNER_ENVIRONMENT=github-hosted` and the explicit opt-in `RERUN_FS_MACHINE_FIXTURES=1`, which `.github/workflows/ci.yml` sets for the Windows test step only (review L6); the same gate allows the elevated run and switches on the strict skip policy. A self-hosted runner or a shell that merely sets `GITHUB_ACTIONS` gets none of it.
  5. No registry, `%TEMP%` or home-directory paths. The test-only root constructor is gated (`cfg(test)`/`fake` feature) and does not bypass the forbidden-root checks for anything else.
- **Contract split and fixture-based setup.** The file system contracts are split by side. The read side (`fs_read_contract`, `fs_link_read_contract`, `fs_volume_contract`, `fs_race_contract`) takes `&dyn Fs` and uses only `Fs::open_dir`, the methods of `Dir` (`info`, `open_dir`, `metadata`, `open_read`, `read`, `read_dir`, `users`) and `DirWrite::open_dir_write`, which only opens; it runs against `sys::fake` and `sys::win`. `users` is pinned by its error kinds and by fixture holds (it never asserts that nobody else holds a file: a scanner may hold a fresh one). Holds (`FsFixture::hold_open(p, Access, Share)`, a handle of the test process, `CreateFileW` in `WinFixture`): a held file is reported by `users` and gone once closed (R1); a hold that shares nothing makes `read` and `open_read` `Busy` but never `metadata` or `users` (R2); a hold with write access makes `read` `Busy` (`open_read` shares read only); a folder held with share 0 makes `open_dir` and `read_dir` of it `Busy`, while a walk through it to an entry below works (R4: `sys::win` opens walk components attribute-only). R3 (`ancestor_renames`): while a `Dir` handle, an `open_read` reader, a file hold (read, sharing read and delete, or nothing), an attribute-only file hold, a folder hold or an attribute-only folder hold is open below a folder, renaming that folder or any ancestor through the fixture is `AccessDenied`, and works once the handle is closed (observed matrix in ADR 0017, A5). `Fs::open_dir_write` and `DirWrite::open_dir_write` (a `WriteCap` from test code of the crate) reach the same directories with the same errors, and `refused_at`/`refused_through` also require `open_dir_write` to stop at every junction, symlink and mount point with `ReparsePoint`. Names (the read-side cases of the phase 1 write contract, set up by the fixture): non-ASCII case folding (`über.TXT` finds `Über.txt`), `Straße` is not `STRASSE`, `a..b`, `.hidden`, `$data.bin` and `my file.txt` listed and read exactly as spelled; renaming an ancestor of an open handle is `AccessDenied` and leaves the handle intact, renaming the handle's own directory makes `final_path` follow, and once the handle is closed the ancestor renames. Bounded reads (ADR 0011, ADR 0012): `read_limited` and `read_dir_limited` at the bound return everything, one byte or entry over it is `TooLarge` (also bound 0, an empty file or directory at 0, the handle's own listing and the next listing after a refusal, a listing of 1,000 entries that spans several `NtQueryDirectoryFile` batches, and one far over the bound that stops in the first batch). Raw UTF-16 names (`FsFixture::utf16_file`, P2-5): two names that differ only in an unpaired surrogate (`a\uD800b`, `a\uDC00b`) are both listed, each as `a\u{FFFD}b` with its own length, none dropped; the converted name addresses neither (`metadata` is `None`); a valid name made from UTF-16 units reads normally (skip `utf16_name`). The write side (`fs_write_contract`, `fs_link_write_contract`) exercises `DirWrite` and `FileGuard` (ADR 0017) and runs against the fake and, from P2-4, against `sys::win` in a `TestRoot` under `target/` (safeguards above). Everything a read contract needs on disk, and every attacker move, goes through an `FsFixture` (std::fs and raw calls in test code; `FakeFs` implements it for the fake): directories, files, junctions, directory and file symlinks, hard links, renames, case-sensitive directories, mounted volumes, `subst`, 8.3 short names, WOF compression, restricted DACLs (`FsFixture::restricted`: the current user is denied every access, the runner can still restore and remove the entry), handles held open (`FsFixture::hold_open`), another program's delete and attribute change (`FsFixture::remove`, `FsFixture::set_attrs`; on a link the link's own attributes, never its target's: `fs_link_read_contract` hides a junction and checks that `metadata` reports it on the reparse point while the target keeps its own, P2-5; the fake models attributes of links since then), files with raw UTF-16 names (`FsFixture::utf16_file`; the fake keeps a name with unpaired surrogates under its own key, so two such names that list alike stay two entries). The runner owns cleanup; a contract needs a fresh, empty work directory and the read contracts never delete anything.
- **Skips are observable.** A case the fixture cannot set up (no symlink privilege, no second volume, 8.3 names disabled, no WOF) returns `Ok(false)` / `Ok(None)` from the fixture. The contract skips it and returns the case names as `Skipped` (`Result<Vec<&'static str>, String>`), so the runner can tell a pass from a pass-by-skipping. The fake test runners assert the exact skip list (the fake has no 8.3 names, no WOF and no `subst`). On GitHub runners (`GITHUB_ACTIONS=true`) a skip is a test failure, except `mount_volume` (no second volume), `short_name` (8.3 names disabled) and `wof_compress` (not supported), which are warnings.
- **What the read contracts pin down.** `Fs::open_dir` accepts only drive-absolute input (`X:\…`, `\\?\X:\…`, `/` as `\`); `.`, `..`, UNC, device and volume-GUID paths, relative paths and stream paths are `InvalidPath`. A reparse point where a directory is expected, including a file symlink, is `ReparsePoint`, never `InvalidPath`. The matrix of link kinds (junction, directory symlink, file symlink, mount point) × position (`steamapps`, `common`, `Game`) is refused everywhere, with the right tag on `metadata` of the link. After every relative open the last segment of the normalized name must equal the requested one, so an 8.3 short name finds nothing (`NotFound`). A volume mounted in a folder reports an empty `volume_path` and its own serial when opened by absolute path and is a `MOUNT_POINT` surrogate below a root; a substituted drive shows the real location in `final_path` with the identity of the target. A restricted file or directory is listed by `read_dir` and described identically by `metadata` (`restricted`, `links: None`, length and attributes from the listing, own file ID), while `open_read`, `read`, `open_dir`, `read_dir` on it, walks through it and `Fs::open_dir` of it are `AccessDenied`.
- **Race harness (M-b).** `fs_race_contract(fs, fx, work, budget)`: the probe runs for at least `budget` and until the flipper has completed one flip (at most 30 s longer, so a loaded CI runner still races); a flipper thread swaps directories for junctions to an outside folder by path (renames at the first, middle and last of three directory levels) while the main thread probes through the root handle (`read`, `metadata`, `read_dir`, `open_dir` and reads through the sub handle). No result that comes back `Ok` may contain the canary's content, file ID or name `canary-only.txt`; allowed are `ReparsePoint`, `NotFound` (gap between two renames) and the real file's content. The assertion has to be able to fail: against the fake a fixture whose "junction" is a plain copy must be caught (`the_race_contract_catches_a_leaking_swap`). Against `sys::win` a test-only naive implementation (`NaiveFs`: check `symlink_metadata` per prefix, `yield_now` plus a 1 ms pause, then act on the full path) must be caught within a teeth window, otherwise the test fails with "harness lost its teeth"; the safe implementation then runs for `min(max(5 s, 10 × time-to-catch-naive), 60 s)`, where the time to the catch is the total, all rounds included. The window is the time of 100,000 fixture renames measured on 32 renames of a scratch folder just before, at least 30 s and at most 120 s (about 30 s on the developer machine), and a second, freshly measured window follows if the first ends without a catch: the test once failed with "harness lost its teeth" on a loaded machine, where every rename and so every flip was slower; what it proves (the naive control is caught) is unchanged (`catch_naive`). A catch only in the second round is a `::warning::` on GitHub runners. Both race tests and the two write contracts of `sys::win` take one process-wide lock (`heavy()` in `sys/win/tests.rs`): run in parallel they slowed each other's renames and flushes so much that the suite took twenty minutes and a naive control once escaped both windows (review of P2-4, measured with four parallel test threads). The fake runs the contract with a short budget as a sanity check; its deterministic step hooks remain the precise TOCTOU tests. Found on real Windows (2026-11-04): a flip is two renames by path (hundreds of microseconds each), so with a bare `yield_now` the naive window is far shorter than a flip and was never caught in 30 s; with the 1 ms pause it is caught in 20–100 ms on the developer machine, so the harness proves that it catches a check-then-use window the size of an ordinary preemption. Two minimal relaxations of the contract, both from real runs: the flipper retries a rename refused with `AccessDenied`/`Busy` (Windows does not rename a directory while any handle is open below it, whatever its share mode, ADR 0017 A5; the fake models the same rule; thousands of retries per run), and `info()` through a probed handle may return `NotFound` (see the `Dir::info` docs: the canonical path is resolved component by component and `sys::win` retries only a bounded number of times).
- **Fixtures that change the machine (mount point, `subst`, 8.3 short names) run only on GitHub runners** (`GITHUB_ACTIONS=true`), never locally (decided 2026-11-04). This extends safeguard 4: locally these fixtures report "not available" and their cases skip. Each one is undone by a drop guard (unmount, `subst /d`, no lasting short name), also on panic.
- **Runners against real Windows** (`sys/win/tests.rs`, fixtures in `sys/win/testfx.rs`, `cfg(all(test, windows))`). They run in the normal `cargo test` step locally and in CI; no extra CI step.
  - `TestRoot::new(case)`: the target directory is the ancestor of `current_exe()` that contains `CACHEDIR.TAG` (else panic); the root is `target/rerun-fs-contract/<pid>-<nanos>-<case>`, created with `create_dir` (never reused). After `canonicalize` it must lie strictly inside the canonical target, on a drive with `GetDriveTypeW == DRIVE_FIXED`, and no ancestor may carry `FILE_ATTRIBUTE_REPARSE_POINT`, `RECALL_ON_OPEN`, `RECALL_ON_DATA_ACCESS`, `OFFLINE`, `PINNED` or `UNPINNED` (else panic). An elevated process outside GitHub Actions gets `None` and the test returns with a note. Drop undoes the fixture's machine-wide changes newest first (mount points with `DeleteVolumeMountPointW`, drive letters with `DDD_REMOVE_DEFINITION | DDD_EXACT_MATCH_ON_REMOVE`, restricted DACLs), keeps the tree if an undo failed, re-checks the safeguards and only then calls `std::fs::remove_dir_all`, which since the CVE-2022-21658 fix is handle-based and removes links without following them (`cleanup_never_follows_a_junction` checks it with junctions to a sibling root).
  - Stale roots (review L7): `TestRoot::new` first removes roots `<pid>-<nanos>-<case>` whose process is gone (a test that was killed before its drop ran). Only plain directories (not reparse points, judged from the listing) that pass safeguard 1 are touched; every entry gets a DACL granting the current user full access through the owner's implicit `WRITE_DAC` (opened with `NtCreateFile` and `WRITE_DAC` only, because `CreateFileW` always adds `SYNCHRONIZE | FILE_READ_ATTRIBUTES`, which a restricted DACL denies), links are reset but never descended into, safeguard 1 is checked again, then `remove_dir_all`. Roots of the current or a possibly live process stay. Manual recovery if a root cannot be removed: `icacls <file> /grant <user>:F` on each restricted entry (as its owner), then delete the folder.
  - `WinFixture` (`FsFixture`) is bound to its `TestRoot` (review L5): every writing method requires the path to lie inside the root component-wise, without `.`/`..`, below no reparse point (the last component may be a link only for renames) and below no mount point of the fixture; link targets must lie inside `target/rerun-fs-contract`. Directories and files with `std::fs`; junctions with `FSCTL_SET_REPARSE_POINT` on a new empty directory (no admin, no `cmd`); symlinks with `CreateSymbolicLinkW(…ALLOW_UNPRIVILEGED_CREATE)`, `ERROR_PRIVILEGE_NOT_HELD` → not available; hard links with `CreateHardLinkW`; raw UTF-16 names with `OsString::from_wide` and `std::fs::write` (NTFS stores unpaired surrogates as given, observed 2026-11-06 on Windows 11 build 26300); renames with `MoveFileExW` without `REPLACE_EXISTING`; case-sensitive directories with `SetFileInformationByHandle(FileCaseSensitiveInfo)`; WOF with `FSCTL_SET_EXTERNAL_BACKING` (file provider, XPRESS4K); holds (`hold_open`) with `CreateFileW`, backup semantics only for a directory (with `SeBackupPrivilege` enabled, a read with backup intent passes a share-0 lock and a guard, a write does not: ADR 0017 "Backup intent"; `backup_intent_against_lock_and_guard` pins it where the privilege is enabled and prints the privilege state); restricted entries with a protected DACL denying the current user everything except `READ_CONTROL`/`WRITE_DAC`, set with `SetKernelObjectSecurity` on a handle opened before the change and kept for the undo (a new open would need `SYNCHRONIZE | FILE_READ_ATTRIBUTES`, which `CreateFileW` always adds and the DACL denies). GitHub runners only: `mount_volume` mounts another NTFS volume that is already mounted at a drive letter (so Windows never mounts a dormant volume for it) with `SetVolumeMountPointW`, and the fixture refuses every write below a mount point (the contracts never create anything there or list it); `subst` uses `DefineDosDeviceW` on a free letter; `short_name` enables `SeRestorePrivilege` on a thread impersonation token (`ImpersonateSelf`, reverted on drop), never on the process token, and calls `SetFileShortNameW`.
  - Skips: on GitHub runners (the gate of safeguard 4) a skip other than `mount_volume`, `short_name` and `wof_compress` panics; those three are written as `::warning::` lines (a `::warning::` for `mount_volume` means the I3 cases, a volume mounted in a folder, were not verified in that run) directly to the process's stdout (past the test harness capture, so the workflow sees them). Locally each skip is a note on stderr. Expected local skips on a standard user without Developer Mode: `dir_symlink`, `file_symlink`, `case_sensitive_dir` (`ERROR_ACCESS_DENIED` without the WSL component), `mount_volume`, `subst`, `short_name`.
  - Found on real Windows (2026-11-04): `wof.sys` hides the WOF reparse point (no attribute, no tag in `FileAttributeTagInformation` or the listing, `FSCTL_GET_REPARSE_POINT` → `ERROR_NOT_A_REPARSE_POINT`) while `FSCTL_GET_EXTERNAL_BACKING` confirms the backing; the WOF case therefore requires the content to be unchanged and accepts no tag or the WOF tag. `GetFinalPathNameByHandleW(FILE_NAME_NORMALIZED)` fails with `ERROR_FILE_NOT_FOUND` while an ancestor is renamed; `WinDir::info` retries such failures up to 32 times.
- **Topology contract** (`topology_contract(&dyn Topology)`, ADR 0010) only reads, so it runs against `sys::win` in CI and locally (`win_fulfils_topology_contract`, and through `WinSystem` in `win_system_bundles_the_real_parts`). `sys/win/cpu.rs` holds the layout test (`parser_offsets_match_windows_sys`: every offset of `rerun_proto::cpu::parse::layout` equals `offset_of!` on the `windows-sys` structures, plus the relationship, cache-type and flag constants), the bounded size-query/retry loop against a scripted call and a smoke test of the two real calls. `dump_cpu_topology` (`#[ignore]`, run by hand: `cargo test -p rerun-core --lib dump_cpu_topology -- --ignored`) reads both calls on the current machine and writes `target/cpu-dump.json` (fixture format 1, description still `TODO`) and `target/cpu-dump.parsed.json`; it writes nothing else. It zeroes every CPU Set byte the parser does not read, bytes 20 to `Size` of each record (an allowlist; found on the 5950X, 2026-11-05: `SchedulingClass` holds the firmware's preferred-core ranking, 15 distinct values that differ per chip sample, i.e. a fingerprint), and checks that the scrubbed bytes parse to the same topology. `rerun-core/tests/cpu_fixtures.rs`: every `*.raw.json` parses to its `*.json` (strict format: four fields, `format: 1`, a description without `TODO`, lower-case hex in 32-byte lines), every parsed fixture validates, every committed dump has the unread CPU Set bytes zero, the 5950X dump is 2 L3 x 8 cores x 2 threads, and mutated real dumps never panic (xorshift, no `proptest`).
- **OS build** (ADR 0015, `hw/os/tests.rs` against the fake; `FakeSystemBuilder::os_build(build, ubr)` writes `CurrentBuildNumber` and `UBR`): `1`, `20348`, `22000`, `26300` and `u32::MAX` parse; empty, `0`, a leading zero, surrounding spaces or a tab, a sign, a dot, a comma, hex, `u32::MAX + 1`, 20 digits, full-width and Arabic-Indic digits and a trailing bidi mark are `Malformed`, as are `REG_DWORD`, `REG_QWORD`, `REG_EXPAND_SZ`, `REG_MULTI_SZ`, `REG_BINARY` and `Raw` values; an absent value is `Missing`, an absent or denied key a `Sys` error with its kind; a value only in the 32-bit view is not seen; `UBR` of another type is `None` and never fails the build; messages name `CurrentBuildNumber` and the kind, never the stored text. On real Windows `os_build_matches_rtl_get_version` (`sys/win/tests.rs`, read-only) reads the build through `WinRegistry` and compares it with `RtlGetVersion` (`testfx::rtl_build_number`, the only call, under its own `expect`) and requires `UBR` (Windows 10, Server 2022 and 11 always set it); it assumes no minimum build. The version APIs (`GetVersion`, `GetVersionExA`/`W`, `VerifyVersionInfoA`/`W`, `VerSetConditionMask`, `RtlGetVersion`, `RtlVerifyVersionInfo`) are `clippy.toml` bans checked by `banned_version_items_resolve`.
- **System profile** (ADR 0015, `hw/tests.rs` against the fake; device IDs other than `0x1002`/`0x7550` are synthetic and mapped by a test-only table): the developer machine (5950X fixture, RX 9070 XT, Basic Render Driver, build 26300) gives `amd`, `rdna4`, 32 threads, not hybrid, build 26300 and 16,384 MiB; a runner's Basic Render Driver without the software flag is dropped (`NoAdapter`), as is a software adapter of any vendor; a GPU error makes both GPU facts `Unavailable` (checked before the adapters and the table) while CPU and OS are read; without a table the vendor is known and the arch `Unavailable` (no adapter still `NoAdapter`); an unknown device is `ArchFact::Unknown` with `integrated: None`; revision and subsystem IDs do not change the lookup; an iGPU listed before a dGPU stays first and is the conditions adapter; another vendor is `Other`; the i5-6600 has 4 threads and is not hybrid, an inline topology with two efficiency classes is; each part fails alone (no topology, a `REG_DWORD` build). - **GPU on real Windows** (ADR 0008 amendment 2026-11-05, read-only): `win_fulfils_gpu_contract` runs the contract against `WinGpu` and requires exactly one Microsoft Basic Render Driver (vendor `0x1414`, device `0x8c`) with the `software` flag, which every machine and every GitHub runner lists. Our leftovers (`n.bin`, a deleted `t.bin`) are reset through the handle before the next round. It runs at least 12 rounds (every move meets every operation) and `budget`. The delays are random per round from a seed per run (xorshift, the seed is in every failure message), so attempts never replay one schedule. - **Real machine** (manual, read-only): `dump_exe_candidates` (`crates/rerun-core/tests/pe_system.rs`, `#[ignore]`, Windows only), see the manual test matrix.

## CLI

See ADR 0016. Output is human-readable text, not an interface; the tests pin it so that changes are deliberate.

- **Escape** (`rerun-core`, `escape` tests): every range of the table at both bounds and one past them (inside escaped, outside kept), for each entry point; `path` escapes everything `text` escapes and everything `is_deceptive` matches; `text` keeps full-width letters, `¥`, special spaces and BMP private use; U+FFFD kept; a clean string comes back borrowed and unchanged; an escaped string has the form `"…"` with `\u{x}`; idempotent for every case and for random strings (xorshift, fixed seed); every valid `RelPath` fixture of `tests/fixtures/paths.json` is unchanged by `path`.
- **Rendering** (golden strings with `assert_eq!`, no snapshot crate): the pure render functions of `system` and `scan` on directly built values (public fields). System: two hardware adapters (numbered from 0 in DXGI order) with the conditions adapter marked and the note, an unknown device (`unknown (0xVVVV:0xDDDD not in the table)`, synthetic ID), the GPU unreadable, no hardware adapter, no table; the 5950X fixture as `2 L3 groups x 8 cores x 2 threads` with one line per L3 group, a hybrid inline topology; the build with and without `UBR`; every fact of the five conditions. Scan: `Main::One`, `Tied` (every tied executable, no pick), `None` with each reason; a version as numbers only; hashes; `UpdatePending` and `NotInstalled` apps listed without executables; an empty or whitespace-only library label without a line, a label with a tab quoted; an unknown requested app ID; the summary and the hint line; the walk line (depth cut or a limit) only with `Main::None`, never with `One` or `Tied`; every untrusted field with ESC, U+202E, U+2028 and tag characters in its escaped form.
- **Output writer:** `BrokenPipe` ends the output silently with exit 0, another write error is exit 1. The last-resort net panics in `cfg(test)`, so every test that renders through `Out` also proves that it never fired.
- **End-to-end against the fake** (in-process: `system`/`scan` with `FakeSystem`, stdout and stderr in memory; `rerun-core` with `fake` is a dev-dependency of `rerun-cli`): one or two games with synthetic images from `tests/support/pe_image.rs` (main executable, launcher). Malicious fixtures: an `installdir` with `..`, a manifest over 1 MiB, nesting over the limit, a missing required field, a name and a label with ESC, U+202E and tag characters, `LastOwner "76500000000000001"`. Expected: exit 0, the other games still listed, one issue line per problem with its location (escaped) and kind and never file content, the affected app never opened; the `LastOwner` value appears nowhere in stdout, stderr or `{:?}` of the scan results. Exit codes: an unresolvable `ForbiddenRoots` (a known folder missing) is 1 without a report, Steam not installed is 0 with a report. The parser-level matrix stays in `rerun-core` and is not repeated here.
- **Binary** (`crates/rerun-cli/tests/`): `--help` and `--version` exit 0; a bad `APP_ID` and an unknown flag exit 2. `rerun system` runs on the real machine in the normal suite (read-only, also in CI): exit 0 with the GPU, CPU, OS and Conditions blocks; on a GitHub runner the GPU block says "no hardware adapter". `rerun scan` on the real machine is a local opt-in only (`#[ignore]`, and only with `RERUN_SMOKE_REAL=1`): read-only, it prints aggregate counts only (libraries, games, parse errors), never names, paths or SteamIDs, and writes no snapshot file (`RERUN_SMOKE_REAL=1 cargo test -p rerun-cli --test scan -- --ignored --nocapture`).
- **Source rule** (`crates/rerun-cli/tests/source_rules.rs`): the product sources of `rerun-cli` (`src/`, without the `tests.rs` files) never call `RawText::as_raw_str` (raw text is shown through `RawText::escaped`), never use a `Debug` format spec (`{:?}`, `{x:>8?}`, `{:5?}`, `{:#x?}`, …) and never `dbg!`; a teeth test for each form.
- **clap without colour** (CI step): fails if `cargo tree -p rerun-cli -e normal,features -i clap_builder` or the same with `--workspace` shows feature `"color"` (with a sanity check that the output still holds `clap_builder feature "std"`).
- **Release `rerun.exe`** (`crates/rerun-cli/tests/hardening.rs`): CI builds `cargo build -p rerun-cli --release` (without dev-dependencies, so without `rerun-core/fake`) before the tests, and `release_rerun_exe_loads_dependencies_from_system32_only` checks it through `RERUN_RELEASE_CLI_EXE` (required on GitHub-hosted runners, skipped locally when unset): `DependentLoadFlags`, `CLI_IMPORTS`, no delay-load import, and no console state API (`SetConsoleMode`, `SetConsoleOutputCP`, `SetConsoleCP`) named anywhere in the image, a byte search over the file (`console_state_apis` in `tests/support/hardening.rs`, with a teeth test), so `detect::pe` needs no function-name API. The test-profile `rerun.exe` gets the same console check.

| `registry_set` round trip in the real `HKCU` (Windows Sandbox, P2-10b) | a `file_install` + `registry_set` plan applied and reverted with `WinSystem` (real `RegOpenCurrentUser(KEY_READ)` root, `RegFlushKey` on the real hive) at `HKCU\Software\RerunSandbox\Game`: snapshot of the game folder and `HKCU\Software\RerunSandbox` identical; a value changed between apply and revert is left (`Foreign`); a link key planted at `Software\RerunSandbox` after the apply is `Foreign` and its target unchanged; power loss in a VM between `Done` and the hive flush (the hive is flushed lazily: the 6a path of scenario 10 runs for real) | open |
| Power loss during apply in a VM (journal on `C:`, game folder on a second virtual disk `D:`) | cut power at random points of a multi-file `file_install`; after boot `status` shows the transaction open or applied, `revert` reaches the exact snapshot taken before the apply; can only show the absence of a problem, not prove durability (ADR 0019) | open |
| Game running during apply and revert | `users()` reports the running exe and an open target: refused with "in use, try again later" before any write; a DLL loaded without an open handle is reported too; nothing changed | open |
| A third party holds the game folder open without `FILE_SHARE_WRITE` | every rename is `Busy`: apply rolls back (or reports the transaction open), nothing half-done; a later run after the handle is closed succeeds | open |
| `compat_layer` in Windows Sandbox | the token list and `~`/`$` prefixes as Windows writes them from the Properties dialog; whether a game reached through a junctioned library is matched by the canonical or the launch path (P2-11, ADR 0018) | open |
| Snapshot over a symbolic-link key in the real `HKCU` (Windows Sandbox) | a scope key holding a link key: the snapshot follows it on reads (ADR 0009); a link key is one `RegLink` entry and is not entered (closed in P2-9; pinned in the fake and an app hive by the snapshot contract), so a link to an ancestor ends at once; in the real hive check the kernel name in the target and that a value behind the link shows only at its target; app hives cannot follow links, so this is a Sandbox case | open |

## Rules

- No test modifies the real system outside the sandbox.
- Bugs: failing test first, then the fix.
- Fixtures are data, not code generators. **Exceptions:** PE test files are built by small builders in test code (`crates/rerun-core/src/detect/pe/testfx.rs`; the minimal writer `tests/support/pe_image.rs` for the hardening teeth and the CLI tests), because third-party binaries must not be committed and hand-written binary fixtures cannot be reviewed. Likewise the Windows topology records (`SYSTEM_CPU_SET_INFORMATION`, `SYSTEM_LOGICAL_PROCESSOR_INFORMATION_EX`) for the parser's edge cases are built by a byte builder in the `rerun-proto` tests (`cpu/parse/tests.rs`, ADR 0010); real machines are raw dumps (`tests/fixtures/cpu/*.raw.json`).
- VDF fixtures (`tests/fixtures/vdf/`, ADR 0011) are synthetic: every path, label, app ID, name, size and ID is invented, never copied from a real Steam installation or account. `.gitattributes` forces `eol=lf`, so CRLF and BOM cases are built inline in the tests.

# ADR 0025 · Packages: download, extraction, versions

**Status:** accepted · 2026-11-10, part 1 (download and cache, P4-6; amended the same day by the reviews of P4-6: exit codes per error, overall deadline, revocation); part 2 (extraction, the `package` step, P4-7) the same day · extends ADR 0008, ADR 0013, ADR 0019, ADR 0020, ADR 0024 · phase 4

## Context
A package (`docs/02-topo-format.md`) names an upstream release archive by URL and pins its SHA-256. Phase 4 must bring that archive onto the machine without a new crate (plan P4, L5: "HTTP over WinHTTP, redirects by hand only to fixed forge hosts, non-elevated only"), without trusting anything the network or the user-writable `<LocalAppData>\Rerun` holds, and so that the later steps (extraction, P4-7; the elevated helper never downloads) can rely on one property: an archive in the cache is used only after it hashed to its pin. One package is one version (user decision E2 a); the download is per package URL, so a version is just another package.

## Decision

### Part 1: download and cache (P4-6)

**One network path.** `sys::Http` (one `get(host, path)`: exactly one HTTPS request, no redirect followed, status, `Location`, `Content-Length` and the body as a stream) with the real `sys::win::WinHttp` and the scripted `sys::fake::FakeHttp`. `Http` is not part of `System`: the elevated helper's system can never reach the network (its source rule forbids `WinHttp` and `http::`), and the curator tool (P4-14) uses the same wrapper without a system.

**WinHTTP, fixed settings** (`sys::win::http`, the only WinHTTP calls; `windows-sys` feature `Win32_Networking_WinHttp`, no new crate; `winhttp.dll` joins `CLI_IMPORTS`, ADR 0008 amendment P4-6):
- a fresh session, connection and request per call, closed in that order when the body drops (owned handles);
- `WINHTTP_FLAG_SECURE`, port 443, TLS 1.2 or 1.3; Schannel validates the certificate as WinHTTP does by default, and nothing ever sets `WINHTTP_OPTION_SECURITY_FLAGS` (a workspace source rule fails on `SECURITY_FLAG_IGNORE_*` and on WinINet's `INTERNET_FLAG_IGNORE_CERT_*`);
- no automatic redirect (`WINHTTP_OPTION_REDIRECT_POLICY_NEVER`, `WINHTTP_DISABLE_REDIRECTS`), no cookie (`WINHTTP_DISABLE_COOKIES`), no authentication (`WINHTTP_DISABLE_AUTHENTICATION`), no automatic logon with the user's credentials (`WINHTTP_AUTOLOGON_SECURITY_LEVEL_HIGH`; a proxy that asks for credentials answers 407, which is an error);
- the system proxy (`WINHTTP_ACCESS_TYPE_AUTOMATIC_PROXY`), synchronous, 30 s per resolve, connect, send and receive, response headers at most 64 KiB; a `Location` is read only for a 3xx status (the fake does the same), at most 8.5 KiB of printable ASCII;
- the path is sent as given (`WINHTTP_FLAG_ESCAPE_DISABLE`, `…_QUERY`) after `sys::http::check_request` (plain host, path from `/`, printable ASCII without space, `\` or `#`, at most 8 KiB);
- the user agent is `Rerun/<version>` and nothing else; no other request header of Rerun's own;
- certificate revocation is not checked (no `WINHTTP_ENABLE_SSL_REVOCATION`), deliberately: integrity rests on the pinned SHA-256 and the fixed hosts, and a CRL/OCSP fetch would break offline and proxied setups where the asset itself is reachable;
- refused unless the process restricted its DLL search path first (`restrict_dll_search`, ADR 0008), because WinHTTP loads further system DLLs at run time.
- `clippy.toml` bans `WinHttpOpen` and `WinHttpSetOption` outside `sys::win::http`, and the URLMon download helpers (`URLDownloadToFileW`, `URLDownloadToCacheFileW`, `URLOpenBlockingStreamW`, `URLOpenStreamW`; they follow redirects and use the browser cache) everywhere.

**The URL rules** (`policy::url`, one grammar for the loader and the downloader; moved there from `catalog::check`): the form of docs/02 (`https_url`, `release_download`), provenance (`belongs`: a release download only of its own `source.repo`, anything else only on the host of `source.page`), and two download rules:
- `HttpsUrl::download`: a package URL in the form, printable ASCII without `#` (the loader's form admits more; the downloader refuses rather than encodes);
- `HttpsUrl::redirect`: a `Location` is followed only if it is an absolute `https` URL without userinfo, port or IP literal, its host passes the host rule and is listed for the host that sent the redirect in `REDIRECTS`, and its path is printable ASCII without `#`. `REDIRECTS` is fixed in code: `github.com` → `objects.githubusercontent.com`, `release-assets.githubusercontent.com`. No other host redirects anywhere, an asset host not further, and a redirect to the same host is refused too (on a forge it could leave the repository the provenance rule checked). A forge that changes its storage hosts fails closed until the list changes (risk R5 of the plan).

**`pkg::download`**: `downloads(package)` lists the downloads of a package of the signed index (`source.release` with `sha256`, or one per `assets[]`), re-checks form and provenance itself, and has none for a `community` package or a `TODO` value. `fetch(sys, http, app, download)`:
1. refuses an elevated process (or one whose elevation is unknown), as every changing command (`exec::standard_user`, P2-13 E3);
2. opens `<AppDir>\cache` handle-relative (created if missing, never through a reparse point) and holds `cache\lock` (share 0) for the whole fetch; deletes temp files (`.rerun-<tag>-<n>.tmp`) an interrupted fetch left, which under the lock none can be using;
3. a cache entry `<sha256>` (64 lower-case hex digits) is hashed on a guard every time: used if it hashes to its name, deleted on that guard and downloaded again if not; an entry that cannot be guarded (hard link, directory, reparse point) is an error that names it;
4. requests the package URL and follows at most three redirects (301, 302, 303, 307, 308) as `HttpsUrl::redirect` allows; a refused `Location` is never requested; any other status than 200 is an error;
5. ends the download when `MAX_DOWNLOAD_TIME` (10 minutes, from the first request to the last byte; about 110 KB/s for 64 MiB) has passed, checked before every request and every read (WinHTTP's timeouts bound each step, this a server that keeps sending slowly); refuses a `Content-Length` above `MAX_DOWNLOAD_BYTES` (64 MiB) before reading; otherwise the length is advisory, the limit is counted on the bytes read, and a body that ends before or runs past its `Content-Length` is refused;
6. streams the body through `DirWrite::create_new` (ADR 0017): a temp file next to the target, hashed on the way; a hash other than the pin, a transport error, the limit or any write error deletes the temp file, so the name `<sha256>` only ever holds exactly the pinned bytes; then the rename without replace and a flush of the folder.

`Download` has private fields: only `downloads` builds one (tests through a `cfg(test)` constructor). `fetch_noting` reports whether the run stored an archive or removed a damaged entry, also when it then fails.

A cached archive stays untrusted: its user (extraction, P4-7) hashes it again on its own handle before reading an entry.

**CLI:** `rerun package fetch <id>@<version>`: the elevated guard, the current signed index (read back and checked like `index show`; none is exit 3), the package by ID and its one version (another version is exit 3 and names the one in the index), then every download of it; one line per download (cached or downloaded, length, SHA-256).

**Exit codes** (`FetchError::transient` decides; amended after the reviews of P4-6):

| Outcome | Errors | Exit |
|---|---|---|
| Every download in the cache | none | 0 |
| A failure after this run stored an archive or removed a damaged cache entry | any | 0, the lines of what was done, then the failure on stderr |
| A refusal by policy or integrity, nothing changed | `Elevated`, no index, unknown package, other version, `NoDownload`, `Provenance`, `Url` (form or redirect rule), `TooManyRedirects`, `NoLocation`, `Status` 4xx other than 429, `TooLarge`, `Mismatch`, `CacheEntry` (a hard link, directory or reparse point at the entry's name: remove it) | 3 |
| Passing or in the environment, nothing changed | `Network` (WinHTTP code), `Status` 5xx and 429, `Length` (a body shorter or longer than its `Content-Length`), `TimedOut`, `CacheBusy` (an entry in use or another passing guard error: try again, never "remove it"), `Root`, `Sys` (also `cache\lock` held by another fetch) | 1 |

### Part 2: extraction and the `package` step (P4-7)

**Formats.** `zip` (entries stored or deflated) and `tar.gz` (one gzip member holding a ustar or GNU tar). The download's file name (the last segment of its URL path) names the format: `.zip`, `.tar.gz` or `.tgz`, ASCII case ignored; anything else is refused (`ExtractError::Format`), and the reader then requires the format's own structure (a zip named `.tar.gz` is `NotFormat`). Inflate is the one new crate, `miniz_oxide` 0.9.1 (raw DEFLATE only, pure Rust with `#![forbid(unsafe_code)]`, MIT OR Zlib OR Apache-2.0, one dependency `adler2`; default features only, pinned exactly like `ed25519-compact`: it decides how untrusted bytes decode). The zip, gzip and tar readers and CRC-32 are Rerun's own (`pkg::archive`, plan L6): about 1,500 lines with their documentation (the test archive writer apart), no `unsafe`, no recursion.

**The readers (`pkg::archive`, the style of ADR 0013).**
- **Whole archive in memory.** At most `max_archive_bytes` (= the download limit, 64 MiB). The caller hashes exactly the bytes it hands in (`pkg::extract` reads the cache entry whole and hashes it again), so nothing can change between the hash and the parse.
- **Structure first, then content.** `Archive::open` checks every entry before anything is extracted; `Archive::extract` then reads only the entries asked for, each against its declared size and (zip) CRC-32, in archive order, one pass.
- **zip:** the end record is the one closest to the end whose comment ends exactly at the end of the file (searched in the last 22 + 65,535 bytes); the central directory lies directly before it and holds exactly the stated entries back to back. Every local header agrees with its central entry (signature, the encryption, data-descriptor and UTF-8 flags, method, the name byte for byte, CRC-32 and sizes; with a data descriptor each is 0 or the same), a data descriptor (with or without its signature) repeats the central CRC-32 and sizes, every entry's local header, data and descriptor lie before the central directory and no two entries share a byte (the overlapping zip bomb). A deflated entry must end its stream exactly at its compressed size and yield exactly its declared size; a stored entry's two sizes are equal; a folder has no content.
- **Refused in a zip:** zip64 (any field at its maximum, a zip64 locator, a zip64 extra field), more than one disk, encryption (bits 0, 6, 13), any method but stored and deflate, the Info-ZIP Unicode path field `0x7075` (other tools would extract under a name Rerun never checked), a malformed extra field, a name that is not UTF-8 with flag 11 or not ASCII without it, a Unix mode other than file or folder (a link, a FIFO …), the Windows reparse point attribute.
- **tar.gz:** the gzip header (`CM` 8, no reserved flag, an optional name and comment of at most 1 KiB each, the header CRC if flagged), the DEFLATE stream counted against the limits, the trailer (CRC-32, length mod 2^32) and nothing after it (no second member). The tar headers: the checksum, the magic `ustar\0` + `00` (POSIX, a `prefix` joins the name) or `ustar  \0` (GNU); octal sizes. After the first zero block only zero bytes. Types `0` (and NUL) and `5` only: hard links, symbolic links, devices, pipes, contiguous files, GNU long names, pax headers (they could rename the next entry for other tools), sparse files and every other type refuse the archive; so do a version 7 header and a base-256 number. The whole gzip member, CRC included, is checked before anything is written; extraction then decompresses once more and copies the asked entries on the way.
- **One name rule for every entry, extracted or not:** the stored name with `/` as the only separator (a `\` is refused), a folder may end in one `/`, a tar name may start with one `./`; the rest must be a `RelPath` (no `..`, `.`, empty segment, leading separator, drive, UNC, `:` and so no alternate data stream, reserved device name, 8.3 short name, trailing dot or space, deceptive Unicode such as fullwidth or slash look-alikes). No two entries share a name compared like NTFS (case-insensitively, one-to-one fold); no entry lies below a file entry. An archive with one bad entry is refused whole.
- **Limits** (`Limits::DEFAULT`; exactly the limit passes, one more is refused):

| Limit | Value | Reason |
|---|---|---|
| archive (`max_archive_bytes`) | 64 MiB | the download limit; DXVK 2.7.1 is 10 MB, the larger Ultimate ASI Loader zip 7 MB |
| entries (`max_entries`) | 4,096 | real package archives hold 1 to a few hundred |
| entry name (`max_name_bytes`) | 1,024 bytes | a `RelPath` has at most 240 characters; a tar name at most 256 bytes anyway |
| one entry (`max_entry_bytes`) | 256 MiB | the largest DXVK DLL is 5 MB |
| all entries / the tar stream (`max_total_bytes`) | 512 MiB | a zip's declared sizes summed; a tar.gz's whole decompressed stream (DXVK: 41 MB) |
| ratio (`max_ratio`, above `ratio_floor`) | 100 : 1 above 1 MiB | per zip entry, and for the whole tar stream; DLLs compress 2 to 4 : 1, small text files may compress far better and are harmless |

**Extraction (`pkg::extract::extract`).** Standard user only. Only the files a package names, from `files[].from`, compared with the archive's names exactly after the separators became `\` (case included; `NotFound` says when only the case differs). Into `<AppDir>\packages\<id>\<version>` (one package is one version, user decision E2 a; another version is another package with its own folder), opened and created handle-relative one level at a time, never through a reparse point, under `packages\.lock` (share 0; not a package ID, which never starts with `.`). Per download: if every file it provides is there with its pinned SHA-256 (hashed on a guard), its archive is not read at all; otherwise the cache entry is read whole (at most the download limit) and hashed again (`CacheChanged`: fetch again; `NotCached`: fetch first), the format is named, the structure checked, and each file streams from the entry reader through `DirWrite::create_new` (temp file, hashed, renamed without replace, folder flushed): a hash other than `files[].sha256`, a damaged entry or a write error leaves nothing under the name (`Mismatch`, `Archive`). A file already there with other content is deleted on its guard first; a link, reparse point or folder in its place is named and left (`Entry`: remove it). Temp files an interrupted run left in a folder are swept before it is written. Nothing here is journaled: the packages folder is Rerun's store, not the game, and `file_install` hashes every source when it plans and again while it copies. A package without files creates nothing.

**Where a file lies (`layout`, `source_path`).** With one download: `<version>\<from>`. With one download per architecture (`assets`): `<version>\<arch>\<from>` (`x86`, `x64`), because the same name is another build per asset (Ultimate ASI Loader's `dinput8.dll`); a file with `arch` comes from those assets only, one without from every asset. One place holds one file: the loader refuses a second entry of the same place with another SHA-256, a file `arch` outside the package's `arch` and, for `assets`, an architecture without an asset (`catalog::check`, `files_placed_once`). The draft `packages/ultimate-asi-loader.yaml` lists its `dinput8.dll` once per architecture accordingly.

**The `package` step (ADR 0020 amendment P4-7).** A Topo's `package: <id>` (the package pins its version, E2 a) becomes the `file_install` step of the package's files for this game (`prim::package::file_install`): the architecture of the main executable from its PE header, the graphics API the Topo states for it (`match.exes[].api`); `ContentRef::Package` names the place below the version folder. The planner only reads: a package whose files are not unpacked is refused with the command that unpacks it.

**CLI.** `rerun package fetch <id>@<version>` downloads every archive of the package (part 1), then unpacks its files (one line per file: unpacked, already unpacked, or unpacked over a changed file). Exit codes as in part 1; an unpacking failure is refused (3) or passing (1) by `ExtractError::transient` (a file in use, the file system), and exit 0 with the lines of what was done when this run downloaded, replaced or unpacked anything before it.

**Tests.** `pkg/archive/tests.rs` (the corpus of docs/09 "Package archives": every bad name in zip and tar, duplicates and case collisions, entries below files, every tar type, zip links, reparse attributes, ratio and every limit at and over, overlapping entries, wrong CRC and sizes, lying descriptors and local headers, zip64, several disks, encryption, other methods, the Unicode path field, data around the archive, the gzip trailer and the tar end, every prefix of an archive, every changed byte), `pkg/extract_tests.rs` (only the named files below the version folder, nothing else in Rerun's folder after a refusal, per-architecture assets, a wrong hash keeps nothing, exact names, formats, the cached archive hashed again, a junction in the version folder, a crash leaves a temp file the next run sweeps, elevated), `topo/tests.rs` TK (the planner's filters and refusals; the round trip cached archive → extract → engine → apply → verify → revert, the game folder identical; `requires`; anti-cheat), the CLI (`package_tests.rs`). [SB] `sandbox_package_dxvk_and_asi_loader_round_trip`: DXVK 2.7.1 (`tar.gz`) and Ultimate ASI Loader v10.0.2 (`zip`, both assets) downloaded in the CI sandbox job, each archive against the `digest` GitHub reports, each unpacked file against its pin and against System32's `tar.exe`, installed into a game folder and reverted.

**Alternatives (part 2).**
- **The `zip` crate, `tar` + `flate2`:** large surfaces (zip64, bzip2, AES, time crates; `tar`'s `unpack` writes links and extracts everything), behaviour decided upstream for exactly the cases this part refuses; the plan chose own readers (L6).
- **Extract everything, then pick:** writes entries Rerun never needs, the very thing Zip Slip abuses; refused.
- **Stream a tar.gz once and write while reading:** the gzip CRC is known only at the end, so a damaged archive could leave files; the second decompression costs about a second for DXVK.
- **Read zip64:** no package archive under the 64 MiB limit needs it; refusing keeps one size field and one offset per entry. Revisit if an upstream ships zip64 for a small archive.
- **Format by magic bytes alone:** the URL's name is signed in the index and says what the curator meant; both must agree.

## Alternatives
- **`reqwest`/`ureq` with rustls:** a TLS stack and an HTTP client as new dependencies (and certificate roots of their own instead of the Windows store, proxy handling of their own); refused by the plan (no new crate, Schannel, the system proxy).
- **WinHTTP's own redirect handling with a callback that vets each hop:** asynchronous mode and a status callback for one check that a loop of plain requests does with less code; the policy would also sit inside `sys`.
- **A size field per package** (exact length pinned next to the hash): stricter than one limit, but a format change for every package; the hash already pins the length, and one limit far above every known archive bounds the cost of a wrong one. Revisit if a package ever comes near the limit.
- **`.part` file names:** the existing `create_new` already writes through a journal-shaped temp name and deletes it on every failure; a second naming scheme would need its own cleanup.

## Consequences
- `rerun.exe` imports `winhttp.dll` (not a KnownDLL; loaded from System32 by `/DEPENDENTLOADFLAG:0x800`); the helper does not (`HELPER_IMPORTS` unchanged, its source rule forbids the network).
- Network tests run only in the sandbox suite: `sandbox_package_download_of_a_github_release_asset` downloads `EaglePatchAC1.zip` (v1.1, 44,574 bytes) through the product path as the CI standard user, checks it against the SHA-256 GitHub reports for the asset and measures it independently. Everything else runs against `FakeHttp` (`docs/09-testing.md`, "Package download").

- Part 2: `miniz_oxide` (and `adler2`) join the lock file; the release binary gains Rerun's archive readers. docs/01 (`pkg`, `prim`, CLI), docs/02 (Unpacking, `files[]`, the `package` step), docs/06 (#5), docs/09 ("Package archives", the [SB] row) updated.

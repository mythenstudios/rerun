# ADR 0030 · Distribution of the alpha: per-user install, portable copy, uninstall gate

**Status:** accepted for the unsigned alpha · 2026-11-24 · plan P5-13 (user decisions U1 a, U2 c, U3 b, U5/U6 as revised, U7 a, U8 a, U9 a) · extends ADR 0006, ADR 0016, ADR 0022, ADR 0023 §2, ADR 0024, ADR 0027 · the final installer form is decided at A6

## Context
Until now Rerun ran only from `target\`. The developer wants to use it every day before the first release: a local release build, installed without administrator rights, updated and removed again cleanly, plus a portable copy of the same files. Code signing and the GitHub release pipeline stay at A6 (docs/08).

Facts that shape the design:
- **The install folder is the folder of the running exe** (`current_exe().parent()` in `rerun-app` and `rerun-cli`). The Steam launch option Rerun offers names it absolutely (`"<install>\rerun-launch.exe" --profile <id> %command%`, ADR 0022, docs/04): moving or removing the folder breaks every game that has the option until the user removes or replaces it in Steam. Rerun does not read Steam's settings (ADR 0028 is phase 6), so it cannot see which options are set; it only knows the profiles transactions hold and the launch results the shim wrote.
- **The helper can only live in `Program Files\Rerun`**, admin-only (ADR 0023 §2, ADR 0008 H2). No active Topo uses `firewall_rule`, and an unsigned helper's UAC prompt cannot be told apart from malware of the same name (A4 S12).
- **Rerun's data** (journal, backups, launch profiles, launch results, packages, index, settings) is in `<LocalAppData>\Rerun`, independent of the install folder. Removing it removes the journal and the backups a revert needs (rule 2).
- **Smart App Control** judges every new unsigned exe by its hash and may block it at any time (os error 4551); the developer machine enforces it.

## Decision
1. **One payload, two forms.** `scripts/alpha-build.ps1` (ADR 0006 amendment P5-13c) builds `dist\rerun-<version>-<commit>\`: `rerun-app.exe`, `rerun.exe`, `rerun-launch.exe`, `LICENSE`, `THIRD-PARTY-NOTICES.txt`, `README.txt`, `index.json` + `index.json.sig`, `install.ps1`, `uninstall.ps1` and `payload.json` (format 1: product, version, build ID, every other file with size and SHA-256, the index's `seq` and key ID or `null`). The portable zip is that folder as it is. For the app, installed and portable do not differ: it needs `rerun-app.exe`, `rerun.exe` and `rerun-launch.exe` in one folder. Not shipped: `rerun-helper.exe` (U2 c: no helper until an active Topo needs one, ideally signed at A6; firewall fixes stay locked with the existing "needs the installed helper" text), `rerun-cpu.asi` (phase 6), `rerun-workbench`.
2. **Fixed install folder `<LocalAppData>\Programs\Rerun`** (known folder `LocalApplicationData` + `Programs`, never the environment), per user, no administrator, no choice of folder. **This path stays for the A6 installer form** whatever it is (MSI, signed scripts, an own installer): a different path would break every Steam launch option at the first update. MSIX is out for that reason (a versioned path).
3. **Technique for the alpha: PowerShell scripts plus one read-only CLI command.** `install.ps1` and `uninstall.ps1` (Windows PowerShell 5.1, ASCII, in `packaging/windows/`) do files and the shortcut; what needs Rerun's knowledge (open transactions, launch options) comes typed from `rerun uninstall-check` (ADR 0016 amendment P5-13b). Both scripts refuse to run elevated (an over-the-shoulder elevation would install into the wrong profile) and start Rerun only as the user. No registry entry (no "Apps & Features" entry in the alpha, U4 moved to A6), no PATH change, no service, no scheduled task, no autostart (rule 1).
4. **Install** (`install.ps1`, from the payload folder): checks every payload file against `payload.json` (plain file, size, SHA-256), file names one segment of `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`, no reparse point on the way to the targets. An existing install (`install.json` there) stops: update is uninstall with `-KeepData` plus install. A folder that holds anything but files of this payload stops with nothing touched; only files of this payload (an interrupted install) are replaced. Preview of every file (size, SHA-256), the target, the Start-menu shortcut `Rerun.lnk` (a foreign one of that name stays and none is created), `install.json`, the index import and the data folder, then one Enter. Then: copy and hash again, `rerun.exe --version` and `rerun-launch.exe` without arguments (usage, starts nothing) as the Smart App Control check, the shortcut, `install.json` (format 1: version, build, the installed files with SHA-256, whether the shortcut is Rerun's), `rerun.exe index import` of the shipped index (a refusal is a note; the app shows why), and Rerun is started. A failure before that end, os error 4551 included, undoes the run newest first: only files with the copied hash, only folders it created and that are empty, only its own shortcut. Smart App Control is never bypassed.
5. **Uninstall gate** (`uninstall.ps1`, for the installed and for a portable copy: it always removes the folder it lives in): an installed copy is recognised by `install.json` (only in the fixed folder), a portable one by `payload.json`; anything else stops. No program of the folder may run (a game Steam started through `rerun-launch.exe` included; a process of Rerun's names whose path cannot be read counts as running). Then `rerun.exe uninstall-check` (only if `rerun.exe` has the manifest's hash): **exit 5 stops with the list and removes nothing** (undo in Rerun, or forget); with `-KeepData` the open changes stay recorded in the kept data folder for the next install (the update path). Any other result, os error 4551 included, stops: Rerun cannot check.
6. **Uninstall removes everything by default** (revised U5/U6): preview of the uninstall check's warnings (games Steam may still start through `rerun-launch.exe`, with the advice to remove the option in Steam; Rerun never edits Steam), the program files that go (only those with the manifest's SHA-256; changed or foreign files stay and are named, and then the folder stays), the shortcut (only if it points to this folder's `rerun-app.exe`), and the data folder `<LocalAppData>\Rerun` with its size and top-level entries; one Enter. `-KeepData` keeps the data folder. The data folder is walked without following links first; a reparse point anywhere in it stops the uninstall with nothing removed (or `-KeepData`), and the removal checks each entry again and never recurses through a link. Never outside these paths, never Steam, a game folder, the registry or another account.
7. **Update = `uninstall.ps1 -KeepData`, then `install.ps1` of the new payload.** The path stays, so launch options keep working; the journal, profiles and index stay. A swap-in-place update with process check and rollback, and the "Apps & Features" entry, come with the A6 installer form.
8. **Version `0.1.0-alpha.N`** in `Cargo.toml` (U9 a): it is in "About", the build ID and the user agent. The build ID is the commit (`-dirty` only for a test payload).
9. **The index and the key (U3 b).** The alpha is the later release build without code signing: the real `release` profile, its own `index` folder, the release key slots. The Ed25519 release key is generated offline by the developer (`rerun-workbench key generate`, on an NTFS stick, BitLocker To Go if possible, a second copy) and is the A6 key; only the developer signs (`alpha-build.ps1 -Key`), never an agent. Until P5-13a fills `RELEASE_KEYS` the script refuses `-Key` and only a `-NoIndex` test payload can be built.

## Alternatives
- **Everything per machine in `Program Files\Rerun`:** every install, update and uninstall needs administrator rights, and the DEV helper scripts treat that folder as foreign.
- **An own Rust installer (`rerun-setup.exe`):** another unsigned exe SAC may block, `IShellLinkW` as a new COM class, self-deletion only with tricks; too much new `unsafe` and review for an alpha.
- **WiX/MSI or Inno Setup:** a foreign tool chain in the build and an unsigned installer exe or MSI; candidates for A6.
- **MSIX:** must be signed and installs to a versioned path (breaks the launch options at every update) with AppData virtualisation that separates `rerun-launch` from `<LocalAppData>\Rerun\profiles`.
- **The uninstaller undoes open changes itself:** would need its own preview per transaction, a second copy of what the app already does with a preview.
- **The data folder always stays:** leaves journal, backups and packages behind after "uninstall"; the user decided "everything goes" with `-KeepData` as the exception.

## Consequences
- The scripts are the reviewed specification of the A6 installer form; `uninstall-check` and the manifests stay whatever the form.
- Running user-writable scripts is accepted for the alpha (same user, no elevation, built locally from `dist`); `-ExecutionPolicy Bypass` is needed on the command line. A6 signs the scripts or replaces them.
- A same-user process can swap a file in the install folder; it runs as the same user (docs/06 #17), and every exe restricts its DLL search (ADR 0008).
- Launch option detection is fuzzy (a launch result shows only the last start); hence a warning, never a blocker. Exact with ADR 0028 (phase 6).
- Smart App Control is checked only when the scripts start a program; a later block of `rerun-launch.exe` makes games with the option fail to start until the option is removed (README).

## Open points
- Sandbox tests of the scripts ([SB] I1 to I10 of plan P5-13) are not automated yet: the scripts wait for Enter; a test mode or a sandbox pass is to be added (docs/09).
- The [DEV] acceptance (`scripts/dev-alpha-check.ps1`, P5-13h) and the alpha next to the DEV scripts (P5-13g, U8 a) are separate slices.
- A6: the installer form, code signing of exes and scripts (does SignPath sign PowerShell in the Foundation programme?), "Apps & Features", a swap-in-place update, `HELPER_MIN_SEQ` equal to the shipped index's `seq`.

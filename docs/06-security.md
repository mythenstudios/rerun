# 06 · Threat model

## What we protect

The user's system (files outside the game folder, registry, firewall, autostart) and the trust that Rerun only does what the preview shows.

## Attackers and scenarios

| # | Scenario | Countermeasure |
|---|---|---|
| 1 | Malicious Topo in the community repo | Purely declarative format, no execute primitive, launch options only as game arguments after `%command%`, INI values without line breaks/paths (`ini_set`, P2-12: names `[A-Za-z0-9_. -]`, values printable ASCII without `\ / : % ; # [ ]` and `..`, only existing `.ini` files of the game folder, never `desktop.ini`; the rule is syntactic only: whether a value is sensible for a game, such as a resolution or a path-free switch, is curation and review of every Topo key, never the parser's job), download URLs bound to the original source, schema validation, review via PR, signed index; `launch.start` and `launch.priority` (P3-3) are safe today: `start` is a relative `.exe` below plain folders of the game root (`RelPath`, stored spelling, no link, nothing case-sensitive), only a key the shim compares with Steam's `argv[0]`, and the shim always starts Steam's own command, never `start`; `priority` is `normal`, `above_normal` or `high`, never realtime |
| 2 | Compromised GitHub repo / index replaced, damaged, truncated or an old index replayed (also a crafted `index.json` the user is talked into importing) | ADR 0024: one bundle, Ed25519 signature over its raw bytes checked before any parsing (at most 8 MiB, a signature of exactly 64 bytes); key generated and kept offline (`rerun-workbench key generate` refuses any Git working tree), two public-key slots in the binary for rotation, no key = every index refused; retired keys (after a rotation) only for reading back the index of a revert, revoked (compromised) keys refused everywhere, also on that path; the private key file gets an owner-only protected DACL and is never written into a Git working tree or a OneDrive folder; the published test key trusted only with the dev-only feature `test-key` (`compile_error!` without debug assertions, unit test, CI `cargo tree` check, release binary checked for its bytes); `ed25519-compact` pinned exactly. After the signature: `deny_unknown_fields`, `RelPath`, typed hashes, no draft and no `TODO` in a released entry, every referenced package present. Monotonic `seq`: a lower one and the same number with other bytes are refused (`<AppDir>\index\current.json`); every accepted index kept by its SHA-256 and read back with its signature checked again, so a revert uses the index it was applied with, never the current one (condition R1). The floor stops a replay from outside, not a process of the user rewriting the pointer (#14: that process can change anything below `<AppDir>`; the signature still binds every entry) |
| 3 | Upstream release replaced | Pinned SHA256 in the package, check before extraction |
| 4 | Path escape (`..`, absolute paths, junctions, ADS, UNC, `CON`, Unicode lookalikes) | `RelPath` and `RootPath` lexically strict; all file operations relative to a root handle opened by `policy::root`, never follow junctions or symlinks below the root, forbidden roots from known folders, never environment variables (Windows, Program Files itself, profile roots, other users' profiles, per-volume system folders; a root may neither lie in nor contain a protected folder; the list fails closed), no network or volume roots, a game folder from a store is opened handle-relative so a junction at game level is an anomaly, root identity re-checked before every apply and revert, hard links never changed in place, invalid names on disk reported and never touched (ADR 0007) |
| 5 | Zip Slip during extraction | Check every entry individually, never extract blindly |
| 6 | Registry abuse | `policy::registry` (ADR 0018) before `sys`: `HKCU` only in phases 2 and 3 (`HKLM` needs the phase 4 helper; phase 3 only reads the `HKLM` layer value, ADR 0018 amendment P3-6), native view only, never from an elevated process (`sys` refuses both, fail closed; with UAC off an administrator is always refused, and Rerun must say so clearly), fixed slots (`AppCompatFlags\Layers` with a token allowlist (P2-11, ADR 0018 amendment P2-11b: each token as the compatibility tab writes it, and admitted only after SB-L6 saw it start a 32-bit and a 64-bit image without elevation in a non-elevated session, since the elevation rule sees only the name `RUNAS…`; never `REGISTERAPPRESTART`, core rule 1, and no operating-system mode: `WINXPSP3` makes a 32-bit image need elevation; the list with its sources in `docs/05-sources-policy.md`): the value is never set, only allowlisted tokens are appended by `policy::registry` (`RegWriter::add_tokens`, which forms the value) and removed again (`remove_tokens`), every other token kept, a value outside the strict grammar or above 1 KiB left alone, a token of the same group as one already there refused, `RUNASADMIN` or another elevation token (`RUNAS…`) is never added by an apply, a revert restores the previous value exactly, or removes only Rerun's tokens if someone changed the value since; accepted deviation from rule 2: the shared keys `AppCompatFlags` and `Layers` can stay behind empty when two games' transactions below them are reverted oldest first (ADR 0020 amendment P2-11); game keys under `Software\<Vendor>\<Product>` in printable ASCII with a vendor deny list, folded, `Khronos` included; value names and `REG_SZ` data in printable ASCII only (no best-fit characters such as U+FF3C that an ANSI reader turns into `\`, no bidi or format characters) and without `\ / : %`, G1: no paths and no environment variables, which blocks plugin and start-path vectors such as `Khronos\Vulkan\ImplicitLayers` or a native-messaging manifest generically; `UserGpuPreferences` reserved for phase 4), allowed types and size limits for new values (`REG_DWORD`, `REG_QWORD`, `REG_SZ`; no `REG_BINARY` until a reviewed Topo needs it); what these rules cannot catch (a DWORD switch of another program, a command line without those characters such as PuTTY's `ProxyTelnetCommand`) is left to the review of every Topo key and to the preview, and the rules guard the phase 4 Topos and are never loosened for one; the write methods reachable only through `policy::registry` (`clippy.toml` bans); every key opened segment by segment relative to its parent with `REG_OPTION_OPEN_LINK`, a link key refused, a volatile key refused, the handle's kernel name checked before a write and again after it, the expected old value compared on that handle; accepted: a rename by another program of the same user in the microseconds between the check and the write makes the write follow the handle into the moved key (no compare-and-swap; the second check reports `Busy`, the caller observes); the previous value recorded exactly in the journal before the write, the key flushed before the closing record, the location checked again on revert; a plan with registry ops is refused in an elevated process before the first record, by an apply and by a revert (P2-10b); the preview shows every key and value, old and new, and says once that a game filling a created key or changing a value later (also with another type) is left as it is and closed with `forget` (P2-10b); old string data up to 1 KiB of a replaced value is shown escaped, an exception to the output rules recorded in ADR 0016 (P2-10b, review S2: a Topo must not replace a value that may hold a secret) |
| 7 | TOCTOU between preview and elevation | The plan hash only catches accidents; the boundary is the helper's own re-validation: it treats the plan as untrusted, only writes into roots that only admins can write and that contain the topo's target exe with the signed hash, verifies index signature and package hashes itself, and opens its root by volume GUID path + file ID; root identity (volume serial + file ID) is checked on every apply and revert (ADR 0007). Helper process hardening: ADR 0008. DLL planting next to a Rerun executable (a user-writable install folder): every shipped executable is linked with `/DEPENDENTLOADFLAG:0x800` (static imports from System32 only) and restricts its DLL search path to System32 as the first statement of `main`, failing closed; tests check the built PE (ADR 0008 amendment 2026-11-05). **Phase 4 helper as built (P4-2c, ADR 0023 §5):** the helper reads nothing by path: the request file and the `index` folder are opened by `{volume GUID, file ID}` with fixed names (a junction planted at `elevate` or `Rerun` after the CLI wrote the request changes nothing, and a volume GUID never names a share), the request hash must equal the argument and its build ID the helper's; an add is re-derived from the signed index read by hash (`trusted_keys`, the revocation list, `HELPER_MIN_SEQ`; never `current.json`), the Topo and picks without `when`, the root opened by identity against the helper's own forbidden list (another account's profile under over-the-shoulder elevation is refused), each program's SHA-256 taken on the helper's own handle, the anti-cheat check repeated; the request's ops must be exactly the derived ones. The CLI runs the same derivation non-elevated (`elevate::check_plan`, A4 S7). Tested as a two-process fake with a refusal per step and the tamper cases (docs/09) |
| 8 | Wrong exe targeted (same name) | Identification via path + hash; IFEO with `FilterFullPath` |
| 9 | Revert deletes foreign/modified files | A revert acts only on roots that reopen with their identity: a root that is gone (its path not found, also a Steam library or an installed app's folder; a folder that changes while it is opened counts as busy, not gone) halts the revert at its newest file op without a record (the transaction stays open, P2-10a); one whose state is undecided (an update pending, another folder at its path, a reinstall until a rebind) refuses before any change; accepted rest risk: D4 does not ask a root that is gone, so a game moved elsewhere and still running may read a registry value its revert resets meanwhile (no data loss, the revert is exact at that moment); a named main executable must be a plain file of its root when planned and applied (a typo or a link would leave D4 asking nothing); the hash check and the delete or replace happen on one handle that shares read only (`FileGuard`, ADR 0017), a different hash is `Mismatch` and nothing is touched; a foreign state is never overwritten or deleted, no question is asked: the op stays unresolved, its backup stays in the journal, `status` shows where, and only an explicit `forget` closes it (user decision D10, ADR 0020); hard-linked targets (mod managers) are never replaced or deleted (D1); apply and revert only with the game closed (`users()`, D4, asked again on the guard before a replace and before a restore); a revert that meets a foreign op records it `Foreign`, leaves it and still reverts the ops below it (P2-8, user decision D3), so the transaction stays open until `forget`; `exec::verify` is the read-only preview before a revert; rebind (P2-14, user decisions E-R1 to E-R6): a Steam folder that is gone or another folder now can be bound to the head's install folder in a Steam library only after a preview the user confirms (the binding shown is derived again under the lock, any difference refuses before the record); never a manual root, never more than one root at a time, never once the revert of a file op of that root began; the folder must open through `policy::root` and be writable, the game closed there, and no op of the root `Foreign` there (`Drifted` allowed: games rewrite their INI files); registry ops stay at the head's locations, so a `Layers` value under the old executable path is the one restored and one under the new path is never touched. `Reverted` after a rebind means the bound folder is exactly as before the apply (the copy Steam made), not every copy: a renamed old folder (`Game.bak`) is not recognised and stays as it is. What Steam keeps when it moves a library (R/H/S, case, temp names) is not measured; any difference is `Foreign` and refuses the rebind (fail closed, then `forget`); a rebind never binds a root to the folder of another root of the same transaction or to a folder inside or around one (apps that share an install folder name, P2-14 review S1); P2-14b: the folder only from the Steam scan (the head's app ID and install folder, exactly one library holding the app), every library Steam lists readable (an unplugged drive refuses, the old library too), a registry candidate before the chosen Steam root with any problem and another Steam folder refuse (no old copy of Steam is used), the confirmation only at a console (`--rebind --yes` is refused); rest risk: a library removed from Steam while its drive was away is no longer listed, so a rebind to a copy elsewhere closes the transaction and Rerun's files on that drive stay untracked, like a renamed old folder; pending cleanup (P2-15, user decisions E-C1 to E-C4): `Closed { Reverted | RolledBack }` means Rerun's changes are exactly undone and nothing of Rerun's is left, so a `.old` a process still maps keeps the transaction open (`status`: cleanup pending; applies on its objects and earlier reverts on them are refused with what to do); only an explicit `rerun revert` of the same transaction deletes it, with its known hash expected, only while the target holds the reverted state (else it is kept as the last copy of a state), after D4, its preview and its question; never an apply, another transaction's revert, the background or a reboot; a foreign content, link, folder or reparse point at that name is never touched, only reported (it is not one of Rerun's changes) Exceptions to an exact revert that belong to this row (foreign `.old` names, rebind, `forget`) are listed in ADR 0020, table "Exceptions to core rule 2" (rows X2, X9, X11). |
| 10 | Crash or power loss in the middle of apply | Write-ahead journal (ADR 0019): backup read back and hashed, then the intent record, then the change; every file, folder and registry key flushed before the closing record, and the op's game folder before every `RevertDone` (P2-8: otherwise a power loss could keep the record and lose the change, or the undo of a failed write sequence, on the game's volume); with a restore, the old content's `.old` goes only after the restore succeeded; recovery observes each op on disk (the intermediate states of a replace, ADR 0017) and never trusts a record alone; an in-process failure rolls back at once (from the results of its own calls: a name found taken is foreign, never removed); recovery runs only on an explicit command, with a preview. Accepted rest risk (P2-8, user decision D1): after a crash between a `CreateDir` intent and its `Done`, recovery removes an empty directory of that name by the file ID it finds, which may be an empty directory someone else created in that window; the same for a `CreateKey` intent (P2-10, user decision 6a): recovery deletes an empty key at that path, a key with values or subkeys is foreign and stays, and since Windows flushes a hive lazily the window is not only microseconds (pinned by test R-T6); a key that exists when `create_key` runs (`false`) is not deleted by the rollback of that run (R-T3), and a value another program wrote just before Rerun's own write (`NotWritten`) is not overwritten by it; rest risk of the same class: a crash between such a result and the rollback's `RevertDone` leaves an intent without `Done`, and the recovery then deletes the key if it is still empty, or restores the old value over a foreign write of exactly the new value (review nit 5). `HKCU` is flushed before `Applied` and before the `RevertDone` of every registry op (P2-10b, J6 with 8 flush sites). A compatibility-layer value someone changed since the apply is reverted semantically (P2-11): Rerun's tokens are removed from the value observed, through `policy::registry`, without a digest in the journal (user decision E8); a crash or power loss after that write leaves a value without Rerun's tokens, which the next run observes as `Before` or `Drifted` and never as `Foreign` (R-L4, R-L5); a revert in another order than newest first can leave the shared keys `AppCompatFlags` and `Layers` empty for good (accepted, ADR 0020 amendment P2-11). Rest risk of the same class (audit A3 nit): the limit "only keys Rerun created" (ADR 0018) does not cover these shared keys, which the compatibility tab and PCA write to as well; a value written between the emptiness check (`counts()`) and `NtDeleteKey` is deleted with the key (the window is tiny; no test can pin a race with another process). The exceptions of this row are listed with their tests in ADR 0020, table "Exceptions to core rule 2" (rows X3 to X8, X10). An INI file the game rewrote since the apply is reverted semantically (P2-12, ADR 0020 amendment P2-12): the content observed and the content written (`policy::ini::unedit`) are recorded as `from`/`to` in the `RevertIntent` before the first change, so the replace sequence of the rewrite has known states and every `.old` is deleted or renamed back only with its expected hash (ADR 0017 and ADR 0019 amendments P2-12); a crash or power loss in any phase of the apply or the rewrite ends in the old file, the rewritten file or `Drifted`, never in a lost INI file and never `Foreign` (R-I4, R-I5); a leftover `X.old` of the apply next to a file the game wrote is deleted only with `Done` recorded and `X` gone (senior-dev M1: after a power loss that kept `Done` but sent `D:` back to phase B, the game may have made a new file, and `X.old` is then the user's only copy); kept, the report names it (S6); the deletions of a pending cleanup (P2-15) are flushed before `Closed` (the tenth flush site, also when every `.old` was already gone, so a deletion of a crashed run never stays undurable under a durable `Closed`), and a lost `RevertDone` with a durable deletion is observed again (`Before`) |
| 11 | Rerun itself perceived as malware | Code signing, no injection, IFEO opt-in only, transparent preview. Until `rerun-helper.exe` is signed, its UAC prompt ("unknown publisher") cannot be told apart from a malware prompt of the same name; no release ships an unsigned helper (ADR 0023, audit A4 S12, checked at A6) |

at most 256 listed libraries, de-duplicated by root identity; `steamapps` opened relative to the library (a junction there is refused, never followed); manifests only as plain files (no directory, reparse point or restricted entry is opened), at most 16,384 per library counted before any manifest is read, so neither the manifest reads nor the issue list grow without bound; untrusted text is `RawText` (no `Display`, `Debug` shows only the length), issues never carry file or registry content beyond paths and names the user must see (the plan preview's old registry values are a separate, bounded exception, ADR 0016 amendment P2-10b), raw ones escaped; the scan never fails as a whole, so one forged or offline library hides nothing else. **Read, and nothing else:** `HKCU\Software\Valve\Steam` `SteamPath`, `HKLM\SOFTWARE\Valve\Steam` `InstallPath` in the 32-bit view (`WOW6432Node`) and in the native view; of the Steam root `steamapps\libraryfolders.vdf`, or `config\libraryfolders.vdf` if the first is missing; of each library the listing of `steamapps` (every entry opened attribute-only, the reparse data of links read) and its `appmanifest_<id>.acf` files; on `open_game` the folders `steamapps\common` and `steamapps\common\<installdir>` (opened, metadata of the game entry); `Dir::info` of every opened root (each registry candidate, each library), of `steamapps`, and in `StoreDir::game` of the store root, `steamapps\common` and the game folder. Errors of the system layer never carry a raw name unescaped (`sys::fs`, error targets). Every untrusted field reaches CLI output only through `rerun_core::escape` (principle "Untrusted display text"); `rerun scan` never opens an app Steam reports as `UpdatePending` or `NotInstalled` (a read-only open shares read only and would block the update). | 14 | Journal, backups or stored plans tampered with by any process of the same user (`<LocalAppData>\Rerun` is user-writable: records edited, deleted or planted, a backup swapped, a junction planted at `Rerun` or `journal`) | The journal is untrusted input (ADR 0019): bounded reads before parsing, `deny_unknown_fields`, `format` checked, numbering without gaps, one written form per record and a grammar shared with the writer, else the transaction is `Damaged` and never acted on automatically (ADR 0019 amendment, P2-7: a damaged transaction whose head is readable and hash-consistent counts as open with its objects; one whose head is unusable blocks every apply until it is forgotten; a valid prefix that ends in `Closed` with anything planted after it counts as closed with an anomaly); `AppDir` opened handle-relative below `LocalAppData`, reparse points refused; paths parsed again as `RelPath`, roots reopened through `policy::root` and checked by identity, registry locations checked again by `policy::registry`; a backup used only if its hash equals its intent; a stored plan applied only if its bytes hash to the `PlanHash` the preview showed, then re-validated. `exec` re-checks a parsed head against its records (temp names and backups by op kind, a backup equal to the replaced file's old state) and refuses a mismatch; a damaged or unreadable transaction blocks every apply and every earlier revert until `forget` writes `journal\<txn>.forgotten` (P2-8, user decision D2): planting such a marker is forgetting, no new capability. An `IniValue` head is bound to its backup before every revert and `verify` (P2-12, `exec::ini::binds`): the backup, hashed against its intent, edited with the head's edits must give exactly the head's new content, else `Blocked`, nothing written; so a tampered head cannot make the revert of a drifted file write other old values than the backup proves. The binding does not cover the path (a head may name another `.ini` file of the same root with the same content; it is still confined by `policy::root` and `ini::path_ok`, and the revert there writes only what `unedit` of that file gives: the class of same-user tampering, ADR 0019). A revert in another order than newest first can leave the shared keys `AppCompatFlags` and `Layers` empty (accepted, ADR 0020 amendment P2-11). The elevated helper never reads the journal (phase 3). Accepted: same-user malware gains nothing it did not have. A planted `Rebind` record (P2-14) names no game path, only a Steam library and identities: the app ID and the install folder always come from the head, and `exec` checks every rebind on every run (a root index of the head, a Steam root, the chain of identities, a change of binding, directory proofs only for `CreateDir` ops of that root, no revert intent of that root before it), else `Blocked`. A forged head gains no power to delete a game file beyond what a forged package op with the file's hash has already (the same-user class, ADR 0019); in `profiles` it can only make the revert delete or restore a profile whose hash it names, the same user's own state. A head naming another `profiles` path is reverted at the current one, decided by hashes only (A1). The planner (P3-3c) reads an existing profile only through `AppDir::profiles_read` (read side, handle-relative, a reparse point refused, at most 8 KiB, one link); its hash goes into `ReplaceFile.old` and is checked again under the guard at apply |

## Principles

- The GUI never runs elevated. Admin only in the helper, per apply, with a validated plan.
- Network only to the Topo index and package hosts from `packages/`. No telemetry.
- `unsafe` minimal, commented, encapsulated in `sys::win`, `rerun-launch` and `rerun-cpu`.
- Dependencies checked with `cargo deny` (licenses, advisories, crates.io only, no OpenSSL) in CI.
- **Policy boundary (ADR 0004):** `sys` executes, `policy` decides. Confinement (`policy::path::RelPath`, `policy::root`) and the registry allowlist (`policy::registry` from phase 2, ADR 0018) sit above `sys` and apply equally to the fake, the real system and the elevated helper.
- **No system access bypassing `sys`:** `clippy.toml` blocks `std::fs` write operations and `std::process::Command::new` (`disallowed_methods = deny`). Exceptions only with `#[allow(…, reason = "…")]` in `sys::win` and `rerun-launch`.
- **No path-based Win32 file APIs:** `clippy.toml` also blocks `CreateFileW`, `DeleteFileW`, `MoveFileExW`, `ReplaceFileW`, `CopyFile*`, `GetFileAttributesW`, `GetNamedSecurityInfoW`, `DefineDosDeviceW` and the other path-based file APIs of `windows-sys`, plus `NtOpenFile`. `NtCreateFile` is fenced to the two wrappers `sys::win::nt::{open_relative, open_absolute_dir}`, which fix the flags (`OBJ_DONT_REPARSE` and `FILE_OPEN_REPARSE_POINT` for every relative open, `FILE_OPEN` only, never `FILE_OPEN_FOR_BACKUP_INTENT`); ADR 0007, amendment "sys::win read side".
- **Registry only through `sys::win::reg`** (ADR 0009): `clippy.toml` blocks every other advapi32, ntdll and shlwapi registry call (writes, legacy and ANSI variants, reads that fix up or expand values, hive loading, predefined-key overrides, transactions, `NtOpenKey*` and the other bypasses), DACL writes by handle (`SetSecurityInfo`, `SetKernelObjectSecurity`, `NtSetSecurityObject`), and every environment-based path source including `GetTempPath*`. `sys/win/bans.rs` makes each `windows-sys` entry fail clippy if it does not resolve.
- **COM** (ADR 0008 amendment P4-5a): in-process only (`CLSCTX_INPROC_SERVER`), one activation call site (`sys::win::com`), behind the A4 S10 environment check; interfaces as owned references, `BSTR` and `VARIANT` only through owning guards; the firewall binding types getters only.
- **DLL loading** (ADR 0008 amendment 2026-11-05): the static imports of every shipped executable are an exact, tested allowlist per binary (`LAUNCH_IMPORTS` for `rerun-launch.exe`, `CLI_IMPORTS` for `rerun.exe`; no graphics DLL, no dynamic CRT in either), no delay-load imports, no hand-written `extern` block, `#[link]` or `raw-dylib` anywhere (source rule test); dynamic loads only through `sys::win::loader` (System32, bare name); `LoadLibrary*`, `GetProcAddress` and every DLL search path call (`SetDefaultDllDirectories`, `SetDllDirectory*`, `AddDllDirectory`, `RemoveDllDirectory`) are `clippy.toml` bans outside it. GPU data only through the hand-written DXGI binding `sys::win::dxgi` (the `D3DKMT*` adapter APIs are banned), never in the elevated helper; COM activation (`CoCreateInstance*`, `CoGetClassObject`, `CoGetObject`, `CoInitialize*`) is banned until phase 3 gives it one wrapper (the shim's `CoInitializeEx` around its one `ShellExecuteExW` call is a reviewed exception, ADR 0008 amendment P3-1b) with `CLSCTX_INPROC_SERVER` only.
- **System profile** (ADR 0015, `rerun-core::hw`): read-only and in-process. The OS build comes only from `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion` `CurrentBuildNumber` (native view, `Registry::get`), an admin-writable value treated as untrusted: a strict `REG_SZ` of ASCII digits, anything else `Malformed`, errors never echo the value; `UBR` is display only. The version APIs (`GetVersion*`, `VerifyVersionInfo*`, `VerSetConditionMask`, `RtlGetVersion`, `RtlVerifyVersionInfo`) are `clippy.toml` bans. Adapter names and PCI IDs come from the driver and are untrusted: the profile keeps them raw (`GpuAdapter`), maps only `(vendor, device)` through the architecture table and never consults revision or subsystem IDs. The GPU architecture table (`data/gpu-arch.yaml`, a compiled-in mirror until the phase 4 index) is declarative data checked by `GpuArchTable::new` before use: at most 256 architectures, 4,096 entries, 1,024 IDs plus ranges per entry and 3 × 65,536 in the whole table (checked before the lookup index is allocated), a Vulkan minor of at most 99, IDs within `0..=0xFFFF`, AMD/NVIDIA/Intel only, declared architectures with a matching vendor, no device covered twice (sorted intervals, ranges never expanded), `source` 1 to 200 characters without control or bidi characters; errors name positions, never content. A Topo is evaluated against exactly the table it was validated with. **The profile never authorises anything:** a `when` condition only chooses which variants are offered; the elevated helper never builds a profile and never evaluates `when`, it checks the plan, not the hardware. A fact that could not be read makes its condition `Unknown`, never preselected or applied automatically.
- **Untrusted display text** (ADR 0016): app names, library labels and paths, install folder and executable names, adapter names, table `source` texts and issue texts are attacker-controlled (any process of the user writes Steam files and game folders, drivers name adapters). Printed raw, escape sequences could rewrite the terminal (cursor moves, forged or hidden lines, window title), and bidi controls and invisible characters could reorder or hide text. Every untrusted field reaches output only as `escape::Shown`, which only the two entry points of `rerun_core::escape` create (one table of code points, Unicode 16): `escape::path` for `RelPath`, `RootPath` and `SysError` targets (`sys::error::shown_target` delegates to it): control, format and default-ignorable characters (tags, variation selectors), U+2028/U+2029, supplementary private use, noncharacters, plus the confusables of `is_deceptive`; `escape::text` for names, labels and messages: the same without the printable confusables. A string holding such a character is shown whole as `{:?}` with each as `\u{x}`, clean text unchanged. A last-resort net checks every output line against the whole base set of `escape::text` (not only control characters): in tests a hit panics, so it never hides a missing field escape; in a build the hit line is written escaped as a whole. Static text is ASCII, no colours. Executable version strings are not shown in phase 1. The phase 5 app additionally isolates untrusted text (`<bdi>`, `dir="auto"`), because strong right-to-left letters are no control characters.
- **CLI** (ADR 0016, ADR 0020): `system`, `scan`, `plan` and `status` write no game folder or registry key and take no lock (`plan` without `--dry-run` stores the plan under `<LocalAppData>\Rerun\plans`, creating Rerun's folder only right before it stores; `plan --dry-run` creates nothing; an elevated `plan`, or one whose elevation cannot be determined, is refused, user decision E3 of P2-13); `apply`, `revert` and `forget` hold the journal lock (`journal\lock`, share 0) for their whole run, so two of them never interleave; `index import` (ADR 0024) writes only below `<LocalAppData>\Rerun\index`, holds `index\lock` while it does, creates Rerun's folder only for an index whose signature and form passed, and is refused elevated; `index show` writes nothing, takes no lock and, like `status`, also runs elevated (it only reads `<LocalAppData>\Rerun\index` and checks it as an import would); `apply --dry-run` (`exec::check`), `revert --dry-run` and the preview of `forget` (`exec::verify`) hold an existing lock file read side while they observe, never creating it, so they write nothing and no writer can start meanwhile. `status`, `revert` and `forget` show a transaction's head without registry data (old values, and the new value of an `add tokens` op, by type, length and SHA-256 only; review S3 of P2-13); `forget` names every backup and every `.old` it leaves before it asks. Elevated (or undeterminable), only `system`, `scan` and `status` run; `exec` itself refuses every write of an elevated process, whatever the plan (P2-13, user decision E3). `apply`, `revert` and `forget` show their preview first (`apply` from the stored bytes) and ask only when stdin and stdout are consoles, else `--yes` is required; a preview that cannot be written (closed pipe) changes nothing. Right before a question the console's pending input is discarded (`FlushConsoleInputBuffer`, no mode change), so typed-ahead or pasted keystrokes never answer it; a revert runs every check (`exec::revert_check`) before its preview and question. Usage errors are Rerun's own lines with the user's value through `escape::text` (clap's rendering would repeat the arguments raw). `--help` and `--version` end before any registry or file system access. The console is left as found: no `SetConsoleMode`, no `SetConsoleOutputCP` (shared with the parent shell, outliving the process); clap is built without `color` (which would call `SetConsoleMode` and read colour variables), checked in CI. `rerun scan` resolves `ForbiddenRoots` from its own install folder, fail closed: on a network drive it exits 1. `--hashes` is opt-in with a warning. Run elevated with another administrator account, `HKCU` and the known folders are that account's, so Steam is "not found" for the interactive user.
- **CI supply chain:** GitHub Actions pinned by commit SHA, `permissions: contents: read`, toolchain pinned in `rust-toolchain.toml`, `Cargo.lock` committed and `--locked`.

## Allowed registry areas

Phase 2 (`policy::registry`, ADR 0018; `HKCU`, native view, non-elevated only):
- `HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers`: value name = canonical path of an executable inside a game root (the root's path and a relative path, M2), `REG_SZ`; Rerun adds and removes only allowlisted tokens and keeps every other token; `RUNASADMIN`, `RUNASHIGHEST` or another elevation token (`RUNAS…`) is never added by an apply, a revert restores the previous value exactly, or, if the value changed since, removes only the tokens Rerun added (P2-11). No value is set: `policy::registry` appends tokens of the add allowlist (`LAYER_TOKENS`, the table with sources in `docs/05-sources-policy.md`, "Reference data"; never `RUNAS…`, ADR 0018 S6, never `REGISTERAPPRESTART`, core rule 1: Windows would restart the program by itself, never an operating-system mode in phase 2: `WINXPSP3` makes a 32-bit image need elevation in a non-elevated session, a UAC prompt at every start, SB-L3; a token is admitted only after SB-L6 saw it launch without elevation, P2-11b) to the old value and forms the new one itself; a value outside the strict grammar (printable ASCII words, one space between them) or above 1 KiB is left alone; a token of the same group as one already in the value (another operating-system mode, DPI, colour or resolution setting) is refused. The keys `AppCompatFlags` and `Layers` are shared with Windows: created by Rerun, a revert deletes them only when empty and otherwise leaves them (user decision E6). A game folder reached through a link or another spelling than its canonical path is refused (E3, final: Windows applies a layer only to the path a program is started by, SB-L2); an old value with a prefix joined to a word (`~X`) or after a word is refused as unusual (P2-11b).
- `HKCU\Software\<Vendor>\<Product>[\…]` (at most 4 further segments): game-specific keys named in the step (later the Topo) and approved in review; key segments and value names printable ASCII; `<Vendor>` not `Microsoft`, `Classes`, `Policies`, `Wow6432Node`, `Clients`, `RegisteredApplications`, `AppDataLow`, `Valve`, `Rerun`, `Mythen Studios`, `Khronos` (folded); value names and `REG_SZ` data without `\ / : %` (G1); new values `REG_DWORD`, `REG_QWORD` or `REG_SZ` (printable ASCII only, at most 1,024 characters), never `REG_BINARY` (until a reviewed Topo needs it), `REG_EXPAND_SZ`, `REG_MULTI_SZ` or `REG_LINK`. The deny list and the content rule are a backstop; the review of every Topo key and the preview stay the defence (user decision G1, ADR 0018).

Reserved, refused until their phase:
- `HKCU\Software\Microsoft\DirectX\UserGpuPreferences` (value name = canonical path of a detected game exe; `gpu_preference`, phase 4, `03b-gpu-display.md`).
- `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\<exe>` (only `Debugger`, `UseFilter`, filter subkeys, for the `ifeo` method; elevated helper, phase 6). No `PerfOptions`: the priority class is a field of the launch profile, set by `rerun-launch` without admin (user decision D6 a).

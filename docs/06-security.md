# 06 · Threat model

## What we protect

The user's system (files outside the game folder, registry, firewall, autostart) and the trust that Rerun only does what the preview shows.

## Attackers and scenarios

| # | Scenario | Countermeasure |
|---|---|---|
| 1 | Malicious Topo in the community repo | Purely declarative format, no execute primitive, launch options only as game arguments after `%command%`, INI values without line breaks/paths, download URLs bound to the original source, schema validation, review via PR, signed index |
| 2 | Compromised GitHub repo / index replaced | Ed25519 signature, key offline, public key in the binary |
| 3 | Upstream release replaced | Pinned SHA256 in the package, check before extraction |
| 4 | Path escape (`..`, absolute paths, junctions, ADS, UNC, `CON`, Unicode lookalikes) | `RelPath` and `RootPath` lexically strict; all file operations relative to a root handle opened by `policy::root`, never follow junctions or symlinks below the root, forbidden roots from known folders, never environment variables (Windows, Program Files itself, profile roots, other users' profiles, per-volume system folders; a root may neither lie in nor contain a protected folder; the list fails closed), no network or volume roots, a game folder from a store is opened handle-relative so a junction at game level is an anomaly, root identity re-checked before every apply and revert, hard links never changed in place, invalid names on disk reported and never touched (ADR 0007) |
| 5 | Zip Slip during extraction | Check every entry individually, never extract blindly |
| 6 | Registry abuse | `policy::registry` (ADR 0018) before `sys`: `HKCU` only in phase 2 (`HKLM` needs the phase 3 helper), native view only, never from an elevated process (`sys` refuses both, fail closed; with UAC off an administrator is always refused, and Rerun must say so clearly), fixed slots (`AppCompatFlags\Layers` with a token allowlist: `RUNASADMIN` or another elevation token is never added by an apply, a revert restores the previous value exactly; game keys under `Software\<Vendor>\<Product>` in printable ASCII with a vendor deny list, folded, `Khronos` included; value names and `REG_SZ` data in printable ASCII only (no best-fit characters such as U+FF3C that an ANSI reader turns into `\`, no bidi or format characters) and without `\ / : %`, G1: no paths and no environment variables, which blocks plugin and start-path vectors such as `Khronos\Vulkan\ImplicitLayers` or a native-messaging manifest generically; `UserGpuPreferences` reserved for phase 4), allowed types and size limits for new values (`REG_DWORD`, `REG_QWORD`, `REG_SZ`; no `REG_BINARY` until a reviewed Topo needs it); what these rules cannot catch (a DWORD switch of another program, a command line without those characters such as PuTTY's `ProxyTelnetCommand`) is left to the review of every Topo key and to the preview, and the rules guard the phase 4 Topos and are never loosened for one; the write methods reachable only through `policy::registry` (`clippy.toml` bans); every key opened segment by segment relative to its parent with `REG_OPTION_OPEN_LINK`, a link key refused, a volatile key refused, the handle's kernel name checked before a write and again after it, the expected old value compared on that handle; accepted: a rename by another program of the same user in the microseconds between the check and the write makes the write follow the handle into the moved key (no compare-and-swap; the second check reports `Busy`, the caller observes); the previous value recorded exactly in the journal before the write, the key flushed before the closing record, the location checked again on revert |
| 7 | TOCTOU between preview and elevation | The plan hash only catches accidents; the boundary is the helper's own re-validation: it treats the plan as untrusted, only writes into roots that only admins can write and that contain the topo's target exe with the signed hash, verifies index signature and package hashes itself, and opens its root by volume GUID path + file ID; root identity (volume serial + file ID) is checked on every apply and revert (ADR 0007). Helper process hardening: ADR 0008. DLL planting next to a Rerun executable (a user-writable install folder): every shipped executable is linked with `/DEPENDENTLOADFLAG:0x800` (static imports from System32 only) and restricts its DLL search path to System32 as the first statement of `main`, failing closed; tests check the built PE (ADR 0008 amendment 2026-11-05) |
| 8 | Wrong exe targeted (same name) | Identification via path + hash; IFEO with `FilterFullPath` |
| 9 | Revert deletes foreign/modified files | A revert acts only on roots that reopen with their identity: a root that is gone (its path not found, also a Steam library or an installed app's folder; a folder that changes while it is opened counts as busy, not gone) halts the revert at its newest file op without a record (the transaction stays open, P2-10a); one whose state is undecided (an update pending, another folder at its path, a reinstall until a rebind) refuses before any change; accepted rest risk: D4 does not ask a root that is gone, so a game moved elsewhere and still running may read a registry value its revert resets meanwhile (no data loss, the revert is exact at that moment); a named main executable must be a plain file of its root when planned and applied (a typo or a link would leave D4 asking nothing); the hash check and the delete or replace happen on one handle that shares read only (`FileGuard`, ADR 0017), a different hash is `Mismatch` and nothing is touched; a foreign state is never overwritten or deleted, no question is asked: the op stays unresolved, its backup stays in the journal, `status` shows where, and only an explicit `forget` closes it (user decision D10, ADR 0020); hard-linked targets (mod managers) are never replaced or deleted (D1); apply and revert only with the game closed (`users()`, D4, asked again on the guard before a replace and before a restore); a revert that meets a foreign op records it `Foreign`, leaves it and still reverts the ops below it (P2-8, user decision D3), so the transaction stays open until `forget`; `exec::verify` is the read-only preview before a revert |
| 10 | Crash or power loss in the middle of apply | Write-ahead journal (ADR 0019): backup read back and hashed, then the intent record, then the change; every file, folder and registry key flushed before the closing record, and the op's game folder before every `RevertDone` (P2-8: otherwise a power loss could keep the record and lose the change, or the undo of a failed write sequence, on the game's volume); with a restore, the old content's `.old` goes only after the restore succeeded; recovery observes each op on disk (the intermediate states of a replace, ADR 0017) and never trusts a record alone; an in-process failure rolls back at once (from the results of its own calls: a name found taken is foreign, never removed); recovery runs only on an explicit command, with a preview. Accepted rest risk (P2-8, user decision D1): after a crash between a `CreateDir` intent and its `Done`, recovery removes an empty directory of that name by the file ID it finds, which may be an empty directory someone else created in that window; the same for a `CreateKey` intent (P2-10, user decision 6a): recovery deletes an empty key at that path, a key with values or subkeys is foreign and stays, and since Windows flushes a hive lazily the window is not only microseconds |
| 11 | Rerun itself perceived as malware | Code signing, no injection, IFEO opt-in only, transparent preview |
| 12 | Manipulated Steam files (`libraryfolders.vdf`, `appmanifest_*.acf` edited or planted by any process of the user: huge or deeply nested files, `#include`/`#base`, odd escapes, forged paths and install folder names) | Bounded parser `detect::vdf` (ADR 0011): only the quoted subset Steam writes, limits for bytes, depth, entries and string length, explicit stack instead of recursion, directives never followed, errors without file content; read handle-relative to the store root with `Dir::read_limited` (at most `max_bytes + 1` bytes read, more refused as `TooLarge`, never truncated), metadata length never trusted; strict typed views (exactly one of each required field, strict `appid`) that extract allowlisted keys only (`LastOwner` and other SteamIDs never, ADR 0016), a malformed library entry fails the whole file; paths and install folder names stay raw and pass `policy::root` (`StoreDir::open`, `StoreDir::game`) before anything is opened. Steam detection (ADR 0012): the registry values (`HKCU` writable by the user, `HKLM` pointing into the same user-writable folder) are read with `Registry::get` only, never expanded (`REG_EXPAND_SZ` with `%` refused), and pass `StoreDir::open` like any path; `HKCU` wins, a disagreeing candidate is reported and never scanned; no fallback from a damaged or locked `steamapps\libraryfolders.vdf` to `config\libraryfolders.vdf` (only on `NotFound`), the two never merged; at most 256 listed libraries, de-duplicated by root identity; `steamapps` opened relative to the library (a junction there is refused, never followed); manifests only as plain files (no directory, reparse point or restricted entry is opened), at most 16,384 per library counted before any manifest is read, so neither the manifest reads nor the issue list grow without bound; the `steamapps` listing itself is bounded (`Dir::read_dir_limited`, 16,384 plus 1,024 entries, counted before any entry is attribute-opened; more and the library has no apps, ADR 0012); `appid` must equal the ID in the file name, `installdir` must be a valid single segment before `StoreDir::game` opens it handle-relative; untrusted text is `RawText` (no `Display`, `Debug` shows only the length), issues never carry file or registry content beyond paths and names the user must see, raw ones escaped; the scan never fails as a whole, so one forged or offline library hides nothing else. **Read, and nothing else:** `HKCU\Software\Valve\Steam` `SteamPath`, `HKLM\SOFTWARE\Valve\Steam` `InstallPath` in the 32-bit view (`WOW6432Node`) and in the native view; of the Steam root `steamapps\libraryfolders.vdf`, or `config\libraryfolders.vdf` if the first is missing; of each library the listing of `steamapps` (every entry opened attribute-only, the reparse data of links read) and its `appmanifest_<id>.acf` files; on `open_game` the folders `steamapps\common` and `steamapps\common\<installdir>` (opened, metadata of the game entry); `Dir::info` of every opened root (each registry candidate, each library), of `steamapps`, and in `StoreDir::game` of the store root, `steamapps\common` and the game folder. Errors of the system layer never carry a raw name unescaped (`sys::fs`, error targets). Every untrusted field reaches CLI output only through `rerun_core::escape` (principle "Untrusted display text"); `rerun scan` never opens an app Steam reports as `UpdatePending` or `NotInstalled` (a read-only open shares read only and would block the update). Accepted limit: opening a library on a disconnected mapped drive can block for the SMB timeout |
| 13 | Manipulated executables in game folders (planted or replaced by any process of the user: huge, truncated, crafted headers, sizes and offsets that point anywhere, old formats) | Bounded parser `detect::pe` (ADR 0013): no memory mapping, no whole-file read; every access is one range read into a buffer sized by a limit, never by a header field alone, charged to a total budget per file (1 MiB) before it happens; header region 64 KiB, at most 96 sections, at most 16 data directories, at most 1,024 DLLs per import table read in one range, DLL names 1 to 255 bytes of printable ASCII (no control, bidi or non-ASCII character can reach an output), no function names, ordinals, exports or forwarders; the version resource only through the `RT_VERSION` branch at fixed depth (three tables of at most 1,024 entries, no tree walk), at most 64 KiB, at most 64 string tables, six kept strings of at most 1,024 UTF-16 units each, kept raw as `RawText` (`Debug` shows only the length) and not shown in phase 1 (only the numbers of the fixed part, ADR 0016); no recursion, no `unsafe`, no system call; DOS, NE and LE/LX recognised and never parsed further; opened only through `open_game_exe`, relative to the `GameDir` handle (no reparse point, restricted entry or online-only placeholder is opened, the length is never asked for, neither from metadata nor by seeking to the end); errors carry a kind and a file offset, never file content. PE facts are hints for display, matching and suggestions, never authorization: a Topo matches an exe by path and hash, the elevated helper by the signed hash. Choosing the files (`detect::exe`, ADR 0014): a breadth-first walk of the game folder only, every directory opened relative to the game handle, at most depth 3, 128 listed directories, 20,000 entries and 64 parsed executables (a partial result is marked incomplete); reparse points and restricted entries are reported, never followed or opened; case-sensitive directories and anomalous names are reported and never used; read per game: the listings, at most 64 × 1 MiB of parser reads, and only with `--hashes` the whole content of at most 8 `Game` executables (at most 2 GiB each plus one 256 KiB chunk, at most 4 GiB per game plus one chunk per hashed file, the chunk clamped to at most 16 MiB), each hashed on the handle it was parsed on after its facts were compared with the first inspection; roles and the graphics API are hints from names and imports, never a reason to drop a file; executable and folder names reach output only through `rerun_core::escape` (ADR 0016) |
| 14 | Journal, backups or stored plans tampered with by any process of the same user (`<LocalAppData>\Rerun` is user-writable: records edited, deleted or planted, a backup swapped, a junction planted at `Rerun` or `journal`) | The journal is untrusted input (ADR 0019): bounded reads before parsing, `deny_unknown_fields`, `format` checked, numbering without gaps, one written form per record and a grammar shared with the writer, else the transaction is `Damaged` and never acted on automatically (ADR 0019 amendment, P2-7: a damaged transaction whose head is readable and hash-consistent counts as open with its objects; one whose head is unusable blocks every apply until it is forgotten; a valid prefix that ends in `Closed` with anything planted after it counts as closed with an anomaly); `AppDir` opened handle-relative below `LocalAppData`, reparse points refused; paths parsed again as `RelPath`, roots reopened through `policy::root` and checked by identity, registry locations checked again by `policy::registry`; a backup used only if its hash equals its intent; a stored plan applied only if its bytes hash to the `PlanHash` the preview showed, then re-validated. `exec` re-checks a parsed head against its records (temp names and backups by op kind, a backup equal to the replaced file's old state) and refuses a mismatch; a damaged or unreadable transaction blocks every apply and every earlier revert until `forget` writes `journal\<txn>.forgotten` (P2-8, user decision D2): planting such a marker is forgetting, no new capability. So tampering can make Rerun forget a change or restore content the same user could have written anyway, never write outside a root accepted by `policy::root` or an allowed registry slot. The elevated helper never reads the journal (phase 3). Accepted: same-user malware gains nothing it did not have |

## Principles

- The GUI never runs elevated. Admin only in the helper, per apply, with a validated plan.
- Network only to the Topo index and package hosts from `packages/`. No telemetry.
- `unsafe` minimal, commented, encapsulated in `sys::win`, `rerun-launch` and `rerun-cpu`.
- Dependencies checked with `cargo deny` (licenses, advisories, crates.io only, no OpenSSL) in CI.
- **Policy boundary (ADR 0004):** `sys` executes, `policy` decides. Confinement (`policy::path::RelPath`, `policy::root`) and the registry allowlist (`policy::registry` from phase 2, ADR 0018) sit above `sys` and apply equally to the fake, the real system and the elevated helper.
- **No system access bypassing `sys`:** `clippy.toml` blocks `std::fs` write operations and `std::process::Command::new` (`disallowed_methods = deny`). Exceptions only with `#[allow(…, reason = "…")]` in `sys::win` and `rerun-launch`.
- **No path-based Win32 file APIs:** `clippy.toml` also blocks `CreateFileW`, `DeleteFileW`, `MoveFileExW`, `ReplaceFileW`, `CopyFile*`, `GetFileAttributesW`, `GetNamedSecurityInfoW`, `DefineDosDeviceW` and the other path-based file APIs of `windows-sys`, plus `NtOpenFile`. `NtCreateFile` is fenced to the two wrappers `sys::win::nt::{open_relative, open_absolute_dir}`, which fix the flags (`OBJ_DONT_REPARSE` and `FILE_OPEN_REPARSE_POINT` for every relative open, `FILE_OPEN` only, never `FILE_OPEN_FOR_BACKUP_INTENT`); ADR 0007, amendment "sys::win read side".
- **Registry only through `sys::win::reg`** (ADR 0009): `clippy.toml` blocks every other advapi32, ntdll and shlwapi registry call (writes, legacy and ANSI variants, reads that fix up or expand values, hive loading, predefined-key overrides, transactions, `NtOpenKey*` and the other bypasses), DACL writes by handle (`SetSecurityInfo`, `SetKernelObjectSecurity`, `NtSetSecurityObject`), and every environment-based path source including `GetTempPath*`. `sys/win/bans.rs` makes each `windows-sys` entry fail clippy if it does not resolve.
- **DLL loading** (ADR 0008 amendment 2026-11-05): the static imports of every shipped executable are an exact, tested allowlist per binary (`LAUNCH_IMPORTS` for `rerun-launch.exe`, `CLI_IMPORTS` for `rerun.exe`; no graphics DLL, no dynamic CRT in either), no delay-load imports, no hand-written `extern` block, `#[link]` or `raw-dylib` anywhere (source rule test); dynamic loads only through `sys::win::loader` (System32, bare name); `LoadLibrary*`, `GetProcAddress` and every DLL search path call (`SetDefaultDllDirectories`, `SetDllDirectory*`, `AddDllDirectory`, `RemoveDllDirectory`) are `clippy.toml` bans outside it. GPU data only through the hand-written DXGI binding `sys::win::dxgi` (the `D3DKMT*` adapter APIs are banned), never in the elevated helper; COM activation (`CoCreateInstance*`, `CoGetClassObject`, `CoGetObject`, `CoInitialize*`) is banned until phase 3 gives it one wrapper with `CLSCTX_INPROC_SERVER` only.
- **System profile** (ADR 0015, `rerun-core::hw`): read-only and in-process. The OS build comes only from `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion` `CurrentBuildNumber` (native view, `Registry::get`), an admin-writable value treated as untrusted: a strict `REG_SZ` of ASCII digits, anything else `Malformed`, errors never echo the value; `UBR` is display only. The version APIs (`GetVersion*`, `VerifyVersionInfo*`, `VerSetConditionMask`, `RtlGetVersion`, `RtlVerifyVersionInfo`) are `clippy.toml` bans. Adapter names and PCI IDs come from the driver and are untrusted: the profile keeps them raw (`GpuAdapter`), maps only `(vendor, device)` through the architecture table and never consults revision or subsystem IDs. The GPU architecture table (`data/gpu-arch.yaml`, a compiled-in mirror until the phase 4 index) is declarative data checked by `GpuArchTable::new` before use: at most 256 architectures, 4,096 entries, 1,024 IDs plus ranges per entry and 3 × 65,536 in the whole table (checked before the lookup index is allocated), a Vulkan minor of at most 99, IDs within `0..=0xFFFF`, AMD/NVIDIA/Intel only, declared architectures with a matching vendor, no device covered twice (sorted intervals, ranges never expanded), `source` 1 to 200 characters without control or bidi characters; errors name positions, never content. A Topo is evaluated against exactly the table it was validated with. **The profile never authorises anything:** a `when` condition only chooses which variants are offered; the elevated helper never builds a profile and never evaluates `when`, it checks the plan, not the hardware. A fact that could not be read makes its condition `Unknown`, never preselected or applied automatically.
- **Untrusted display text** (ADR 0016): app names, library labels and paths, install folder and executable names, adapter names, table `source` texts and issue texts are attacker-controlled (any process of the user writes Steam files and game folders, drivers name adapters). Printed raw, escape sequences could rewrite the terminal (cursor moves, forged or hidden lines, window title), and bidi controls and invisible characters could reorder or hide text. Every untrusted field reaches output only as `escape::Shown`, which only the two entry points of `rerun_core::escape` create (one table of code points, Unicode 16): `escape::path` for `RelPath`, `RootPath` and `SysError` targets (`sys::error::shown_target` delegates to it): control, format and default-ignorable characters (tags, variation selectors), U+2028/U+2029, supplementary private use, noncharacters, plus the confusables of `is_deceptive`; `escape::text` for names, labels and messages: the same without the printable confusables. A string holding such a character is shown whole as `{:?}` with each as `\u{x}`, clean text unchanged. A last-resort net checks every output line against the whole base set of `escape::text` (not only control characters): in tests a hit panics, so it never hides a missing field escape; in a build the hit line is written escaped as a whole. Static text is ASCII, no colours. Executable version strings are not shown in phase 1. The phase 5 app additionally isolates untrusted text (`<bdi>`, `dir="auto"`), because strong right-to-left letters are no control characters.
- **CLI** (ADR 0016, ADR 0020): `system`, `scan`, `plan` and `status` write no game folder or registry key and take no lock (`plan` without `--dry-run` stores the plan under `<LocalAppData>\Rerun\plans`); `apply`, `revert` and `forget` hold the journal lock (`journal\lock`, share 0) for their whole run, so two of them never interleave. `--help` and `--version` end before any registry or file system access. The console is left as found: no `SetConsoleMode`, no `SetConsoleOutputCP` (shared with the parent shell, outliving the process); clap is built without `color` (which would call `SetConsoleMode` and read colour variables), checked in CI. `rerun scan` resolves `ForbiddenRoots` from its own install folder, fail closed: on a network drive it exits 1. `--hashes` is opt-in with a warning. Run elevated with another administrator account, `HKCU` and the known folders are that account's, so Steam is "not found" for the interactive user.
- **CI supply chain:** GitHub Actions pinned by commit SHA, `permissions: contents: read`, toolchain pinned in `rust-toolchain.toml`, `Cargo.lock` committed and `--locked`.

## Allowed registry areas

Phase 2 (`policy::registry`, ADR 0018; `HKCU`, native view, non-elevated only):
- `HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers`: value name = canonical path of an executable inside a game root (the root's path and a relative path, M2), `REG_SZ`; Rerun adds and removes only allowlisted tokens and keeps every other token; `RUNASADMIN`, `RUNASHIGHEST` or another elevation token is never added by an apply, a revert restores the previous value exactly. New values refused until `compat_layer` (P2-11).
- `HKCU\Software\<Vendor>\<Product>[\…]` (at most 4 further segments): game-specific keys named in the step (later the Topo) and approved in review; key segments and value names printable ASCII; `<Vendor>` not `Microsoft`, `Classes`, `Policies`, `Wow6432Node`, `Clients`, `RegisteredApplications`, `AppDataLow`, `Valve`, `Rerun`, `Mythen Studios`, `Khronos` (folded); value names and `REG_SZ` data without `\ / : %` (G1); new values `REG_DWORD`, `REG_QWORD` or `REG_SZ` (printable ASCII only, at most 1,024 characters), never `REG_BINARY` (until a reviewed Topo needs it), `REG_EXPAND_SZ`, `REG_MULTI_SZ` or `REG_LINK`. The deny list and the content rule are a backstop; the review of every Topo key and the preview stay the defence (user decision G1, ADR 0018).

Reserved, refused until their phase:
- `HKCU\Software\Microsoft\DirectX\UserGpuPreferences` (value name = canonical path of a detected game exe; `gpu_preference`, phase 4, `03b-gpu-display.md`).
- `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\<exe>` (only `PerfOptions\CpuPriorityClass`, `Debugger`, `UseFilter`, filter subkeys; elevated helper, phase 3).

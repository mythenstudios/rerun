# 06 · Threat model

## What we protect

The user's system (files outside the game folder, registry, firewall, autostart) and the trust that Rerun only does what the preview shows.

## Attackers and scenarios

| # | Scenario | Countermeasure |
|---|---|---|
| 1 | Malicious Topo in the community repo | Purely declarative format, no execute primitive, launch options only as game arguments after `%command%`, INI values without line breaks/paths, download URLs bound to the original source, schema validation, review via PR, signed index |
| 2 | Compromised GitHub repo / index replaced | Ed25519 signature, key offline, public key in the binary |
| 3 | Upstream release replaced | Pinned SHA256 in the package, check before extraction |
| 4 | Path escape (`..`, absolute paths, junctions, ADS, UNC, `CON`, Unicode lookalikes) | `RelPath` and `RootPath` lexically strict; all file operations relative to a root handle opened by `policy::root`, never follow junctions or symlinks below the root, forbidden roots from known folders, never environment variables (Windows, Program Files itself, profile roots, other users' profiles, per-volume system folders; a root may neither lie in nor contain a protected folder; the list fails closed), no network or volume roots, a game folder from a store is opened handle-relative so a junction at game level is an anomaly, root identity re-checked before every apply and revert, hard links never changed in place, invalid names on disk reported and never touched (ADR 0007) |
| 5 | Zip Slip during extraction | Check every entry individually, never extract blindly |
| 6 | Registry abuse | Allowlist of keys, previous value to the Journal |
| 7 | TOCTOU between preview and elevation | The plan hash only catches accidents; the boundary is the helper's own re-validation: it treats the plan as untrusted, only writes into roots that only admins can write and that contain the topo's target exe with the signed hash, verifies index signature and package hashes itself, and opens its root by volume GUID path + file ID; root identity (volume serial + file ID) is checked on every apply and revert (ADR 0007). Helper process hardening: ADR 0008. DLL planting next to a Rerun executable (a user-writable install folder): every shipped executable is linked with `/DEPENDENTLOADFLAG:0x800` (static imports from System32 only) and restricts its DLL search path to System32 as the first statement of `main`, failing closed; tests check the built PE (ADR 0008 amendment 2026-11-05) |
| 8 | Wrong exe targeted (same name) | Identification via path + hash; IFEO with `FilterFullPath` |
| 9 | Revert deletes foreign/modified files | Delete only if the hash matches, otherwise ask |
| 10 | Crash in the middle of apply | Write-ahead Journal, revert also works with incomplete entries |
| 11 | Rerun itself perceived as malware | Code signing, no injection, IFEO opt-in only, transparent preview |
| 12 | Manipulated Steam files (`libraryfolders.vdf`, `appmanifest_*.acf` edited or planted by any process of the user: huge or deeply nested files, `#include`/`#base`, odd escapes, forged paths and install folder names) | Bounded parser `detect::vdf` (ADR 0011): only the quoted subset Steam writes, limits for bytes, depth, entries and string length, explicit stack instead of recursion, directives never followed, errors without file content; read handle-relative to the store root with at most `max_bytes + 1` bytes, metadata length never trusted; strict typed views (exactly one of each required field, strict `appid`), a malformed library entry fails the whole file; paths and install folder names stay raw and pass `policy::root` (`StoreDir::open`, `StoreDir::game`) before anything is opened. Steam detection (ADR 0012): the registry values (`HKCU` writable by the user, `HKLM` pointing into the same user-writable folder) are read with `Registry::get` only, never expanded (`REG_EXPAND_SZ` with `%` refused), and pass `StoreDir::open` like any path; `HKCU` wins, a disagreeing candidate is reported and never scanned; no fallback from a damaged or locked `steamapps\libraryfolders.vdf` to `config\libraryfolders.vdf` (only on `NotFound`), the two never merged; at most 256 listed libraries, de-duplicated by root identity; `steamapps` opened relative to the library (a junction there is refused, never followed); manifests only as plain files (no directory, reparse point or restricted entry is opened), at most 16,384 per library counted before any manifest is read, so neither the manifest reads nor the issue list grow without bound (the `steamapps` listing itself is not bounded: `read_dir` collects and attribute-opens every entry first; accepted limit, only the same non-elevated user can fill it; phase 2 follow-up a bounded `read_dir` next to `Dir::read_limited`, ADR 0012); `appid` must equal the ID in the file name, `installdir` must be a valid single segment before `StoreDir::game` opens it handle-relative; untrusted text is `RawText` (no `Display`, `Debug` shows only the length), issues never carry file or registry content beyond paths and names the user must see, raw ones escaped; the scan never fails as a whole, so one forged or offline library hides nothing else. **Read, and nothing else:** `HKCU\Software\Valve\Steam` `SteamPath`, `HKLM\SOFTWARE\Valve\Steam` `InstallPath` in the 32-bit view (`WOW6432Node`) and in the native view; of the Steam root `steamapps\libraryfolders.vdf`, or `config\libraryfolders.vdf` if the first is missing; of each library the listing of `steamapps` (every entry opened attribute-only, the reparse data of links read) and its `appmanifest_<id>.acf` files; on `open_game` the folders `steamapps\common` and `steamapps\common\<installdir>` (opened, metadata of the game entry); `Dir::info` of every opened root (each registry candidate, each library), of `steamapps`, and in `StoreDir::game` of the store root, `steamapps\common` and the game folder. Errors of the system layer never carry a raw name unescaped (`sys::fs`, error targets). Accepted limit: opening a library on a disconnected mapped drive can block for the SMB timeout |
| 13 | Manipulated executables in game folders (planted or replaced by any process of the user: huge, truncated, crafted headers, sizes and offsets that point anywhere, old formats) | Bounded parser `detect::pe` (ADR 0013): no memory mapping, no whole-file read; every access is one range read into a buffer sized by a limit, never by a header field alone, charged to a total budget per file (1 MiB) before it happens; header region 64 KiB, at most 96 sections, at most 16 data directories, at most 1,024 DLLs per import table read in one range, DLL names 1 to 255 bytes of printable ASCII (no control, bidi or non-ASCII character can reach an output), no function names, ordinals, exports or forwarders; the version resource only through the `RT_VERSION` branch at fixed depth (three tables of at most 1,024 entries, no tree walk), at most 64 KiB, at most 64 string tables, six kept strings of at most 1,024 UTF-16 units each, kept raw as `RawText` (`Debug` shows only the length) for the output layers to sanitize; no recursion, no `unsafe`, no system call; DOS, NE and LE/LX recognised and never parsed further; opened only through `open_game_exe`, relative to the `GameDir` handle (no reparse point, restricted entry or online-only placeholder is opened, the length is never asked for, neither from metadata nor by seeking to the end); errors carry a kind and a file offset, never file content. PE facts are hints for display, matching and suggestions, never authorization: a Topo matches an exe by path and hash, the elevated helper by the signed hash. Choosing the files (`detect::exe`, ADR 0014): a breadth-first walk of the game folder only, every directory opened relative to the game handle, at most depth 3, 128 listed directories, 20,000 entries and 64 parsed executables (a partial result is marked incomplete); reparse points and restricted entries are reported, never followed or opened; case-sensitive directories and anomalous names are reported and never used; read per game: the listings, at most 64 × 1 MiB of parser reads, and only with `--hashes` the whole content of at most 8 `Game` executables (at most 2 GiB each plus one 256 KiB chunk, at most 4 GiB per game plus one chunk per hashed file, the chunk clamped to at most 16 MiB), each hashed on the handle it was parsed on after its facts were compared with the first inspection; roles and the graphics API are hints from names and imports, never a reason to drop a file |

## Principles

- The GUI never runs elevated. Admin only in the helper, per apply, with a validated plan.
- Network only to the Topo index and package hosts from `packages/`. No telemetry.
- `unsafe` minimal, commented, encapsulated in `sys::win`, `rerun-launch` and `rerun-cpu`.
- Dependencies checked with `cargo deny` (licenses, advisories, crates.io only, no OpenSSL) in CI.
- **Policy boundary (ADR 0004):** `sys` executes, `policy` decides. Confinement (`policy::path::RelPath`) and the registry allowlist (from Phase 3 `policy::registry`) sit above `sys` and apply equally to the fake, the real system and the elevated helper.
- **No system access bypassing `sys`:** `clippy.toml` blocks `std::fs` write operations and `std::process::Command::new` (`disallowed_methods = deny`). Exceptions only with `#[allow(…, reason = "…")]` in `sys::win` and `rerun-launch`.
- **No path-based Win32 file APIs:** `clippy.toml` also blocks `CreateFileW`, `DeleteFileW`, `MoveFileExW`, `ReplaceFileW`, `CopyFile*`, `GetFileAttributesW`, `GetNamedSecurityInfoW`, `DefineDosDeviceW` and the other path-based file APIs of `windows-sys`, plus `NtOpenFile`. `NtCreateFile` is fenced to the two wrappers `sys::win::nt::{open_relative, open_absolute_dir}`, which fix the flags (`OBJ_DONT_REPARSE` and `FILE_OPEN_REPARSE_POINT` for every relative open, `FILE_OPEN` only, never `FILE_OPEN_FOR_BACKUP_INTENT`); ADR 0007, amendment "sys::win read side".
- **Registry only through `sys::win::reg`** (ADR 0009): `clippy.toml` blocks every other advapi32, ntdll and shlwapi registry call (writes, legacy and ANSI variants, reads that fix up or expand values, hive loading, predefined-key overrides, transactions, `NtOpenKey*` and the other bypasses), DACL writes by handle (`SetSecurityInfo`, `SetKernelObjectSecurity`, `NtSetSecurityObject`), and every environment-based path source including `GetTempPath*`. `sys/win/bans.rs` makes each `windows-sys` entry fail clippy if it does not resolve.
- **DLL loading** (ADR 0008 amendment 2026-11-05): the static imports of every shipped executable are an exact, tested allowlist (no graphics DLL, no dynamic CRT), no delay-load imports, no hand-written `extern` block, `#[link]` or `raw-dylib` anywhere (source rule test); dynamic loads only through `sys::win::loader` (System32, bare name); `LoadLibrary*`, `GetProcAddress` and every DLL search path call (`SetDefaultDllDirectories`, `SetDllDirectory*`, `AddDllDirectory`, `RemoveDllDirectory`) are `clippy.toml` bans outside it. GPU data only through the hand-written DXGI binding `sys::win::dxgi` (the `D3DKMT*` adapter APIs are banned), never in the elevated helper; COM activation (`CoCreateInstance*`, `CoGetClassObject`, `CoGetObject`, `CoInitialize*`) is banned until phase 3 gives it one wrapper with `CLSCTX_INPROC_SERVER` only.
- **System profile** (ADR 0015, `rerun-core::hw`): read-only and in-process. The OS build comes only from `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion` `CurrentBuildNumber` (native view, `Registry::get`), an admin-writable value treated as untrusted: a strict `REG_SZ` of ASCII digits, anything else `Malformed`, errors never echo the value; `UBR` is display only. The version APIs (`GetVersion*`, `VerifyVersionInfo*`, `VerSetConditionMask`, `RtlGetVersion`, `RtlVerifyVersionInfo`) are `clippy.toml` bans.
- **CI supply chain:** GitHub Actions pinned by commit SHA, `permissions: contents: read`, toolchain pinned in `rust-toolchain.toml`, `Cargo.lock` committed and `--locked`.

## Allowed registry areas (initial list)

- `HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers` (value = path of the game exe)
- `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\<exe>` (only `PerfOptions\CpuPriorityClass`, `Debugger`, `UseFilter`, filter subkeys)
- Game-specific keys that are explicitly named in the Topo and approved in review

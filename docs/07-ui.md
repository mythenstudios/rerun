# 07 · UI

The app `rerun-app.exe` (ADR 0027) over `rerun_core::flow`, drawn with Slint (ADR 0026). Design reference: layout C of the design round 2026-11-11 (Windows 11 Settings style), theme "Mythen". This document describes the app as built; what a step adds later is marked with the step of plan P5.

## Window

- **Frameless, own title bar** (40 px): the lockup `rerun_` (copy of `brand/logo/rerun-lockup-schnee.svg` in `crates/rerun-app/assets/`), "by Mythen Studios", minimise, maximise/restore and close as own buttons with names and roles. The title bar is the drag area; a double click maximises. Hovering the maximise button opens the Windows 11 snap layouts (the window subclass in `ui::chrome`, ADR 0026).
- **Navigation** on the left (264 px): Library, Applied, History, System, Settings. Library shows the number of games, Applied the number of open transactions. The game page belongs to Library.
- **Status bar** (24 px): "No background process · Topo index <seq> · Signature checked" (with "· N entries not usable" after the index when this version sets entries of it aside, ADR 0024 amendment "Forward compatibility"), or "No Topo index" / "Topo index refused" with "No signature to check". A test-key build adds "Test key build, not for release".
- **Blocked**: an elevated or undeterminable process (rule 6, ADR 0027) gets one full page instead of navigation and pages: "Rerun runs as administrator. Start it normally. …" Nothing is read, nothing listed. A system layer that cannot be created or folders that cannot be read (install folder, forbidden roots, Rerun's folder) get the same page with the core's text as the detail.

## Pages

**Library**
- Page title; the **first-launch card** (three sentences: nothing runs in the background, everything can be undone, only verified sources; "Got it" hides it for the session; remembered with the settings file in P5-10).
- The line "N games in M Steam libraries" (while scanning: "Reading the Steam libraries.").
- Notices, each a card with a strong left rule: no Topo index; this build trusts no index key (`NoKeys`); the stored index refused (with the core's text); Steam not found; no games; "N problems while reading" with the details (game name and the core's text, at most 50) behind "Show problems".
- Search field (part of the name, case-insensitive) and the switch "Group by status". Grouped: **Topo available** (the signed index names a Topo for the app; whether it matches the installed files is the game page's question), **No Topo, nothing offered** (also a game whose only Topos this version sets aside: its badge says **"Needs a newer version of Rerun"** (glyph "!") when a newer Rerun can use one, else **"Not supported by this version of Rerun"** (glyph "–", quiet); German "Braucht eine neuere Rerun-Version" / "Von dieser Rerun-Version nicht unterstützt"), **Not ready** (Steam is updating it, not installed, or its folder could not be read). Ungrouped: "All games". Sorted by name.
- One row per game: status glyph, name, graphics API (from the imports) and the main executable, a status badge (symbol and word), a chevron. Rows are streamed while the scan runs.
- "Scan again".
- Views: list only. Tiles and the dense view ("Zeilen") follow in P5-10; game pictures are a later step (U9).

**Game page** (hero header)
- "‹ Library", the eyebrow "Game · Steam", the title (Steam's name), **one status sentence** in plain words with its glyph, e.g. "1 problem affects your PC · 1 fix available", "There is no Topo for this game. Rerun offers nothing and changes nothing.", "Rerun does not know this version of the game." (no matching executable), "Several Topos fit this game …", "Steam is updating this game …", "This game is listed by Steam but not installed.", "Rerun cannot open the game folder." (with the detail). A game whose only Topos are set aside (ADR 0024 amendment "Forward compatibility" §10) shows the row's badge as the sentence, with "A newer version of Rerun can read the Topo for this game. Until then Rerun offers nothing and changes nothing." or "This version of Rerun cannot use the Topo for this game. …" under it; no problems, no fixes.
- **Set-aside Topos**: "Show details" opens, per set-aside Topo of the game, its ID and the reason (the core's text, escaped, each in its own element). A game with a usable Topo and a set-aside one shows the usable one as usual, with the note "Another Topo for this game needs a newer version of Rerun." (or "… is not supported by this version of Rerun.") and the same details.
- Notes under it: anti-cheat found (fixes refused), a marker that could not be checked, anti-cheat released by the Topo, several graphics adapters, a Topo due for a retest.
- Quiet facts: Steam app, program (the main executable), graphics, Topo revision and status, and (P5-6a) **Last start** when `rerun-launch` has written a result for this game (its profile ID is the game's): how long ago and what came of the rule, e.g. "2 hours ago · Rule applied"; what Rerun adds to it (the option still set, a launcher, the method `watch`) is a note under the hero. The full sentence is on History.
- **Report a problem...** (P5-10a, user decision E4 a) at the foot of the page: a dialog shows first exactly the title and text of the GitHub issue (each line in its own monospaced element), what happens with it (GitHub receives the text as soon as the page opens; nothing is submitted until the user does it there, with a GitHub account), the destination `github.com/mythenstudios/rerun`, and that the text holds only facts Rerun determines itself (no game name, no path, no account). "Open in browser" opens exactly that issue (the click carries the dialog's nonce; another or an older one opens nothing); "Cancel" or Esc closes it. The focus returns to the button.
- **Problems on this PC**: every issue, those that affect this PC first, then "May occur", then "Does not affect this PC" (quiet); each with its fixes by ID.
- **Fixes**: one card per fix, i.e. per variant ID (ADR 0027 U2 a): a fix listed under two issues (EaglePatch for Assassin's Creed) appears **once** with both issues, each with its own `when` and evidence (Verified, Reported, Not confirmed). A fix the engine refuses says why (anti-cheat; the launch cannot carry it, with the core's text) and cannot be selected.
- **Selecting fixes** (P5-5a): a fix the app can apply has a checkbox ("Select this fix"). Only fixes that are *verified* for a problem that affects this PC are ticked at first (and why: "Preselected: tested by us, and the problem affects this PC"); a fix that is only reported, not confirmed, or for a problem that does not affect this PC is never ticked. Fixes that answer the same problem exclude each other (ticking one unticks the other, and the card says "Cannot be combined with ..."); a fix that solves several problems is ticked once. Each problem it solves shows its own evidence, **side effects** ("No side effects listed" when there are none) and **sources** (type and link, as text; since P5-10a an **Open** button next to every link the core would open, accessible name the link and description "Open in browser": the click names the source by its fix, issue and position, the worker looks the URL up again in the current signed index and hands it to the default browser; a link the index no longer has, or one outside the open grammar (ADR 0027 amendment P5-10a), opens nothing and says so calmly). A fix that needs Rerun's administrator helper (a firewall rule, P5-5c) has a checkbox when the helper is installed safely and Windows allows administrator rights here, and says that Windows asks for a confirmation (UAC) when it is applied; it is never ticked at first. Otherwise it says why it cannot be ticked: the helper is not installed safely (the installed version of Rerun brings it), or Windows grants this account no administrator rights. A fix whose package is not in Rerun's packages folder says it needs a download first, has a checkbox, and ticking it opens the **download consent dialog** (below) instead of ticking; a package Rerun does not download itself (a community build, a `TODO` value) says so and cannot be ticked. A fix whose packages are in place is selected like any other.
- **Download dialogs** (P5-5b, rule 4 and 5, ADR 0025): they use the window's one dialog, so the focus trap, Esc, the title taking the focus and the focus returning to the fix's checkbox work as for undo.
  - **Consent** ("These files will be downloaded"): nothing is requested yet. Per package: name and version, **source** (the repository), **release** (the full URL, per architecture for a package with one download each), **host** and the storage hosts it may hand the download over to (the fixed redirect list of ADR 0025), **SHA-256** (the pinned value, per download), **licence**, and the size ("shown while it downloads": the index lists none, the size is the `Content-Length` the server announces), and the sentence that the file is checked after the download and kept only if it has that SHA-256. "Download" starts it; "Cancel" or Esc closes the dialog and nothing happens. The click carries the dialog's nonce: the worker downloads only for the list it showed, and the core checks the index against that list again.
  - **Progress**: the same list with, per package, its state (waiting, downloading with "1.2 MB of 3.1 MB" or "1.2 MB so far" when the server announced no length, already downloaded and checked again, unpacking, done). No confirm button; "Cancel download" asks the download to stop and then reads "Cancelling ..." and waits until the worker confirms, which can take a few minutes in the worst case (WinHTTP waits up to 30 seconds per phase of a request, per address and per redirect, and the cancel is checked between reads, not inside a request). A cancelled download keeps nothing of the body that was running: no archive and no temporary file is left in the cache, and the page says "Download cancelled". Packages of the fix that finished before the cancel stay unpacked (and the first of two downloads of one package stays in the cache, complete and verified); a cancel that arrives during unpacking is not honoured and ends as done.
  - **Failure**: the same list, what went wrong in words (no connection, too slow, the connection broke, a redirect to a place that is not allowed, an error status, a wrong SHA-256 (the file was deleted), too large, the package could not be unpacked safely, the list changed since you looked), the core's text as an escaped detail, and "Try again", which downloads the list that is shown. "Try again" is offered only for a passing failure (no connection, too slow, the connection broke, a server error 5xx, a passing file-system error); a wrong hash, a refused redirect, too large, an unsafe archive, a changed list or a package that cannot be downloaded end with the list closed, and the user opens the fix again. A failed package shows "Failed", those behind it "Not downloaded".
  - **Success**: the dialog closes, the fix is ticked and the usual preview follows, now with the package files; nothing is applied before "Apply".
  - **Closing the window during a download** cancels it and says so ("Rerun cancels the download first"); the window closes by itself as soon as the worker reports that the download has stopped, and at the latest after 15 seconds even if a request still hangs (rule 1: the process ends; a leftover temporary file in the cache is removed by the next download's sweep, ADR 0025). A write still blocks closing as before (a write comes first).
- **Preview** (rule 5, under the fixes, live with the selection): the number of changes, the game folder and the plan checksum (the hash the Apply button carries and the core checks again); every op with what it does and where (create folder or file, replace or patch a file with the new and the current content, set a registry value with the current and the new value, add compatibility layers, edit INI keys with section, key, current and new value, set the graphics preference, the launch profile with its rule, start program and priority, a firewall rule), what **undo** does with each; the warnings with the glyph and the word (Smart App Control, a signed or Steam-built program, a VirtualStore copy the game reads instead, an unknown problem state, anti-cheat, a retest, ...); the notes once per plan (what undo does not restore, registry, layers, INI, launch profile, shared files, patches, graphics preference, Documents); for a launch profile the **Steam launch option** to paste (read-only text, "Copy launch option", where it goes, that existing options go after `%command%`, that undo leaves it to the user, and why it would not work: the shim missing, the install folder unknown); "Administrator rights: not needed", or for a plan with a firewall rule "Administrator: yes – Windows asks you in a moment (UAC)" with the dialog Windows shows (a Yes/No consent, or an administrator's password), a note when it appears on the normal desktop instead of the secure one (other programs could reach it), and when only signed programs are elevated; on a PC where Windows does not ask at all, the preview says that the click on Apply is the only confirmation; and one sentence that undo takes the whole plan back together (the launch profile is named only when the plan has one). "Apply" is enabled only after the window reported the preview rendered and while the game is closed (the core checks); nothing is stored before the click (looking never creates Rerun's folder).
- **Waiting for Windows** (P5-5c): after "Apply" (or "Undo this change") of a change that needs the helper, the window's one dialog says "Waiting for Windows (UAC) ...": confirm the User Account Control dialog (Rerun passes its window as the dialog's owner so that Windows shows it in front of the window; that is the goal until the [DEV] check of docs/09 confirms it), and where to look if it is hidden (a flashing shield in the taskbar). It has no button, Esc does nothing and the window cannot be closed meanwhile; the result closes it.
- **Results and refusals** appear in a banner above the page that takes the focus (the screen reader reads it): applied, nothing to change, taken back, only partly done (with a pointer to Applied), and calm refusals with what to do: a file of the game in use, another Rerun operation, a damaged or earlier change that must be dealt with first (its transaction ID is the detail), a taken DLL name, Steam busy, an admin-only folder. With the helper: administrator approval declined (nothing applied, everything before it taken back, the change closed), the helper did not finish (taken back, the reason as the detail), the change stays open because Rerun could not confirm what the helper did (undo it under Applied), the helper not installed safely, no administrator rights here, a helper still busy. **The game changed since the preview** and **the state changed since the preview** are not errors: the page is read again and the banner says to look at the fixes and the preview again.
- **Applied to this game**: the cards of the game's open transactions (below).

**Applied**: "Nothing applied / Your games are unchanged", or the number of open transactions, then **one card per transaction** (user decision U1 a): the game, the state with symbol and word (Applied; Interrupted, Undo interrupted, Cleanup pending, Damaged, Unreadable, Needs you), the transaction ID, what is wrong if something is, **every change in it** as in the preview, and the sentence that undo takes all of it back together, the launch profile included, and that changing one of them later means undoing the card and applying again. "Undo" opens the **undo dialog**: nothing has changed yet; per change, newest first, what undo meets now (will be set back, already as before, Rerun's part is set back and later changes stay, someone else changed it and Rerun leaves it, stays for another change that relies on it, not reached); the game must be closed; the cleanup it would do; where it would stop and why; and what becomes of the launch option (remove it in Steam by hand, with the option shown; the earlier profile is back; the profile stays). "Undo this change" does it; Esc or "Cancel" closes. If the state changed since the dialog opened, the dialog shows again with a calm note and nothing was written. An undo that removes a firewall rule names the UAC prompt it brings and asks Windows once when confirmed; a declined prompt undoes nothing and keeps the card (Undo asks again). Without a safely installed helper the dialog says why and cannot be confirmed. "Close without undoing" (forget) has its own dialog with what is on disk now; it is the way out of a change someone else changed or a damaged record, and says that Rerun can no longer undo it. Reloaded whenever the page opens and after every write.

**Rebind dialog** (P5-6c, user decision E3 a): when an undo cannot go on because Steam moved or reinstalled the game (its folder is gone where it was recorded, or it is another folder now), the undo dialog says "The game folder has changed", explains that Rerun can check the folder Steam lists now and that nothing changes before the user confirms, and has a second button "Check new folder" (it only reads). That opens the **rebind dialog**: the folder recorded and its library, why it does not open, the folder Steam lists now and its library, the folders the change created there (found, or missing), every change with what the undo meets there, the game must be closed, the note on registry changes (only for a change that has some), that only the folder bound now is undone, that **the new binding is permanent**, and what becomes of the launch option. One confirm, "Rebind and undo", and no extra checkbox; Esc or "Cancel" closes. If the folder changed since the preview, the dialog shows again with a calm note and nothing was written. A change that is bound already goes straight to its undo preview; every other refusal (a folder you chose yourself, several libraries hold the game, a library cannot be read, Steam is updating the game, another folder of the change is gone, ...) is said in its own words. A change whose firewall rule is still there is not rebound from the app yet: its undo needs the administrator prompt, so the dialog says so and cannot be confirmed (the command line `rerun revert <id> --rebind` does it); once an undo has removed the rule, the rebind is available. When the game folder is at the same path as recorded but is another folder (a reinstall), the dialog says so. The result lists, per change, what did not go back as expected (as after any undo).

**Start band** (P5-6b): when the journal holds changes that need the user (a card with a problem: Interrupted, Undo interrupted, Cleanup pending, Needs you, Damaged, Unreadable; an applied card alone never counts), a calm band above every page says "N changes need you", that Rerun changes nothing by itself, and has "View" (goes to Applied) and "Dismiss". It is separate from the result banner, takes no focus (a screen reader still finds it), and **never acts**: no recovery starts at launch (ADR 0019, rules 1 and 5). It is evaluated after every read of the journal, goes by itself when the problems are solved, is hidden on Applied itself, and a dismissal holds for the changes it was made for this session (a new change with a problem shows it again). After an undo the result banner lists, per change, what did not go back as expected: only Rerun's part set back, someone else's change left as found (with where the old state is kept), a change left to a later change that relies on it, copies of Rerun's that are still in use or kept next to a changed file (with the way out) or are not Rerun's, and launch profiles set back in another folder. A rebind whose record may or may not be on disk says so in its own words.

**History** (P5-6a): the whole journal, read each time the page opens, and the last start of each launch profile. Looking is read only (undo and close are on Applied); the one button here that changes anything is **Clear history…** (P5-6d-1b, below). The journal has no time stamps (ADR 0019), so the entries come **newest first by their number, without a date**, each with its transaction ID. Groups, in this order, only those that have entries: **Open** (everything not closed; a pointer says it is still under Applied; always shown in full), **Undone**, **Rolled back** (an apply failed and Rerun put everything back) and **Closed without undoing** (forgotten: says where the backups stay and which `.old` files may remain next to the game's files; if the change still holds a launch profile, that the Steam launch option keeps working until you remove it by hand). The three closed groups start **collapsed** with their number in the heading ("Undone (45)") and a "Show" button; expanded they show the newest 20 entries and "Show older (N not shown)" reveals the next 20. The collapse state is the window's, for the session only (nothing is stored). A transaction that began and changed nothing is not listed at all (P5-6d-0). Each entry: the game (its name, or "Steam app N"), the state with symbol and word, the ID, and every change in it behind "Show details" (as on the card). Entries of the journal folder that are not Rerun's are counted. Below: **Last start of each game**, one row per launch result, newest first: the game (a profile Rerun cannot attribute to a game shows its profile ID), how long ago ("2 hours ago", from the clock when the page was read) and the exact UTC time next to it (no time zone is read from Windows), what came of the rule (symbol and word: Rule applied, Changed after start, Ended early, Check failed, Rule not applied, Unreadable) with one sentence about it (the CPU rule and priority as set and what the check found, or the reason it was not applied, how Steam's command was started and how a paused process was ended), and what Rerun adds: the Steam launch option still set although no profile was found (and which change holds the profile now), the check that covered a launcher, not the game, the method `watch` and its target, a priority class that could not be put back. A result file that cannot be read is a row with the reason; an unreadable launch folder or one with entries that are not Rerun's is one line.

Keeping the history short (P5-6d-1b, ADR 0027 amendment P5-6d). Under the order line the page says, quietly, what Rerun keeps: "Rerun keeps the last 100 undone or rolled back entries; older ones are removed when you apply or undo something." (the number is the core's `HISTORY_KEEP`; the line is not shown while there is no history). The cap itself runs in the core after a write of Rerun's own (apply, undo, rebind, close without undoing); the window only reports it: after the result's text a **quiet line** such as "3 older history entries removed" (nothing when none were removed; a failure of the cap is only logged in the timing trace, never shown, because the write it followed went through). **Clear history…** (a button under that line, not shown while there is no history) asks the core for a preview and opens a dialog that **lists** (rule 5: a list, not a count) under "Entries to be removed (N)" each entry that goes (the game as the history names it, "No. 12", and its state in words; the entries that changed nothing are one summary line, "2 empty entries (changed nothing)", not a row each), under "Launch results to be removed (N)" each launch result that goes (the game, or the profile when no game has it), then under "Stays (N)" each entry and launch result that stays with one short reason (not finished, folder unreadable, holds a launch profile, handed over a file a newer change may rely on, folder holds something that is not Rerun's, too many files, closed without undoing so its backups stay (the line says only "Its backups stay."), a backup in use right now; a launch result whose Steam launch option is still set, or that cannot be read), and the sentence "Game folders, the registry and the firewall stay unchanged." The one confirm, "Clear history", carries the nonce of the dialog shown (the rule of undo: a confirm of any other dialog writes nothing and shows the current preview again); the core removes exactly what was listed. If the history changed since the preview, nothing is written and the dialog is shown again with the note "The history changed; look at it again.". With nothing to remove the dialog says so, still lists what stays, and has no confirm. Clearing is a write: the window does not close while it runs. Afterwards the history page is read again and a result says how many entries and launch results were removed ("3 entries and 2 launch results removed."). Open changes, changes closed without undoing and anything unreadable are never removed; an entry that handed files over to a later change goes once every later change that may rely on them is finished. If the core refuses an entry at delete time (a backup in use, something that is not Rerun's in its folder), the result lists it under "Stays (N)" with its reason, and an entry that was gone already counts as removed. When the dialog closes (confirm, cancel or result) the keyboard focus returns to the "Clear history…" button.

**System**: graphics adapters (name, video memory, architecture, integrated), processor (logical processors, cores, cache groups), Windows build, Smart App Control, Steam. Read when the page opens. Below (P5-6b, only when there is something to say): **Firewall rules of Rerun without a change**, the rules (name, program) that no open change of this Windows account owns, read by its own job when the page opens (never at start, never kept): they may belong to another account; Rerun does not remove them, so the page says to remove them in Windows Defender Firewall with Advanced Security. No button. A firewall or journal that cannot be read is one line with its reason.

**Settings** (skeleton): Safety (preview before every change, only sources from the signed index: both always on), **Packages** (P5-8b-3, below), **Data** (P5-10a, below), Appearance (theme, language following Windows), About (version, licence). The rest follows with P5-10.

**Settings > Appearance > Theme** (P5-10c, user decision E1 a). A radio group, "Mythen" and "Night" ("Nacht" in German), applied at once and remembered in the settings file (ADR 0027 amendment P5-10); the line under the title says both are dark. While Windows' high contrast is on, its colours win: both radio buttons are off and the line says so ("Windows high contrast is on, so Rerun uses its colours. The theme applies again once it is off."). Accessible names: the group "Theme" ("Thema"), each choice by its name with its checked state.

**Settings > Data** (P5-10a, ADR 0027 amendment P5-10a). Read each time the page opens (a worker job, nothing created): a line on what the folder holds, then its path in mono (`<LocalAppData>\Rerun`, fixed, user decision U6 a). When it exists, **Open in Explorer** shows it (only this folder); when it does not, "Not created yet. Rerun creates it when it first stores something." and no button. A path that cannot be told is a note with the core's words.

**Settings > Packages** (P5-8b-3, ADR 0025 amendment P5-8b, ADR 0027 amendment P5-8b-3). Rerun's package store, read each time the page opens (a worker job, never kept). A line says that undoing a fix never needs a package and that a removed package is downloaded again when a fix needs it, if the index still lists it. Under it, one card per package (by ID and version): its name in the signed index (or the ID), "<id> <version>" in mono, its state with symbol and word (unpacked, incomplete: a file of the index is missing, only the download), "1.4 MB · 2 files · 1 archive", and "Not in the index: it can't be downloaded again" for a package the index no longer lists. Who uses it: one line per transaction that is not settled ("Used by Assassin's Creed · No. 12 · Applied"; the game as the history names it), or "Not used". **Remove...** on every card (accessible name "Remove...: <name> <id> <version>"); it is off, with the reason under the lines, while a change uses the package, a transaction that cannot be read keeps every package, or the package's folder holds something Rerun does not remove (a link, a hard link, a read-only, hidden or system entry, too many entries, a name that is not Rerun's, a drive that cannot remove it). **Remove all unused...** sits under the intro (off when nothing can go). Below the cards, quietly: downloads no package of the index names, leftovers of interrupted downloads, and the entries of the store Rerun never touches, each with its reason. A store that cannot be read is one card with what it means and the core's words; no store folder: "Rerun holds no packages."

The **removal dialog** works like the clear dialog (P5-6d-1b): both buttons only ask the core for the preview (reads, writes nothing), and the dialog lists (rule 5) under "Packages to be removed (N)" each package that goes (name, ID and version, size, files and archives, "can't be downloaded again" where it applies), then **one folded list per package** (button "Show the files (N)" / "Hide the files", collapsed at first; every file below its version folder and every archive of the cache is listed), "Downloads without a package to be removed (N)", the leftovers, and under "Stays (N)" each package that stays with its reason and the changes that use it. Then how much room it frees and that game folders, the registry and the firewall stay unchanged. A package that stays has a dialog without a confirm button. The confirm carries the dialog's nonce; the worker removes only for the dialog it showed last, and the core removes exactly what was shown (`RemoveShown`): if the store or the use of a package changed, nothing is removed and the dialog is shown again with "The packages changed; look at them again." While the job runs the window cannot close (a write job). The result says "2 packages and 1 archive removed, 13.6 MB freed." (what stopped, say a file a scanner holds, is listed with its reason), the page is read again, and the session forgets what it read of the games, so a fix card whose package went offers the download again. Focus: the dialog's title when it opens, then back to the button that opened it (a card's button is gone with its package). Esc and Cancel close it before the confirm. In every list of the clear and removal dialogs and on the cards, untrusted text (a game name from the Steam library, a package name, a path) is its own element beside Rerun's words (`TextLine`: before, name, after), never inside a sentence. The headings say what will happen ("Packages to be removed (N)"), not what has.

Later steps (plan P5): the library views and the language choice (P5-10d), About with the third-party notices (P5-10e). Not planned for the first release: accent colours, density, tiles, an own contrast theme (Windows' high contrast is followed instead), Mica and Acrylic.

## Design system: theme "Mythen"

Strictly monochrome; surfaces are fills, not borders; hairlines separate rows.

| Token | Value | Use |
|---|---|---|
| `bg` (Fels) | `#0b0b0b` | window, title bar, status bar |
| `raised` | `#111110` | cards, groups |
| `raised2` | `#161615` | selected navigation entry, hovered row, quiet badges |
| `raised3` / `raised4` | `#1f1f1e` / `#2a2a28` | secondary buttons, hovered |
| `line-soft` | `#1a1a19` | hairlines, badges |
| `line` / `line-strong` | `#2e2e2c` / `#8a8a86` | inputs; the rule of a callout, the outline of a quiet badge |
| `text` / `strong` | `#e8e8e4` / `#f7f7f5` | body text / headings, the primary button's fill |
| `muted` / `faint` | `#9c9c98` / `#8a8a86` | secondary text / the status bar |

Radii 2 px (chips, inputs) and 4 px (cards, buttons); spacing 4, 8, 12, 16, 24, 32, 40, 56 px; the primary button is inverted (Schnee on Fels). The tokens live in `rerun-app::theme` and are copied into the global `Theme` of `ui/app.slint`; no colour literal in a `.slint` file (source rule). Every text/background pair reaches a contrast of 4.5:1 (test).

## Theme "Nacht" and Windows' high contrast

P5-10c (user decision E1 a, replacing U8 a): a second dark theme and Windows' high contrast; no light theme, no own contrast palette, no transparency.

"Nacht" ("Night" in English) takes the neutral dark greys of Windows 11, without an accent; the primary button stays inverted.

**Windows' high contrast** wins over the chosen theme, read before the first frame and followed live (the window subclass hears `WM_SYSCOLORCHANGE` and `WM_SETTINGCHANGE`). Every colour comes from five system colours: every surface is the window colour, every text, line and the primary button's fill the window text colour (the pair Windows guarantees), disabled text and the status bar the grey text colour, the close button under the pointer the highlight colours. Since fills no longer tell shapes apart, buttons, cards, badges, the switch's track, a hovered row and the selected navigation entry get an edge (`edge`, 0 in the themes). Status stays symbol and word. A light contrast theme ("Desert") makes the window light: that is the user's choice in Windows; the search field keeps Slint's dark Fluent style.

Fonts (user decisions U10 a and 2026-11-12): **embedded**, OFL, unmodified, imported by `ui/app.slint` and compiled into `rerun-app.exe`; nothing is loaded from disk or network at run time. Archivo Expanded ExtraBold (800) for the page and hero titles, IBM Plex Sans 400/500/600 for text, IBM Plex Mono 400/500 for IDs, paths, hashes and the status bar. Files, versions, sources and SHA-256 are in `crates/rerun-app/assets/fonts/FONTS.md` (checked by `tests/fonts.rs`; policy exception in `docs/05-sources-policy.md`). A glyph the embedded fonts lack (CJK or other scripts of Steam titles, the status symbols) falls back to a Windows system font; Segoe UI Symbol (status glyphs) and Segoe Fluent Icons (window buttons) stay Windows' own. The About page of P5-10 shows the three OFL licence texts and the copyright lines of the fonts (the `OFL.txt` files are the source), next to Slint's licence.

A glyph never stands alone: the word next to it carries the meaning, and screen readers read the word.

## Accessibility (requirements)

- Every interactive element has a name and a role through UI Automation (Slint's AccessKit adapter): the window buttons, navigation entries (tabs, the active one selected), rows (list items with index and count), buttons, the switch (checked state), the search field.
- Dialogs (P5-5a, P5-5b): while a dialog is open every control outside it is disabled (a focus trap: Tab cycles in the dialog), the dialog's title takes the focus when it opens, Esc closes it, and the button on the card (or the checkbox of the fix) that opened it takes the focus back. Results appear in a banner that takes the focus; the checkbox of a fix and the buttons of a card are named with the fix or game they belong to.
- Full keyboard use: Tab and Shift+Tab through navigation, controls and rows; Enter or Space activates; a focused element is scrolled into view; the focus ring shows only after keyboard focus. Open until the hand check of P5-3: whether Tab reaches the search field (the automated walk skipped it).
- Slint has no heading role: a page's title takes the focus when the page opens, and the page region carries the page's name, so Narrator reads where it is.
- Status as symbol and word; contrast at least 4.5:1 in every theme; text follows Windows' scaling (per-monitor DPI V2). Windows' high contrast is read and followed live (P5-10c, above). The app has no animation, so "show animations" needs no reading. Windows' text size setting is not read yet (a known gap: every page would have to be checked at 200 %).
- Untrusted text (Steam names, paths, Topo texts, the core's error texts) is escaped (ADR 0016) and drawn in its own text element, never inside a sentence, so its direction cannot reorder the text around it.

## Copy

English is the base, German the second language (the app follows Windows' display language). Every string is a typed message of `rerun-app::text`; a missing translation does not compile. Tone: calm, direct, concise; informal "du" in German, Swiss "ss"; no superlatives, no exclamation marks (tests). Rerun never guesses and says so: "Rerun offers nothing and changes nothing."

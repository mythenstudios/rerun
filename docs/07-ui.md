# 07 · UI

The app `rerun-app.exe` (ADR 0027) over `rerun_core::flow`, drawn with Slint (ADR 0026). Design reference: layout C of the design round 2026-11-11 (Windows 11 Settings style), theme "Mythen". This document describes the app as built; what a step adds later is marked with the step of plan P5.

## Window

- **Frameless, own title bar** (40 px): the lockup `rerun_` (copy of `brand/logo/rerun-lockup-schnee.svg` in `crates/rerun-app/assets/`), "by Mythen Studios", minimise, maximise/restore and close as own buttons with names and roles. The title bar is the drag area; a double click maximises. Hovering the maximise button opens the Windows 11 snap layouts (the window subclass in `ui::chrome`, ADR 0026).
- **Navigation** on the left (264 px): Library, Applied, History, System, Settings. Library shows the number of games, Applied the number of open transactions. The game page belongs to Library.
- **Status bar** (24 px): "No background process · Topo index <seq> · Signature checked", or "No Topo index" / "Topo index refused" with "No signature to check". A test-key build adds "Test key build, not for release".
- **Blocked**: an elevated or undeterminable process (rule 6, ADR 0027) gets one full page instead of navigation and pages: "Rerun runs as administrator. Start it normally. …" Nothing is read, nothing listed. A system layer that cannot be created or folders that cannot be read (install folder, forbidden roots, Rerun's folder) get the same page with the core's text as the detail.

## Pages

**Library**
- Page title; the **first-launch card** (three sentences: nothing runs in the background, everything can be undone, only verified sources; "Got it" hides it for the session; remembered with the settings file in P5-10).
- The line "N games in M Steam libraries" (while scanning: "Reading the Steam libraries.").
- Notices, each a card with a strong left rule: no Topo index; this build trusts no index key (`NoKeys`); the stored index refused (with the core's text); Steam not found; no games; "N problems while reading" with the details (game name and the core's text, at most 50) behind "Show problems".
- Search field (part of the name, case-insensitive) and the switch "Group by status". Grouped: **Topo available** (the signed index names a Topo for the app; whether it matches the installed files is the game page's question), **No Topo, nothing offered**, **Not ready** (Steam is updating it, not installed, or its folder could not be read). Ungrouped: "All games". Sorted by name.
- One row per game: status glyph, name, graphics API (from the imports) and the main executable, a status badge (symbol and word), a chevron. Rows are streamed while the scan runs.
- "Scan again".
- Views: list only. Tiles and the dense view ("Zeilen") follow in P5-10; game pictures are a later step (U9).

**Game page** (hero header)
- "‹ Library", the eyebrow "Game · Steam", the title (Steam's name), **one status sentence** in plain words with its glyph, e.g. "1 problem affects your PC · 1 fix available", "There is no Topo for this game. Rerun offers nothing and changes nothing.", "Rerun does not know this version of the game." (no matching executable), "Several Topos fit this game …", "Steam is updating this game …", "This game is listed by Steam but not installed.", "Rerun cannot open the game folder." (with the detail).
- Notes under it: anti-cheat found (fixes refused), a marker that could not be checked, anti-cheat released by the Topo, several graphics adapters, a Topo due for a retest.
- Quiet facts: Steam app, program (the main executable), graphics, Topo revision and status.
- **Problems on this PC**: every issue, those that affect this PC first, then "May occur", then "Does not affect this PC" (quiet); each with its fixes by ID.
- **Fixes**: one card per fix, i.e. per variant ID (ADR 0027 U2 a): a fix listed under two issues (EaglePatch for Assassin's Creed) appears **once** with both issues, each with its own `when` and evidence (Verified, Reported, Not confirmed). A fix the engine refuses says why (anti-cheat; the launch cannot carry it, with the core's text) and cannot be selected.
- **Selecting fixes** (P5-5a): a fix the app can apply has a checkbox ("Select this fix"). Only fixes that are *verified* for a problem that affects this PC are ticked at first (and why: "Preselected: tested by us, and the problem affects this PC"); a fix that is only reported, not confirmed, or for a problem that does not affect this PC is never ticked. Fixes that answer the same problem exclude each other (ticking one unticks the other, and the card says "Cannot be combined with ..."); a fix that solves several problems is ticked once. Each problem it solves shows its own evidence, **side effects** ("No side effects listed" when there are none) and **sources** (type and link, as text). A fix that needs Rerun's administrator helper is shown with that fact and cannot be ticked yet (the helper, P5-5c; the command line still applies it). A fix whose package is not in Rerun's packages folder says it needs a download first, has a checkbox, and ticking it opens the **download consent dialog** (below) instead of ticking; a package Rerun does not download itself (a community build, a `TODO` value) says so and cannot be ticked. A fix whose packages are in place is selected like any other.
- **Download dialogs** (P5-5b, rule 4 and 5, ADR 0025): they use the window's one dialog, so the focus trap, Esc, the title taking the focus and the focus returning to the fix's checkbox work as for undo.
  - **Consent** ("These files will be downloaded"): nothing is requested yet. Per package: name and version, **source** (the repository), **release** (the full URL, per architecture for a package with one download each), **host** and the storage hosts it may hand the download over to (the fixed redirect list of ADR 0025), **SHA-256** (the pinned value, per download), **licence**, and the size ("shown while it downloads": the index lists none, the size is the `Content-Length` the server announces), and the sentence that the file is checked after the download and kept only if it has that SHA-256. "Download" starts it; "Cancel" or Esc closes the dialog and nothing happens. The click carries the dialog's nonce: the worker downloads only for the list it showed, and the core checks the index against that list again.
  - **Progress**: the same list with, per package, its state (waiting, downloading with "1.2 MB of 3.1 MB" or "1.2 MB so far" when the server announced no length, already downloaded and checked again, unpacking, done). No confirm button; "Cancel download" asks the download to stop and then reads "Cancelling ..." and waits until the worker confirms, which can take a few minutes in the worst case (WinHTTP waits up to 30 seconds per phase of a request, per address and per redirect, and the cancel is checked between reads, not inside a request). A cancelled download keeps nothing of the body that was running: no archive and no temporary file is left in the cache, and the page says "Download cancelled". Packages of the fix that finished before the cancel stay unpacked (and the first of two downloads of one package stays in the cache, complete and verified); a cancel that arrives during unpacking is not honoured and ends as done.
  - **Failure**: the same list, what went wrong in words (no connection, too slow, the connection broke, a redirect to a place that is not allowed, an error status, a wrong SHA-256 (the file was deleted), too large, the package could not be unpacked safely, the list changed since you looked), the core's text as an escaped detail, and "Try again", which downloads the list that is shown. "Try again" is offered only for a passing failure (no connection, too slow, the connection broke, a server error 5xx, a passing file-system error); a wrong hash, a refused redirect, too large, an unsafe archive, a changed list or a package that cannot be downloaded end with the list closed, and the user opens the fix again. A failed package shows "Failed", those behind it "Not downloaded".
  - **Success**: the dialog closes, the fix is ticked and the usual preview follows, now with the package files; nothing is applied before "Apply".
  - **Closing the window during a download** cancels it and says so ("Rerun cancels the download first"); the window closes by itself as soon as the worker reports that the download has stopped, and at the latest after 15 seconds even if a request still hangs (rule 1: the process ends; a leftover temporary file in the cache is removed by the next download's sweep, ADR 0025). A write still blocks closing as before (a write comes first).
- **Preview** (rule 5, under the fixes, live with the selection): the number of changes, the game folder and the plan checksum (the hash the Apply button carries and the core checks again); every op with what it does and where (create folder or file, replace or patch a file with the new and the current content, set a registry value with the current and the new value, add compatibility layers, edit INI keys with section, key, current and new value, set the graphics preference, the launch profile with its rule, start program and priority, a firewall rule), what **undo** does with each; the warnings with the glyph and the word (Smart App Control, a signed or Steam-built program, a VirtualStore copy the game reads instead, an unknown problem state, anti-cheat, a retest, ...); the notes once per plan (what undo does not restore, registry, layers, INI, launch profile, shared files, patches, graphics preference, Documents); for a launch profile the **Steam launch option** to paste (read-only text, "Copy launch option", where it goes, that existing options go after `%command%`, that undo leaves it to the user, and why it would not work: the shim missing, the install folder unknown); "Administrator rights: not needed"; and one sentence that undo takes the whole plan back together (the launch profile is named only when the plan has one). "Apply" is enabled only after the window reported the preview rendered and while the game is closed (the core checks); nothing is stored before the click (looking never creates Rerun's folder).
- **Results and refusals** appear in a banner above the page that takes the focus (the screen reader reads it): applied, nothing to change, taken back, only partly done (with a pointer to Applied), and calm refusals with what to do: a file of the game in use, another Rerun operation, a damaged or earlier change that must be dealt with first (its transaction ID is the detail), a taken DLL name, Steam busy, an admin-only folder. **The game changed since the preview** and **the state changed since the preview** are not errors: the page is read again and the banner says to look at the fixes and the preview again.
- **Applied to this game**: the cards of the game's open transactions (below).

**Applied**: "Nothing applied / Your games are unchanged", or the number of open transactions, then **one card per transaction** (user decision U1 a): the game, the state with symbol and word (Applied; Interrupted, Cleanup pending, Damaged, Unreadable, Needs you), the transaction ID, what is wrong if something is, **every change in it** as in the preview, and the sentence that undo takes all of it back together, the launch profile included, and that changing one of them later means undoing the card and applying again. "Undo" opens the **undo dialog**: nothing has changed yet; per change, newest first, what undo meets now (will be set back, already as before, Rerun's part is set back and later changes stay, someone else changed it and Rerun leaves it, stays for another change that relies on it, not reached); the game must be closed; the cleanup it would do; where it would stop and why; and what becomes of the launch option (remove it in Steam by hand, with the option shown; the earlier profile is back; the profile stays). "Undo this change" does it; Esc or "Cancel" closes. If the state changed since the dialog opened, the dialog shows again with a calm note and nothing was written. An undo whose preview needs the administrator prompt is not offered yet. "Close without undoing" (forget) has its own dialog with what is on disk now; it is the way out of a change someone else changed or a damaged record, and says that Rerun can no longer undo it. Reloaded whenever the page opens and after every write.

**History**: placeholder (the journal, filterable; later).

**System**: graphics adapters (name, video memory, architecture, integrated), processor (logical processors, cores, cache groups), Windows build, Smart App Control, Steam. Read when the page opens.

**Settings** (skeleton): Safety (preview before every change, only sources from the signed index: both always on), Appearance (theme Mythen, language following Windows), About (version, licence). The rest follows with P5-10.

Later steps (plan P5): the history, the helper's UAC prompt owned by the window (P5-5c), the interrupted-transaction banner and rebind (P5-6), links and "report a problem", themes Nacht and Kontrast, density, the library views, the settings file.

## Design system: theme "Mythen"

Strictly monochrome; surfaces are fills, not borders; hairlines separate rows.

| Token | Value | Use |
|---|---|---|
| `bg` (Fels) | `#0b0b0b` | window, title bar, status bar |
| `raised` | `#111110` | cards, groups |
| `raised2` | `#161615` | selected navigation entry, hovered row, quiet badges |
| `raised3` / `raised4` | `#1f1f1e` / `#2a2a28` | secondary buttons, hovered |
| `line-soft` | `#1a1a19` | hairlines, badges |
| `line` / `line-strong` | `#2e2e2c` / `#8a8a86` | inputs; the rule of a callout, the outline of a quiet badge |
| `text` / `strong` | `#e8e8e4` / `#f7f7f5` | body text / headings, the primary button's fill |
| `muted` / `faint` | `#9c9c98` / `#8a8a86` | secondary text / the status bar |

Radii 2 px (chips, inputs) and 4 px (cards, buttons); spacing 4, 8, 12, 16, 24, 32, 40, 56 px; the primary button is inverted (Schnee on Fels). The tokens live in `rerun-app::theme` and are copied into the global `Theme` of `ui/app.slint`; no colour literal in a `.slint` file (source rule). Every text/background pair reaches a contrast of 4.5:1 (test). Further themes (Nacht, Kontrast, Windows' high contrast) follow with P5-10 (user decision U8 a).

Fonts (user decisions U10 a and 2026-11-12): **embedded**, OFL, unmodified, imported by `ui/app.slint` and compiled into `rerun-app.exe`; nothing is loaded from disk or network at run time. Archivo Expanded ExtraBold (800) for the page and hero titles, IBM Plex Sans 400/500/600 for text, IBM Plex Mono 400/500 for IDs, paths, hashes and the status bar. Files, versions, sources and SHA-256 are in `crates/rerun-app/assets/fonts/FONTS.md` (checked by `tests/fonts.rs`; policy exception in `docs/05-sources-policy.md`). A glyph the embedded fonts lack (CJK or other scripts of Steam titles, the status symbols) falls back to a Windows system font; Segoe UI Symbol (status glyphs) and Segoe Fluent Icons (window buttons) stay Windows' own. The About page of P5-10 shows the three OFL licence texts and the copyright lines of the fonts (the `OFL.txt` files are the source), next to Slint's licence.

## Status: always symbol and word

| Glyph | Meaning |
|---|---|
| ◆ | affects this PC |
| □ | a fix is available / Topo available |
| ■ | applied |
| ○ | nothing offered |
| ? | may occur, unknown |
| ! | needs attention (updating, not read, refused) |
| – | does not apply here, not offered |
| ✓ | verified |
| ◌ | not confirmed |

A glyph never stands alone: the word next to it carries the meaning, and screen readers read the word.

## Accessibility (requirements)

- Every interactive element has a name and a role through UI Automation (Slint's AccessKit adapter): the window buttons, navigation entries (tabs, the active one selected), rows (list items with index and count), buttons, the switch (checked state), the search field.
- Dialogs (P5-5a, P5-5b): while a dialog is open every control outside it is disabled (a focus trap: Tab cycles in the dialog), the dialog's title takes the focus when it opens, Esc closes it, and the button on the card (or the checkbox of the fix) that opened it takes the focus back. Results appear in a banner that takes the focus; the checkbox of a fix and the buttons of a card are named with the fix or game they belong to.
- Full keyboard use: Tab and Shift+Tab through navigation, controls and rows; Enter or Space activates; a focused element is scrolled into view; the focus ring shows only after keyboard focus. Open until the hand check of P5-3: whether Tab reaches the search field (the automated walk skipped it).
- Slint has no heading role: a page's title takes the focus when the page opens, and the page region carries the page's name, so Narrator reads where it is.
- Status as symbol and word; contrast at least 4.5:1; no animation in P5-3; text follows Windows' scaling (per-monitor DPI V2). Windows' text size setting, high contrast and "show animations" are read with P5-10.
- Untrusted text (Steam names, paths, Topo texts, the core's error texts) is escaped (ADR 0016) and drawn in its own text element, never inside a sentence, so its direction cannot reorder the text around it.

## Copy

English is the base, German the second language (the app follows Windows' display language). Every string is a typed message of `rerun-app::text`; a missing translation does not compile. Tone: calm, direct, concise; informal "du" in German, Swiss "ss"; no superlatives, no exclamation marks (tests). Rerun never guesses and says so: "Rerun offers nothing and changes nothing."
